# Error and learning documentation

Keep mistake and learning records in this directory, separate from research
evidence. Read this guidance before creating or revising one.

## Preserve each incident

- Create a new, descriptively named Markdown record for a new incident or a
  recurrence after a correction. Link related earlier records from the new one.
- Preserve existing records as written. Similar causes do not authorize merging
  incidents, replacing earlier conclusions or appending a new incident to an
  older record. Revise an existing record when the user explicitly requests it.
- If later evidence corrects an earlier account, explain the correction and its
  evidence in a new linked record. An explicitly requested amendment to an older
  record should identify what changed and why, retaining the original account
  unless the user asks to replace it.

## Explain the systematic failure first

1. State the failed decision or execution practice and its consequence. Explain
   how it produced the error and why existing checks failed to catch or stop it.
2. Support that account with the smallest useful sequence of concrete actions
   and direct evidence links. Separate observed events from inferred causes;
   use dates and quantities only when the record supports them.
3. Describe the impact: which decisions, claims or work were affected and which
   remain usable. Specific technical errors illustrate the mechanism; an error
   catalogue or claim count is not a substitute for explaining it.
4. Give an actionable correction: when it applies, what behavior changes and
   what would demonstrate that the failure has been addressed. A reminder to
   “be careful” or another document alone does not establish resolution.
5. State what has been corrected and what remains open. Keep technical evidence
   and decision acceptance in their owning investigations; a retrospective
   neither accepts nor invalidates findings merely by describing them.

Use only the detail needed to understand the failure and change future behavior.
Own the assistant's decisions; attribute a failure to missing requirements,
equipment or user input only when the evidence establishes that dependency.

## Finish the documentation task

Check that the new record leads with the systematic lesson, evidence links work,
and unrelated existing records are unchanged. Report the new record and any
explicitly requested amendments. Documentation completion and correction of the
underlying work are separate outcomes.
