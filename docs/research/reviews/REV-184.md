## Independent findings

### R1 — checker PASS does not cover the method's full integrity contract

`DEADLINE_MECHS` includes mach_wait_until and dispatch leeway0 but omits
`dispatch_source_timer_strict`. Consequently I6 ignores every strict early
count. A lightweight in-memory copy of the completed JSON, changing one
strict row to `early=1,min_ns=-1`, still returns code0 and `RESULT: PASS` through
the exact frozen checker. No source or raw file was changed. A separate
in-memory mutation to `roundtrip_min_ns=0` also passes, although the Metrics
table requires a positive delivery-round-trip minimum. I17 checks only the
one-way/round-trip p99 relation, not that minimum.

The actual six strict rows have zero early counts and minima 3125, 11000,
6041, 15875, 19583 and 21000ns in emitted order. Actual round-trip minima are
positive. Thus these mutations reveal validation gaps, not an observed early
strict wake or zero-duration event in this normal artifact. Reopen the code
gate for the promised predicates and isolated regression cases. A newly
reviewed checker may re-derive these aggregate checks over unchanged raw; a
fresh collection is not automatically required merely to check existing
fields. The original transcript must remain immutable and cannot be silently
replaced. REV162's narrow directional-reporting acceptance is preserved as
history, not treated as a complete audit of these separate predicates.

### R2 — dispatch measurement is not timer-only requested-deadline error

The producer constructs `deadline_abs=base_abs+target` before dispatch setup,
but requests `dispatch_time(DISPATCH_TIME_NOW,target)` later during setup. It
never replaces the first deadline, despite the comment saying the deadline is
re-taken. The reported dispatch error therefore subtracts a pre-setup reference
from a callback timestamp. It includes setup/reference displacement and retains
the method's cross-thread-clock assumption. The recorded `setup_p_mean_ns`
covers creation/configuration before resume, not the exact paired displacement
to the requested dispatch deadline; its mean cannot be subtracted from a
median or p99 to reconstruct the corresponding corrected quantile.

Even `early=0` only says no callback timestamp preceded the producer's earlier
reference. It does not establish no delivery before the actual requested
dispatch deadline, which is not retained. Preserve the raw uncorrected
reference-error statistics with that explicit scope. A claim of timer-only
error, exact requested-deadline no-early behavior, or corrected quantiles needs
a reviewed method/code correction and new collection, not post-hoc arithmetic.
Independent method return must adjudicate whether a narrowly described
setup-inclusive statistic can support the intended T2 claim; do not present
the frozen checker line as resolving this measurement/claim mismatch.

### R3 — concurrent nominal rate and threshold misses must remain explicit

The concurrent loop constructs each deadline from the current time plus 1ms.
It does not maintain fixed-phase periodic deadlines, record achieved throughput,
or prove sustained per-vCPU 1kHz delivery. `aggregate_wakeups_per_s` is simply
`nthreads*1e9/target`; 2000/4000/8000 are nominal requested rates, not observations.
The measured scope is 2/4/8 concurrent streams of repeated 1ms requested waits.
Their pooled medians are 509208, 509500 and 509459ns, all missing the declared
250000ns criterion. The printed T1–T4 report omits those concurrent comparisons;
a single strict-timer T2 meet cannot make claim20 or the full SMP requirement
pass. Do not manufacture an achieved-rate estimate from a median either.

The claim/README rationale that per-thread reporting would itself be a core-
placement statement is incorrect: thread identity is not core identity.
Pooling is the existing collection/reporting choice and must remain disclosed;
it provides no per-thread fairness/tail guarantee and cannot recover omitted
per-thread results after the producer sorts the pooled array. Correct the
rationale without pretending this run collected those omitted dimensions.
