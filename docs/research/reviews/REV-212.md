## Independent findings and closure

Claim -24 is supported as qualified. The header describes a main-thread-bound
default queue, explicitly permits servicing it with a CFRunLoop on the main
thread, and warns about non-UI-process side effects. The manual's compatibility
section describes main-run-loop common-mode service but expressly does not
guarantee main-thread execution with dispatch_main. The candidate preserves
that exception instead of deriving unconditional affinity from the queue
name. It is a premise for a possible new instrument cell, not a recommendation
to make the main queue the product's timer architecture.

Claim -25 is supported. The manual gives general queues no fixed execution
thread, warns against expecting pthread_self identity between blocks, and
states identity remains fixed within one block. Its warning that comparing
current and main queue values does not establish main-thread execution is in
DEPRECATED FUNCTIONS. The initial claim reference and ledger row named only
DESCRIPTION/COMPATIBILITY; root added the missing section in both and recorded
the correction in self REV-211. That required citation-location correction is
closed at the pinned hashes. No CPU-placement or cross-thread clock
comparability guarantee is derived from pthread identity.

Claim -26 accurately inventories declarations. The header declares current
and main run-loop access, default/common modes, run/run-in-mode, stop/wakeup
and block scheduling (the latter under the blocks compile condition). The
candidate does not claim these declarations establish loop lifetime, callback
delivery, precision, a requested-deadline mapping, or any timer performance.
Actual use of the block interface still requires the corresponding compile
configuration; this source approval is not generated-code approval.

The four source-to-claim mappings match that bounded support. General queue
rules are read together with the qualified main-run-loop case rather than
used to erase it or its dispatch_main exception. All failed or missing
measurement cells, constructor/callback identity checks, global-queue,
strict/non-strict, both-QoS and sustained SMP obligations remain method work.
A new queue cannot retroactively rescue existing invalid samples or become
a like-for-like substitute without an explicit reviewed method.
