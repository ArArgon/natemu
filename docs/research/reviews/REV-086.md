## Required changes

1. `INV-01-08` owner, return to result gate: record the plain-SB
   user-interactive power problem in Limitations, using this replication as
   the evidence. Two full runs of the same code on the same host gave 39 and
   **1** relaxed outcomes per 10^6 in that arm, and 1004 and 3299 at
   background. `I2`'s any-arm rule is the only reason the second run did not
   fail its own positive control. State that a user-interactive SB arm has
   demonstrably marginal power on this host, that no SB conclusion may rest on
   the user-interactive stratum alone, and that the relaxed-outcome rate is
   unstable across runs even in order of magnitude — which the record already
   asserts in principle but has not until now shown. This is the same evidence
   as `REV-085` change 2 and may be closed by the same edit.
2. `INV-01-08` owner, return to method gate: say how a boundary-straddling
   histogram pair is reported. The frozen rule compares both-observed
   fractions with an order-of-magnitude threshold, which is the right shape,
   but `MP`/`DMB ISH`/background sat at 28.3× for the author and 9.0× for this
   replication and so flipped from INCONCLUSIVE to COMPARABLE on noise alone.
   Predeclare the handling — for example, that a pair whose ratio falls within
   a stated factor of the boundary is reported as indeterminate and needs a
   second run before either verdict is used, or that the verdict is taken from
   the pooled fractions across runs. Do not change the threshold after data
   exists without reopening the method gate, which is why this returns there
   rather than being fixed in place.

## Verdict

- Verdict: `revise`
- Rationale: **the claimed result reproduced.** Executing the approved probe
  at `d8cb40c`, extracted from Git and verified to hash identically to the
  revision the code gate accepted, and checking it with a checker written for
  this review that recomputes the derived rates from raw primitives rather
  than trusting them, every categorical outcome recurred: the positive control
  fired, no architecture-forbidden relaxed outcome appeared in any of the four
  strengthened arms, no LSE arm lost an update at any thread count, the six
  alignment cases matched outcome for outcome including `SIGBUS`/`BUS_ADRALN`
  on the three crossing cases, there were no round-trip timeouts, and the
  `T4b` miss recurred. The record's headline negative — all four SB pairs
  INCONCLUSIVE — recurred too, so it is not an artefact of one run. `accept`
  is prohibited because the replication surfaced two things the single run
  could not: the plain-SB user-interactive control fell to a single event in
  10^6, and one histogram pair flipped its adjudication verdict purely because
  it straddles the rule's boundary. Both need recording before the result
  stands; neither is a reproduction failure.
- Applicability limitations: this replication widens nothing. It is the same
  `Mac16,10` (M4), the same macOS 26.6.2 (25G83), and the same SDK 26.4, on a
  shared host with other agents active, so every figure remains this-host
  only. `P1` (M1 Pro / Sequoia 15) replication is still owed and is unusually
  load-bearing, because the Arm feature level `CLM-01-08-04`, `-05`, and `-19`
  depend on is generation-dependent. Nothing here disposes `KA-06` or
  establishes that the architecture forbids any outcome. The reviewer's runner
  and checker were written and reviewed by the same context, which is a stated
  limit of this replication.
