## Required changes

1. **R1 — `INV-01-10` experiment owner, return to code gate (one line, before
   the re-run).** Make the environment block tolerate a `sysctl` key that does
   not resolve, so a missing or renamed OID cannot abort the run before
   `SHA256SUMS.txt` is written — for example `sysctl hw.model hw.memsize
   hw.ncpu hw.pagesize kern.osversion || true`, or query the keys individually.
   The script runs under `set -eu`; `sysctl` exits non-zero on an unknown OID;
   and I confirmed by direct test that such a failure inside this brace group
   aborts the script, which would leave the artifact without its integrity
   listing. The hazard cannot fire on either accepted host pair, so this is a
   robustness fix rather than a correction — but it is one line in the very
   script that is about to be run, and fixing it before the re-run costs
   strictly less than discovering it after. Note for the same owner, outside
   this review's scope: `experiments/INV-01-01/run.sh` has the same block shape
   and the same latent behaviour, and is the cheaper place to fix it at the same
   time.

## Verdict

- Verdict: `revise`
- Rationale: The change is correct, minimal, and exactly scoped, and every
  property `REV-071` accepted survives it. Verified against git rather than on
  report, no author experiment file other than this `run.sh` differs from the
  accepted revision `6c0acf5` — `tools.sh`, `check.py`, and both READMEs are

  `REV-094` R1 found missing from all six artifact files, and the block

  inventory. All three refusal branches still fire before any write, including
  the symlink-into-the-repository case, and the script still writes nothing
  under `experiments/`. `accept` is withheld for one reason, and it is narrow:
  the added `sysctl` is the first command in that block that can fail, and under
  `set -eu` a failing `sysctl` aborts the script before `SHA256SUMS.txt` is
  written — which I confirmed by direct test rather than inferring. It cannot
  fire on the accepted hosts, so nothing about the imminent re-run would be
  wrong; but this review's `accept` is what authorizes that re-run, and
  authorizing a run of a script with a known one-line abort path in the block
  the change just introduced is not something a code gate should do when the fix
  is `|| true`. Fix the line, re-run once, and the result return has a clean
  artifact to judge.
