## Independent findings on the corrected text

*The registered alternate-stack fact is stated more strongly than the
capture.* `CLM-01-19-07` (line 109) and the stack section (line 547) both say
the system switches "only if the **thread** is not currently executing on that
stack". The capture says process: "the system checks to see if the *process*
is currently executing on that stack. If the *process* is not currently
executing on the signal stack, the system arranges a switch" (capture lines
18–21). The same claim then states "the captured alternate-stack page does not
state a per-thread property", and line 560 repeats "SRC090's wording does not
prove a per-thread contract". So the claim contradicts itself in one sentence,
and the contradiction is load-bearing: the method installs a *distinct*
alternate stack per worker (line 542) and derives the shared-stack nesting
consequence from this rule. Under the page's own process-scoped wording the
behaviour of a second worker's alternate stack is simply not stated — which
the method elsewhere handles honestly by demanding same-cell observation. The
fix is to quote the source scope and keep the per-thread gap as the limit it
already declares. R2.

*The SP check is decidable in-handler.* Comparing an entry SP (or the
handler's automatic-local address, the identity route at 255–258) against the
parent depth's value published in a lock-free atomic word is a load and an
integer comparison: no library call, no TLS, no allocation, consistent with
the handler surface at 236–246. So the check RC2 asked for is executable as
specified; only its polarity at 378–381 is wrong. One non-blocking caution:
depths run in different handler functions (`P_outer`/`P_inner`/`D_*`), so
automatic-local addresses are frame-offset proxies for SP rather than SP
itself; the descending/non-overlap test is safe at frame granularity but the
method should record which reference point each depth samples.

*Bounded re-entry versus the depth accounting — consistent, but the storage
and the wait are under-specified.* A benign second fault arrives after normal
return and the instruction retry (lines 300–304), so it is a fresh depth-one
entry, not a nested one; it therefore does not collide with the positive-depth
rule (383–390) nor with D's reserved terminal depth 3, and it cannot occur as
a nested entry in P at all, since `P_fault` keeps both fault classes in
`sa_mask` (line 357). The policy is consistent with the D configuration's
terminal depth. Two things it does not say. First, the re-entry writes a
second trace record for the same worker/event/entry-depth, which the
uniqueness rule at 412 and the no-recycle-before-ack rule at 250–251 do not
provide for; the atomic counter records that a re-entry happened, not the
event. Second, "again waits on the helper's acknowledgement" is ambiguous
about whether the handler republishes a repair request or returns on the
standing acknowledgement — under the standing-ack reading the wait is vacuous
and the policy reduces to "one extra normal return", which is a defensible
and probably correct semantics but must be stated, because a code reviewer
cannot derive it. R3.

*Campaign bound.* Lines 681–684 conclude that a "low-to-mid four-figure child
count bounds serial single-host execution to a two-to-three-figure number of
wall-clock hours" at the 30-second ceiling. 1,000 × 30 s = 8.3 h and 5,000 ×
30 s = 41.7 h — one to two figures, not two to three; three-figure hours would
need roughly 12,000+ children, well outside the stated cardinality. The
estimate is also declared "before negative arms" while being used as the
campaign's aggregate bound, so the excluded portion is unquantified. Separately,
the per-cell plan is consistent with the watchdogs: 10 warm-up plus 100 checked
events is 110 events per child inside the 30 s ceiling (~270 ms per event) with
the 5 s no-progress watchdog bounding each handler/helper exchange, and the
bounded re-entry adds at most one extra wait per affected event, which does not
disturb that. It is only the aggregate line that does not follow. R4.

*The first stage is genuinely INV-01-18-free, and not prerequisite-free.* All
six named groups avoid every Q18 object: the no-JIT A and R baselines and the
no-JIT retry report (299–301), the mask/delivery/context-size preflight
(369–372), the D depth-2/3 controls on an *owned non-JIT protected page*
(418–423), the alternate-stack and no-`SA_ONSTACK` diagnostics (542–560) and
the offline checker mutations (613–617), which the plan already requires
before any runtime work. None needs the arena, the protocol or an INV-01-18
result, and none discharges a matrix row — the declaration is executable as
scoped. But two of the six consume a different accepted dependency the bullet
does not mention: the context-size/accessor check is explicitly "against the
accepted same-cell Q06 baseline before field use" (lines 261–262), and the
no-altstack identity route uses a captured general-register cookie (line 258),
both inside the Q01-04/Q01-06 same-cell inputs that lines 162–163 and the gate
table hold as prerequisites. Also, the cited range 418–432 runs past the
non-JIT controls into "Also test one terminal witness under A and directly at
depth0 …" (424–428); the terminal witness of the permission section samples an
in-arena word and a JIT stub (453–454), so a code reviewer reading the range
literally could pull an arena-dependent sub-test into a stage declared
arena-free. Both are one-sentence fixes, and both matter because "first stage"
is a scope claim the code gate must be able to check. R5.

*Review-record integrity.* `REV-221`'s artifacts table records
`docs/research/reviews/REV-190.md` at SHA-256 `bc9db719…`. That value is
`REV-178.md`'s digest (`REV-190`'s own artifacts table row for `REV-178`, and
recomputed here); `REV-190.md` is `5717ed68…`. `REV-221` discloses that it
carried the value over rather than recomputing it, which is how the
transposition happened. It is minor and it changes nothing substantive, but
the self return whose central item is retrievable pinning mis-pins the very
review it closes. R6.
