## Required changes

1. `INV-01-08` owner, return to code gate: add `("SB", "ldar-stlr")` to
   `check.py`'s forbidden-outcome set in `I5`. Demonstrated, not inferred:
   this reviewer took the repository's own `experiments/INV-01-08/tests/valid.json`,
   changed a single field — `relaxed_observed` from `0` to `41` on both SB
   `ldar-stlr` arms — and ran the unmodified checker, which reported
   `PASS  I5 no architecture-forbidden relaxed outcome: ... []` and
   `RESULT: PASS (0 integrity failures)` with exit 0. `SRC-108`, cited by this
   very record, defines `bob ⊇ [L]; po; [A]` and states that a store-release
   before a load-acquire "is required to be observed in order by all threads",
   so the SB relaxed outcome under `STLR`+`LDAR` is architecturally forbidden.
   The checker therefore cannot detect the single most likely form of harness
   failure in the strengthened arms. This must close together with `REV-043`
   required change 1 and `REV-044` required change (source dependency); fixing
   the rule without fixing `CLM-01-08-09` would leave the record and the code
   contradicting each other. Note for the record: in the reviewer's own run
   the arm observed zero, which is what the architecture requires.
2. `INV-01-08` owner, return to code gate: strengthen `validate.sh`'s
   instruction check to the symbol range, or record the manual disassembly
   review as the gate artifact. The emitted code is correct — this reviewer
   read the whole `_lit_thread` range and confirms that with the SB side
   selected by `csel` between offsets `0` and `0x80`, variant 0 emits
   `str x11, [x17]` then `ldr x15, [x16]`; variant 1 emits `stlr x11, [x17]`
   then `ldar x15, [x16]`; variant 2 emits `str x11, [x17]`, `dmb ish`,
   `ldr x15, [x16]`; the MP writer emits `str x11, [x20]` then
   `str`/`stlr`/`dmb ish`+`str` to `[x9]`; and the MP reader emits
   `ldr`/`ldar`/`ldr`+`dmb ish` then `ldr x15, [x20]`. Nothing under test is
   folded, hoisted, reordered, or elided, and the two litmus locations are
   128-byte aligned as claimed. The problem is that `validate.sh` proves none
   of this: it greps the entire disassembly for `ldr str ldar stlr dmb ldaddal
   ldadd cas`, and `ldar`, `stlr`, `ldaddal`, and `dmb` all appear in the C11
   sense-reversing barrier and in `rt_peer` no matter what the litmus bodies
   contain. The check would pass unchanged if every variant degenerated to
   plain `LDR`/`STR` — the exact defect the disassembly artifact exists to
   catch.
3. Both owners, return to code gate: give the `T*` threshold checks a physical
   lower bound, or suppress threshold reporting when any integrity rule has
   failed. In the reviewer's `INV-01-07` `--negative` run the checker printed
   `MEET  T3 IPI analogue: p99 delivery < 100 us at user-interactive:
   pthread_kill spinning-target p99 = -3000 ns`. The run still failed overall
   because `I10` catches `min_ns < 0`, but a subtler sign defect that left the
   minimum positive would produce a MEET on an impossible tail. The same
   applies to `INV-01-08`'s `T2`, `T3`, and `T4`.
4. `INV-01-07` owner, return to code gate: restrict `T1` to monotonic clocks.
   `fastest = min((c["read_cost_p50_ns"] for c in clocks), default=None)`
   includes `clock_gettime(CLOCK_REALTIME)`, a settable wall clock, although
   `CLM-01-07-11` is about "the fastest documented monotonic clock". On this
   host the outcome is unaffected (`mach_absolute_time` was fastest at 11 ns
   in the reviewer's run, against 17 ns for `CLOCK_REALTIME`), but the rule as
   written can satisfy a monotonicity-scoped claim from a non-monotonic clock.
5. Both owners, return to code gate: extend `--negative` to the integrity
   rules it does not reach, or state per rule which are mode-validated and
   which are fixture-validated. Measured: `INV-01-07 --negative` fails `I4`,
   `I6`, `I7`, `I10` and never exercises `I3` or `I11`; `INV-01-08 --negative`
   fails `I2`, `I3` and never exercises `I5`, `I7`, `I9`, `I10`, `I11`, `I13`,
   `I14`. (`I8`/`I12` and `I4` also failed in the reviewer's runs, but only
   because of the reduced sample counts, not because of the injection.) Both
   records state that a `--negative` run the checker does not fail stops the
   code gate, which implies the mode validates the checker; it validates about
   half of it.
6. `INV-01-08` owner, return to code gate: correct
   `experiments/INV-01-08/README.md`, which still tells the operator that
   `src/check.py` "must report `RESULT: FAIL` (rules `I1` and" for the
   negative run. After the `5fe6a68` renumbering the negative run fails `I2`
   (positive control) and `I3` (concurrency), as the reviewer's run confirms.
7. `INV-01-08` owner, return to code gate: make the `cas` arm report what it
   measures. `lse_thread`'s `use_cas` path executes a relaxed load, a `cas`,
   and a retry until success, but `run_lse` divides elapsed time by
   `expected = S->iters * nthreads`, the count of *successful* increments, so
   failed attempts are charged to the per-operation cost. Count attempts and
   emit them alongside successes so the result gate can separate instruction
   cost from retry amplification; without that, the reviewer's observed
   `cas` 3.62 → 198.10 ns/op (54.7×) cannot be attributed.
8. Both owners, return to code gate: either extend `--iters`/`--n` to every
   arm or document the fixed ones. `g_n_clock`, the cross-thread clock arm's
   200 000 iterations, all six LSE arms' 10^6 operations per thread, the
   fallback arm's 250 000 per thread, and `g_rt`'s 20 000 handshakes ignore
   the flags entirely, so the "reduced sample counts" both records say the
   probes were smoke-tested at do not reduce the contention arms at all.
9. Both owners, return to code gate: harden `run.sh`'s repository detection.
   `repo_root=$(cd "$(dirname "$0")/../.." && pwd)` makes the containment test
   relative to the script's own location, so a relocated copy silently changes
   what counts as inside the repository; and the subsequent
   `git -C "$repo_root" status` and `rev-parse` calls are unguarded under
   `set -eu`, so outside a work tree the script exits 128 with git's own
   "fatal: not a git repository" instead of the documented exit-2 refusal.
   Verify `repo_root` is a Git work tree first and fail with the same guarded
   message and exit code.
10. Both owners, return to code gate: mark the inline-asm outputs early-clobber
    (`"=&r"`). `LD_PLAIN`, `LD_ACQ`, `probe_one`'s three cases, and
    `lse_thread`'s `ldadd` all pair a plain `"=r"` output with `"r"` inputs
    holding the address and, for the atomics, the operand. The current build
    allocates distinct registers (`ldaddal w11, w15, [x14]` in the
    disassembly), but nothing in the source requires it, and an `Rs == Rt`
    allocation for `ldadd`/`ldaddal` would execute a different architectural
    case from the one the arm claims.
11. `INV-01-08` owner, return to code gate: bound the fault handlers' lifetime
    or make the abort path safe. `run_alignment` installs process-wide
    `SIGBUS`/`SIGSEGV` handlers and never restores the previous dispositions,
    so the round-trip arm runs under them; an unexpected fault there hits
    `_exit(90)` with `result.json` half written, and `check.py` then dies with
    an unhandled `json.JSONDecodeError` rather than reporting
    `RESULT: FAIL`. Restore the dispositions after the arm, or flush and close
    the output stream before `_exit`. The rest of the fault handling is sound
    and is recorded as such: the `g_in_probe` window correctly refuses to
    swallow any fault raised outside a probe, `SA_SIGINFO` captures the
    `si_code`, `sigsetjmp`/`siglongjmp` with a saved mask is a legitimate
    technique for a synchronous fault, and the classification is *recorded*
    rather than assumed — the reviewer's run emitted, per case,
    aligned control `faulted:false`; misaligned within the 16-byte granule
    `faulted:false`; crossing 16 bytes `faulted:true, signal:10, si_code:1`;
    crossing the 64-byte line `faulted:true, signal:10, si_code:1`; plain
    `ldr` crossing the line `faulted:false`; `ldar` crossing the line
    `faulted:true, signal:10, si_code:1`. `I11` enforces that every fault
    carries a signal number.
12. Both owners, return to code gate: deallocate the port returned by
    `mach_thread_self()` in the affinity arms. Cosmetic; it does not affect the
    recorded return value, which was 46 (`KERN_NOT_SUPPORTED`) in both probes
    in the reviewer's runs.
13. Both owners, return to code gate: record the resolved SDK in
    `environment.txt`. `xcrun --show-sdk-path` emits
    `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`, a symlink, while
    the source inventories pin header digests to `MacOSX26.4.sdk`; capture the
    resolved path, and ideally the digests of the cited headers, so a result
    reviewer can bind the binary to the sourced headers.
14. `INV-01-07` owner, return to code gate: the `dispatch_source` arm's
    per-iteration source creation is disclosed as a confounder in the record
    but is not measured. Emit the setup cost as its own field so the arm's
    numbers can be corrected rather than only described as an upper bound.

## Verdict

- Verdict: `revise`
- Rationale: the code is competently written and the two hardening revisions
  closed real defects — unchecked `pthread_set_qos_class_self_np` (which would
  have silently mislabelled every QoS arm), unchecked allocations and thread
  creation, `atol` argument parsing, and the absence of a lock-free guarantee
  for the signal handler's atomics. The emitted machine code is correct: this
  reviewer confirmed from the disassembly that the three litmus variants
  differ exactly as claimed and that nothing under test is reordered or
  elided. `run.sh` refuses correctly in every case tested and writes nothing
  under `experiments/`; the sample-size rules make a reduced-count run
  unusable as evidence; the fault classification is recorded rather than
  assumed. `accept` is nevertheless prohibited, and one finding is
  disqualifying on its own: `check.py`'s forbidden-outcome rule accepts an
  architecture-forbidden SB relaxed outcome under `STLR`+`LDAR`, demonstrated
  by injecting it into the repository's own valid fixture and obtaining
  `RESULT: PASS`, so a passing run would not distinguish a working harness
  from a broken one in the arms that matter most. Thresholds can report MEET
  on physically impossible values; `T1` can be satisfied by a non-monotonic
  clock; `--negative` validates about half of each checker; `validate.sh`'s
  instruction check proves nothing about the litmus bodies; and the `cas` arm
  does not report what it measures.
- Applicability limitations: this verdict covers `experiments/INV-01-07/` at
  `c497cf3` and `experiments/INV-01-08/` at `5fe6a68` only. It approves no
  evidence run and no claim. Every measurement quoted here was produced by
  this reviewer for code validation on `Mac16,10` / macOS 26.6.2 (25G83) /
  SDK 26.4 at reduced sample counts under concurrent system load, written to a
  scratch directory outside the session raw root, with no manifest; it is not
  evidence, and no record may cite it.
