## Required changes

1. `INV-01-12` experiment owner, return to the **code** gate — **regression
   introduced by this return.** `call r/m64` (`FF /2`) no longer transfers
   control to its target. The branch stashes the target in `CPUOFF(tmp)` and
   then calls `emit_push_tmp2`, whose `emit_store_mem` → `hst()` sets
   `c->tmp = val`, overwriting the target with the pushed return address; the
   following `emit_ld_cpu(X1, CPUOFF(tmp))` therefore writes the return address
   into `rip`. Demonstrated: a guest `call rax` into a function that stores a
   marker leaves the marker at `0` under `1c14dbc` and at `0x1234` under
   `1c14dbc^` with the identical guest source, and the `1c14dbc` run reports
   `abort: null`, `timed_out: false` and PASSes the checker. Stash the target
   somewhere the store path does not touch, and add a guest indirect call so
   the path is exercised by an invariant rather than left silent.
2. `INV-01-12` experiment owner, return to the **code** gate: make `check.py`
   evaluate the abort-only document `run.sh` synthesizes for a host-level
   death. It currently raises `KeyError: 'vcpu0_done'` on
   `{"host":{},"vcpu":[],"guest":{"fault_log":[]}}` and would also `IndexError`
   on the empty `vcpu` list, so the verdict still arrives as a traceback —
   which is the outcome `REV-051` change 5 asked to remove. Evaluating `I1a`
   first and returning, or reading every field with `.get` and a sentinel,
   is enough.
3. `INV-01-12` experiment owner, return to the **code** gate (cross-referenced
   from `REV-073` change 1, recorded here because the fix is in `run.sh`):
   `run_one` maps every non-zero `check.py` exit to `verdict=FAIL`, which equals
   the expected verdict for a control, so the `UNWITNESSED` result that
   `--expect` produces when a targeted invariant does not fire leaves
   `status` at 0 and `run.sh` exits 0. Give the case a distinct exit status or
   have `run_one` inspect the `.check` output, and set `status=1`.
- One advisory note is recorded above (the uninitialized tail of the sixteen-byte
  decode window when a continuation page is MMIO). It is not a required action,

## Verdict

- Verdict: `revise`
- Rationale: Nine of the eleven `REV-051` required actions are verifiably
  closed, and the closures were checked by re-derivation rather than taken on
  report. The push and call ordering is genuinely fixed and now has its own
  control, which reproduces the original corruption exactly. Nested faults are
  detected and named instead of livelocking — the probe that once ran 132 384
  512 faults into the watchdog now aborts on the first one with `I1c`. The
  ThreadSanitizer evidence is controlled rather than asserted: the identical
  recipe finds eight races in the pre-return revision and none in this one, and
  its instrumentation limit is stated honestly. The unaligned access that once
  killed the process with no artifact is now a visible `#GP` and a failed
  `I7b`, and the self-modifying-code patch no longer depends on an accident of
  code layout. `LOCK` is rejected where it cannot be honoured, the decoder reads
  only inside a bounded window and faults properly on a not-present
  continuation, all six oracle holes are shut against re-applied
  falsifications, `--selftest` covers `I5c` and `I14` among 52 mutations, and
  simplification row 9 is replaced by an argument that survives reading the
  code. Two things block `accept`. The fix to required change 1 introduced a new
  silent control-transfer defect — `call r/m64` loses its target because the
  store helper clobbers the slot the new push helper made it share — which I
  demonstrated as a regression against the pre-return revision and which the
  checker reports as PASS. And the synthetic abort document that required
  change 5 asked for still crashes the checker rather than yielding a named
  invariant. Both are small and local; neither is a mechanism failure, and per
  `INV-00-06` family kill 3 neither is evidence of structural impossibility for
  `F2` or any family. But a code gate exists to catch exactly the class of
  defect that a fix introduces, so `accept` is prohibited while they are open.
- Applicability limitations: This review judges the `INV-01-12` experiment code
  only. Every observation was made on `Mac16,10` (Apple M4) / macOS 26.6.2
  (25G83) / SDK 26.4, in a scratch directory outside the repository, with
  `NATEMU_RAW_ROOT` never set to the real raw root and nothing written under
  `experiments/` or the raw root. No run reported here is evidence, none
  supports any claim in any record, and none may be cited as a result — the
  result gate is untouched and no evidence run exists. This review accepts no
  source mapping (`REV-072`, which accepts the source gate), no method
  (`REV-073`, which returns `revise`), and no `KA-04`, `KA-06`, or `KA-11`
  disposition. Nothing here authorizes planning or implementation.
