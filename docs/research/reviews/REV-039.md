## Required changes

1. **C1 — experiment owner, return to code gate.** `check.py` must be able to
   fail on the outcomes the investigation cares about. Add rules that require
   the `KA`-relevant fields, keyed on the invocation's `label` (or an explicit
   expected-outcome argument): `map_jit.mmap_ok` true; `jit_write_protect.toggle_ok`
   true and `crashed` false; `hypervisor.hv_vm_create_hr` equal to `HV_DENIED`
   for the unentitled label and to `0` for the entitled label; and reject any
   record whose `crashed` is false while `crash_signal` is non-zero. As shipped,
   an injected `MAP_JIT` failure — `KA-01` falsified — passes the checker.
2. **C2 — experiment owner, return to code gate.** Make the callback path
   discriminating: zero the region, have `jit_write_callback` write a *different*
   instruction sequence (for example `mov w0, #43; ret`), and assert the new
   constant in both `probe.c` and `check.py`. As shipped, a callback that writes
   nothing at all reports `write_with_callback_np_ok: true` with value 42 and
   PASSes, so the metric backs no evidence.
3. **C3 — experiment owner, return to code gate.** Fix the fault guard and the
   undefined behavior together: add a `volatile sig_atomic_t g_jmp_armed` set
   only around the two guarded sections, and have `fault_handler` restore
   `SIG_DFL` and re-raise when it is not armed, so a fault outside a live
   `sigsetjmp` scope terminates the process instead of jumping into a returned
   frame; declare every local that is modified between `sigsetjmp` and
   `siglongjmp` and then printed as `volatile`; and add a wall-clock timeout to
   `run.sh` around each probe invocation. Without this, one fault in the
   unguarded `mach_vm_remap` section makes the probe loop forever emitting
   invalid JSON — reproduced here — and an evidence run would hang and fill the
   raw root.
4. **C4 — experiment owner, return to code gate.** Call
   `sys_icache_invalidate(g_jit_region, sizeof(kJitCode))` (include
   `<libkern/OSCacheControl.h>`) after every write to the `MAP_JIT` region and
   before every execution, as `SRC-059` ¶26 requires. This is also the change
   that makes C2's different-constant assertion meaningful rather than
   accidentally satisfied by a stale cache line.
5. **C5 — experiment owner, return to code gate.** Emit `null` (or omit the
   field) for any Hypervisor call not attempted, and add a per-call `attempted`
   flag, so `HV_ERROR`-the-initializer is never indistinguishable from
   `HV_ERROR`-the-return-value.
6. **C6 — experiment owner, return to code gate.** Print `hv_return_t` as an
   unsigned hex string — the probe already does this correctly for
   `id_aa64mmfr0_el1_raw` — so the raw artifact literally carries `0xfae94007`
   and `0x0`, matching the threshold the record states, and so the C1 checker
   rule can compare against the documented constants.
7. **C7 — experiment owner, return to code gate.** Stop writing under
   `experiments/`: build into `$OUT` (or a `mktemp -d`) and sign there, and
   correct `run.sh`'s header comment and `README.md`, both of which currently
   assert a property the script does not have.
8. **C8 — experiment owner, return to code gate.** Harden the out-of-repository
   guard: resolve the path first (`NATEMU_RAW_ROOT=$(cd "$NATEMU_RAW_ROOT" && pwd -P)`)
   before the `case`, and derive `REPO_ROOT` from
   `git -C "$(dirname "$0")" rev-parse --show-toplevel` rather than from `cd ../..`.
   A symlink into the repository currently passes the guard.
9. **C9 — experiment owner, return to code gate.** Pin the SDK: pass
   `-isysroot "$(xcrun --show-sdk-path)"` in `build.sh` and record the resolved
   SDK path (`readlink`) plus the SHA-256 of the cited headers in the
   environment capture, so a result reviewer can tie the executed binary to
   `SRC-050`–`SRC-056`'s digests by construction rather than by symlink
   coincidence.
10. **C10 — experiment owner, return to code gate (minor).** Guard the
    `setrlimit` doubling against `RLIM_INFINITY` overflow, which would silently
    lower the limit and still report `set_ok: true`; escape `--label` before
    interpolating it into JSON. Advisory within the same change: deallocate the
    `mach_thread_self()` send right, and check `printf`/`fflush` results so a
    short write is reported rather than producing truncated JSON.

## Verdict

- Verdict: `revise`
- Rationale: The code is small, dependency-free, readable, and builds clean
  under `-Wall -Wextra` on an independent recompile, and two contract properties
  hold as claimed: `run.sh` refuses with `NATEMU_RAW_ROOT` unset and with a
  non-existent directory, in both cases before any build or write, and the
  declared negative control behaves exactly as documented — `--negative` reports
  `0xBAD` and `check.py` exits 1 with precisely the one predicted rule
  violation. `accept` is nonetheless prohibited, because a PASS from this code
  does not presently mean what the investigation needs it to mean. Three
  reviewer fault injections established that concretely, none of them exotic.
  A run in which `MAP_JIT` is unavailable — `KA-01` falsified, the single most
  consequential result this probe can produce — is reported PASS, because every
  capability rule in the checker is written as `if it happened, check it`. A JIT
  write callback that writes nothing at all is reported as a successful
  callback-gated write with the correct constant, because the callback rewrites
  bytes the earlier toggle path already left in the region. And one fault in the
  `mach_vm_remap` section, which has no `sigsetjmp` of its own although the
  handlers are installed process-wide, sends the probe into an already-returned
  frame where it loops forever emitting invalid JSON with visibly indeterminate
  locals — a C11 7.13.2.1p3 defect that `run.sh`, having no timeout, would let
  run against the raw root. Alongside these: the probe executes freshly written
  code without the `sys_icache_invalidate` call its own record's cited source
  calls mandatory; unattempted Hypervisor calls are reported as plausible error
  codes; the return codes are rendered as signed decimals the stated thresholds
  do not match; `run.sh` writes under `experiments/` in contradiction of its own
  header, the README, and the evidence policy; the out-of-repository guard is
  bypassable by a symlink; and the SDK the record cites by digest is not pinned
  at build time. Every required change above is a small, checkable edit to a
  named file and line range.
- Applicability limitations: This review adjudicates the code of
  `experiments/INV-01-01/` only, at working-tree revision `ff5bd7e`, built and
  run on `Mac16,10` (M4) / macOS 26.6.2 (`25G83`) / `MacOSX26.4.sdk`. It
  establishes no platform capability and no `KA-01` or `KA-02` disposition:
  every run performed here was a reviewer smoke or fault-injection run in a
  scratch directory, it is not evidence, it supports no claim, and nothing was
  written to `/Users/liaozping/orca/natemu-raw`. Observed values quoted above
  (for example `thread_policy_set` returning `46`, or the unentitled
  `hv_vm_create` code) are cited to show what the code does with them, not as
  findings about the platform. This review does not accept the sources
  (`REV-037`) or the method (`REV-038`), and nothing here authorizes an evidence
  run, planning, or implementation.
