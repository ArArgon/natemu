## Verdict

- Verdict: `revise`
- Rationale: Ten of the eleven `REV-050` required actions are verifiably closed,
  and several are closed better than the change asked. The concurrency claim no
  longer says "simultaneously"; it is bounded by a real instrument — per-thread
  consumed CPU time over the wall span, with a floor of 1.50 frozen before data
  — that I measured at 2.00× in five of five runs and that fires when halved,
  and the record concedes in three separate places what the barrier and the
  window overlap do not exclude. The frozen configuration is now asserted rather
  than reported: I re-applied all twelve falsifications that previously produced
  PASS and every one now FAILs. The unwitnessed list is rebuilt invariant by
  invariant with exactly two honest declarations, the targeted-versus-collateral
  separation is written into the method, the README and the runner, the drop-IPI
  coupling is recorded with the numbers I measured independently, the A/D
  observable and the fault-versus-interrupt priority the breadth pass demanded
  are both supplied, the coalescing rule is restated to match the racy guard the
  code actually has, the nested-fault stop is implemented and I confirmed it
  fires in place of the old livelock, and simplification row 9 is replaced by an
  argument that survives reading the code. One action remains open, and it is
  not cosmetic: the method and the README both assert that `--expect` fails the
  run when a targeted invariant does not fire, and the runner swallows exactly
  that signal, so a control that silently stopped witnessing its own invariant
  would still be recorded as an expected FAIL. `accept` is prohibited while that
  action is unresolved.

  predeclared oracles only. It accepts no source mapping (see `REV-072`, which
  accepts the source gate), no experiment code (see `REV-074`, which returns
  `revise` on two code defects including a control-transfer regression

  disposition; no evidence run exists and none may be performed until the method
  and code gates pass. Every number quoted here is from reviewer scratch runs on
  `Mac16,10` (M4) / macOS 26.6.2 (25G83) / SDK 26.4, diagnostic of oracle
  discrimination only, supporting no claim in any record and stating nothing
  about `P1` or any platform-wide behaviour. Nothing here authorizes planning or
  implementation.
