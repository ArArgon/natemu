## Defects found and fixed during this self review

Three genuine defects were found by reading the code against the method
text and against each other, not by running the binary (which this review
cannot do). All three are fixed in the hashes above; none remain open.

1. **Unreleased port-set right.** `main()` allocated `g_port_set`
   (`MACH_PORT_RIGHT_PORT_SET`) for the serial topology but never disposed
   of it. Fixed: `main()` now calls `mach_port_mod_refs(..., PORT_SET, -1)`
   after every worker's own teardown and logs a `disposal` record for it.
   This is exactly the class of defect `check.py`'s `check_disposal`
   fixture exists to catch, so it would have been an embarrassing gap to
   ship unfixed. The dedicated data page's `munmap` was added alongside it
   for the same reason, though it is not a Mach right.
2. **Registration race.** `main()` (serial topology's port-set membership
   setup) and every server thread (`perworker_server_thread`,
   `prior_server_thread`) read a worker's `recv_port` field without waiting
   for that worker's own thread to have written it in `register_worker()`.
   Fixed: `register_worker()` now sets a `registration_done` atomic on
   every exit path (success, `PRIOR-HANDLER-UNSUPPORTED`, or any terminal
   failure — via a single `goto done` sink, not a flag duplicated at each
   return), and `main()` spin-waits on every worker's `registration_done`
   before creating any server thread or touching `recv_port`. This directly
   implements "register workers before arming" (`INV-01-06.md:600`) instead
   of asserting it in a comment.
3. **Named hold points did not reset, and one was unused.** The hold-point
   rendezvous incremented `arrivals` and never reset it, so it degenerated
   into a permanent no-op after the first pairing (a hold point is reached
   once per checked event, not once per process). Fixed with a generation
   counter: a waiter blocks on the generation changing rather than on
   `arrivals < 2`, so the second arrival can safely reset `arrivals` for the
   next round without racing a waiter that has not yet re-checked the
   predicate. Separately, `HOLD_PRIOR_BEFORE_REPLY` — one of the eight named
   holds in `INV-01-06.md:736-737` ("front before forward **and prior
   before its reply**") — was declared but never called; the prior's own
   repair branch was silently sharing the front's `HOLD_REPAIRED_BEFORE_
   REPLY` point. Fixed: the shared repair branch now selects
   `HOLD_PRIOR_BEFORE_REPLY` when serving the prior's own port. This
   machinery is gated off by default (`--holds`, never passed by this
   session) and so was never exercised by an actual `mach_msg` exchange;
   the fix is reviewed by inspection and reasoning about the two-thread
   rendezvous, not by execution.
