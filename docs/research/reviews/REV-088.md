## Verdict

- Verdict: `revise`
- Rationale: The one required action from `REV-073` is fully closed, and closed
  on the stronger of the two branches it offered — the enforcement branch rather
  than the restatement branch. I did not accept the author's report: `check.py`
  now returns 2 for an unwitnessed targeted invariant, `run_one` captures that
  status and sets `status=1`, and a copy of `run.sh` with one control
  deliberately mis-targeted exits 1 end to end while still recording the
  expected FAIL verdict — so a control that silently stopped witnessing its own
  invariant can no longer pass as an expected failure. The supporting method
  text in both the INV and the README now states exit 2 and the runner's
  treatment of it, the self-check grew to 53 mutations plus a synthetic-document
  assertion, and the new `I16` criterion is properly predeclared with a Metrics
  row, a threshold, an invariant and a guest test. Nothing from the two previous
  returns regressed: parallelism measured 2.00× in five of five runs, all six
  controls fired their targeted invariants with no UNWITNESSED, and the
  short-circuit added for abort-only documents is correctly scoped so
  `--inject-skip-restart` is still evaluated in full. One new issue blocks
  `accept`, and it is genuinely load-bearing given what happens next:
  `CLM-01-12-05`'s frozen prediction of `pf_count == 3` contradicts the frozen
  oracle's `4`, and authorizing the evidence run against two different
  predeclared values for one counter would leave the result gate choosing
  between them after seeing data. The fix is a single cell. `accept` is
  prohibited while it is open.
