## Required changes

- R1 — investigation owner; return to source gate: correct `CLM-01-18-07` to preserve §B2.2.5's conditions. State that, outside the enumerated restricted replacement cases, the synchronization requires (a) no PE executing the instruction while another modifies it, (b) the applicable writer maintenance/barrier sequence, and (c) ISB **or a context synchronization event** on each executing PE after the instructions become observable. Preserve the Inner Shareable domain qualification and the explicit exception to `DC CVAU` for Non-cacheable/Write-Through Cacheable memory. Note that changed VA-to-PA mappings can fall under the same CMODX rule. The restricted cases guarantee only the specified old-or-new behavior; do not infer fresh-code visibility, safe reclamation, or an Apple protocol from them.
- R2 — investigation/source-ledger owners; return to source gate: repair the `SRC-105` mapping to -07 and its premise mapping to -09 to match R1; qualify -09's architecture premise to the applicable modification case. Retain the existing limit that `sys_icache_invalidate` has not been mapped to the whole architectural sequence. Do not describe a literal ISB as the only admitted executing-PE synchronization action.

Both changes remain open at this return. They concern existing `Q-01-18` and its `Q-01-19` dependency; no new question ID is needed. The source ledger and investigation are intentionally left to the integrating owner.
