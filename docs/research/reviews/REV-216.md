## Independent findings

The original readable-neighbor sentence did not distinguish a dedicated data
extent from protection of the complete single JIT arena. N1 makes that
distinction explicit at the method gate rather than silently substituting
an unrelated data read in code and calling it adjacent. It preserves the
actual protected targets and labels the weaker JIT accessibility observation.

For the data limb, physical adjacency remains mandatory: the neighbor begins
at the first page boundary outside the scheduled full one/four-host-page
target, and both extents must belong to the child's original owned control
mapping. The known neighbor value is read both before and after successful
target-only PROT_NONE. An unprotected page hidden inside a shortened target
cannot satisfy the control. Separate forbidden-target and restored-target
fresh children remain required. Full base/length/ownership and API/errno
checks are not replaced by the neighbor's successful read.

For the JIT limb, the whole same16MiB arena remains protected. No inside-arena
page can be both outside that target and its readable neighbor. N1 neither
claims that an outside physically adjacent mapping is impossible nor permits
probing an unowned one; it deliberately makes no JIT physical-neighbor
observation. The defined replacement observation is only continued unrelated
AOT execution and an owned normal-data read. Exact function/data addresses
must be outside the arena, and both actual executions/reads bracket the
successful protection call, with the second occurring while the entire arena
is still PROT_NONE. Known before/after values and API/range records are
required. It would not satisfy this method merely to print constants or
record an AOT address without executing the specified access; actual code
and compiler/disassembly validation belong to the later code gate.

This accessibility observation does not stand in for JIT denial or restoration.
The forbidden generated-code call remains a separate pre-thread sacrificial
child with durable pre-attempt marker and expected signal termination.
Unrelated startup failure, missing marker/status or normal completion cannot
be called that negative. The separately restored child still requests the
original protections over the same entire arena, performs the declared
normal-context approved empty callback restoration candidate, invalidates,
executes ISB and checks the generated pair. It must observe that restoration,
not infer it from successful AOT/data accessibility. Signing C still forbids
the toggle API; no handler resumes modified JIT code. Public mprotect's
interface/failure contract does not supply a source-backed guarantee for
this callback/JIT composition, and N1 says so explicitly.

The original M protocol's all-ACK STOP/RESUME, mapping-worker old/new values,
exact targets, callback/cache/range/ISB checks and generation/lifetime oracles
remain operative. This pre-thread control cannot itself demonstrate SMP
quiescence. Three fresh repetitions, one/four-page data sizes, one16MiB arena,
1/2/4/8 scheduling identities, local A/B/C scope, watchdog/raw/status records
and all stress/cost floors remain. A failed or unavailable applicable limb
stays unresolved/invalid; the other limb cannot cover it. The one-factor
covering design is not silently enlarged into a measured Cartesian product.

The change is therefore an explicit, bounded clarification of what the JIT
accessibility control can establish, not a claim that physical-neighbor
coverage was obtained or that every other mapping remained unchanged.
No target shrink, second arena, unowned-address test, new source-backed API
guarantee, code acceptance, cost waiver or architecture choice is introduced.
The full Q18 publication/quiescence/mapping/cost question is retained; cost
still requires eligible same-host Q07 instrument evidence and local calibration.
No required method correction was found in this submitted clarification.
