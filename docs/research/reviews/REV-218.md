## Independent findings

### Bundle and provenance identity

The 17-file bundle digest is the canonical sorted compact JSON mapping of
relative filename to file SHA-256, hashed with SHA-256, exactly as
`src/authorization.py:18-40` defines it. Recomputing it here yields
`e48e4cead8174ccefd8ce623c34115e9d26e9ad1abe2b2e96b952c5910d68943`, matching

(verified by inspecting the built binary's literal strings). Copying the

derived from the bytes on disk at build time, not from a label.

### Native producer, fault path and lifetime

The independent inspection of `src/litmus.c` and `src/fallback.h` reaches the
same conclusions REV-210 reached on the unchanged native body, which this
return did not alter apart from the R3 stamp. Four uniquely identified
workers, explicit user-interactive QoS before ready, C11 ready/go/abort
synchronization, 250000 protected increments each, a fresh 128-aligned
256-byte allocation, offset 78/width 4 with fixed adjacent canaries, and
distinct completed-iteration/lock/unlock/actual-write counters. The injected
lock error (`src/fallback.h:46-48`) is evaluated before the lock and cannot
enter the RMW; the omitted store (`src/fallback.h:53-56`) skips both the store
and the write counter. `src/fallback.h:130-134` refuses `pthread_mutex_destroy`
after an unlock-error ownership ambiguity and `src/fallback.h:192` refuses the
matching `free`, so no recovered-and-timed path exists; `fb_join_fatal`
(`src/fallback.h:71-86`) exits 91 through coordinator-only output without
touching live worker storage.

The unexpected-fault path is confirmed `_exit`-only and async-signal-safe at
the instruction level, not merely by `validate.sh`'s grep: in the optimized
`build/litmus.s`, `_fault_handler` contains exactly two calls, and the branch
taken when `si` is NULL, when `g_in_probe` is clear, or when `si_addr` lies
outside the recorded 4-byte probe window falls through to `mov w0, #90; bl
__exit` with no intervening call. `bl _siglongjmp` is reachable only from the
expected-probe branch. REV-202 R2 therefore still holds; this is not approval
for general exception recovery.
