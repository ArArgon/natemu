## Findings and required changes

### R1 — fallback timing lacks its required correctness oracle

`fallback_thread` ignores both mutex return values. `run_alignment` records
planned operations, elapsed time and derived ns/op, but neither records nor
checks the initial/final counter or expected update count. Unlike the LSE arm,
the fallback has no lost-update oracle. I1–I14 contain no fallback predicate;
T2 only tests the supplied `ns_per_op < 500`. Thus successful process exit and
the historical fourteen-rule PASS do not establish successful fallback RMWs.
The separate reviewer reports that a synthetic fallback row with zero
threads/ops/elapsed and negative ns/op still receives T2 MEET/PASS; this
reviewer did not rerun that mutation, but the missing validation is directly
visible in the inspected code.

Required: reopen the affected method/code/result/replication dependencies.
Specify the fixed workload and initial state, checked lock/unlock outcomes,
expected final value/no-lost-update predicate, valid positive timing/count
fields, primitive-derived cost, and negative/malformed/missing-oracle tests.
Obtain method acceptance before code repair, code acceptance before new data,
then correctness-qualified results and independent replication. The missing
observed counter cannot be reconstructed by applying a new checker to old raw.
Keep old raw and T2 output as historical artifacts, not qualified evidence for
claim -11. Preserve the functional fallback question; do not close it by
dropping the hardware-refused guest-legal atomic case from scope.

Independently, one mutex implementation on one address is not a demonstrated
cost **floor**, a uniquely required strategy, or a complete x86 split-lock
implementation. Withdraw those statements in claim -11 and the resolution.
Any future positive cost claim must name the actually validated operation and
exclude untested ordinary/mixed/overlapping accesses that do not participate
in that locking protocol. Guest compatibility remains an obligation, not a
selected architecture.

### R2 — unexpected-fault termination is not contract-safe

`fault_handler` calls `fputs` and `fflush` before `_exit(90)` when outside the
probe window. The captured sigaction NOTE explicitly excludes functions absent
from its safe list; neither stdio call is listed. Failure-path success during
a smoke test would not establish a contract, and a stdio deadlock or another
fault could prevent the intended termination.

Required: reopen this producer failure-path method/code validation. Specify a
source-justified bounded termination/reporting path with no unsafe handler
stdio, plus sacrificial-process negative checks and a parent timeout/status
oracle. Recheck recovery/probe classification assumptions as part of that
return. This is a real code dependency outside REV-198's reporting-only scope;
transactional Python output cannot repair unsafe C signal handling. It does
not prove that a manifested normal run encountered the defective branch.

### R3 — aggregate elapsed/attempt is not isolated instruction cost

LSE timing starts before thread creation and ends after joining all workers.
The numerator includes creation/join, scheduling, loop/load/branch work and
attempt bookkeeping; the denominator is attempts across parallel workers.
The ratio is an aggregate elapsed-time-per-attempt measure, not instruction
latency. Counting CAS attempts usefully separates two denominators through
`elapsed/success = (elapsed/attempt) × (attempts/success)`, but does not isolate
causes of scaling or make retry effects disappear from contention.

Required: correct claims -12/-18, Metrics, Results, resolution and alternatives
to the bounded aggregate metric; retain attempts/success and both threshold
results. Rewrite -18's exact Observed proposition so it reports the actual
67.3297069389583×/66.1658439610570× misses, rather than saying the ratio is
within60× and contradicting that proposition in the status column. Do not
soften the misses or convert cost into a KA-06 falsifier. No new run is needed
merely to label the existing arithmetic correctly.

### R5 — histogram and sample descriptions overstate identification

The operative diagnostic compares the both-observed cell fraction; retaining
all four cells does not make that test a whole-distribution equivalence test.
Neither a both-observed outcome nor the iteration barrier measures physical
execution overlap or demonstrates equal scheduling between mappings. Replace
the claim that the histogram adjudicates those alternatives with the actual
limited screening rule. The MP/DMB/background cross-run flip is observed
variation, not an established effect of "noise alone". No warm-up exclusion
does not guarantee conservative bias under unknown frequency/load effects.

Required: repair the causal/statistical prose, retaining the accepted exact
zero cases, inclusive [10/3,30] band, compatible count pooling and separate
matching-plain-exposure prerequisite. Only MP/LDAR-STLR/background has bounded
corroboration eligibility; UI has zero matching exposure, all SB pairs remain
inconclusive, and MP/DMB/background remains indeterminate. No finite-sample
probability bound or prohibition is licensed. This is an interpretation
repair, not permission to replace the rule after seeing results.

### R6 — scope qualifiers need consistent application

Eight host workers on a ten-core machine are not demonstrated oversubscription
or eight guest vCPUs; the applicability row must not label their placement
"oversubscribed". Keep oversubscription/lock-holder-preemption and full guest
composition open. Claim -14's specific tag=1 call returned
`KERN_NOT_SUPPORTED`; "this host does not support it at all" exceeds that
single observed request. Alignment claims must name the tested 32-bit
instruction/offset cases and not turn six categorical probes into exhaustive
all-address/all-width coverage or deterministic future behavior.

The breadth pass explicitly requires preceding clock characterization for
the round-trip metric. Trace the applicable accepted instrument evidence in
the finding return, considering INV-01-07's reopened timing work. This probe
reads both endpoints on the sender, so a cross-thread timestamp defect in a
different probe is not by itself a demonstrated defect here. Equally, a
recorded timebase alone must not silently stand in for whatever instrument
prerequisite this method actually requires. Preserve the flag-handshake-only
scope: no TLB visibility, remote-core identity or live-patch result follows.
