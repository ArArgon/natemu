## Required changes

1. `INV-01-07` owner, return to code gate: correct the record's statement that
   "the primary latency measurement is unchanged". The formula, the `woke`
   capture points, the `err[i]` store, and every mechanism branch are indeed
   untouched — I verified that by grepping the diff for each of them and
   getting no hits — but the correction reorders the two reads at the top of
   the loop, so one `clock_gettime_nsec_np` call now sits between `base_abs`
   and entry to the wait where previously it sat before `base_abs`. Every
   reported wakeup error is therefore inflated by one clock read, tens of
   nanoseconds, relative to the previous build. Say so, and state that it is
   immaterial against the 250 µs `T2` bound (about 0.01%) — which it is. The
   claim as written invites a later reviewer to compare `MAN-01-07-01`'s
   wakeup figures with the re-run's as if the measured path were identical,
   and it is not quite.

## Verdict

- Verdict: `revise`
- Rationale: the code is correct and the diff is disciplined. It is confined
  to the stated hunks; the implementation matches the method's description of
  the bracket exactly; the emitted tolerance makes the artifact
  self-describing; the regenerated fixtures still cover every rule including
  `I16`; and `validate.sh` and both run modes pass. Most importantly `I16` was
  verified by injection rather than by inspection: it fires one nanosecond
  over tolerance on an enforced arm, stays silent for the same magnitude on a
  background arm, still fires on a 1% conversion artefact after the narrowing,
  and treats the boundary as strictly "more than". The dispatch exclusion is
  confirmed necessary on real data. `accept` is prohibited by one small
  accuracy defect: the record claims the primary latency measurement is
  unchanged, when the read reordering inserts one clock read into the measured
  path. The effect is about 0.01% of the `T2` bound and changes no conclusion,
  but it should be stated rather than denied, because a later reviewer will
  otherwise compare the failed run's wakeup numbers against the re-run's as
  like for like.
- Applicability limitations: this verdict covers `experiments/INV-01-07/` at
  `13c6e98` only. It approves no evidence run and no claim. Every measurement
  quoted here was produced by this reviewer for code validation on `Mac16,10`
  (M4) / macOS 26.6.2 (25G83) / SDK 26.4 at `--n 60` under concurrent load,
  written to a scratch directory outside the session raw root, with no
  manifest; it is not evidence and no record may cite it. A worst-case-over-N
  metric grows with N, so nothing here bounds what a 2000-sample run will
  show.
