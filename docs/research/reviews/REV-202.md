## Independent findings

### R1 — fallback correctness is not checked before its cost is promoted

Observed from the producer and raw JSON: `fallback_thread` ignores both mutex
return codes. After joining four workers, `run_alignment` records only
`threads`, the intended `ops`, `elapsed_ns`, and `ns_per_op`. It never reads
the final target value, checks it against a known initial value plus completed
increments, or records lost updates. Neither the main checker nor the
independent verifier has a fallback correctness invariant. LSE's final-counter
oracle does not cover this different arm.

The normal raw fallback object is exactly four fields:
`threads=4, ops=1000000, elapsed_ns=19063625, ns_per_op=19.06`.
The replication likewise contains no correctness observation. A second timing
number cannot retrospectively supply the missing oracle.

Independently reproduced non-evidence counterexample: load the digest-matched
normal JSON into memory, change only its fallback object to
`threads=0, ops=0, elapsed_ns=0, ns_per_op=-1`, and call the current checker's
`main` with that in-memory object. It returns 0, prints
`MEET T2 software fallback under 500 ns/op at 4 threads: -1 ns/op`, and
`RESULT: PASS (0 integrity failures)`. No repository fixture or raw artifact
was changed. REV-198's exception transaction does not address this case:
these malformed values cause no exception.

Inferred consequence: CLM-01-08-11/T2 is not established as the cost of a
correct software fallback. This is missing correctness evidence, not proof
that an actual lost update occurred. It does not by itself refute the
separately checked litmus counts or LSE counter outcomes.

Required repair must retain the software-fallback research limb. Approve a
method amendment defining initial/final-value and completed-operation oracles,
mutex-error handling, input/arithmetic validation and a deterministic defective
control before implementing them. Review the resulting producer/checker code
before fresh normal/negative collection and independent replication. Existing
fallback timings must be held as unvalidated diagnostics, not promoted by
adding fields after the fact. Preserve the original raw and historical review
records. No failed-correctness sample may supply a timing claim.

### R2 — unexpected-fault abort is not reliably signal-safe

Observed from `fault_handler`: when `g_in_probe` is false, it calls `fputs`
and `fflush` on `g_out` before `_exit(90)`. The inspected Apple manual's
NOTE excludes those functions from its signal-safe list and explicitly
describes unlisted functions as unsafe. The path can interrupt stdio while
the handler is installed, so it cannot promise a reliable fail-closed exit or
valid JSON. Flushing an error record from a handler is not a correctness
defence merely because the normal run did not encounter the path.

Required repair: use an async-signal-safe termination/diagnostic path, with
any structured report emitted outside the handler. Add a bounded targeted
negative control proving an unexpected fault cannot become a completed
normal result or hang the runner. Review the code before new evidence runs.
This finding does not assert that the unexpected-fault path ran in the
existing successful artifacts or that their recorded alignment signals are
false. It reopens the producer's claimed fault-containment defence.

### R3 — measured denominators do not isolate instruction cost or a cost floor

Observed from `run_lse`: one coordinator wall-clock interval begins before
thread creation and ends after all joins. It includes scheduling, loop
instructions, the CAS loop's separate relaxed loads, retries, and completion
accounting. Dividing that interval by total attempts across parallel workers
is a well-defined aggregate harness-time-per-attempt statistic; it is not an
isolated executed-instruction latency. Dividing the same interval by successes
does expose the exact denominator effect of retry amplification, but does not
separately identify instruction cost as claimed by the resolution and
Alternative explanations. The arithmetic identity is not causal isolation.

Likewise, a single shared address not benefiting from address striping does
not establish that this global-mutex algorithm is a lower bound on all
correct fallbacks. CLM-01-08-11's `cost floor` inference is unsupported.

Required repair: preserve the observed counts, ratios and T4b miss, but define
the measured intervals and their aggregate denominators accurately, including
creation/join and loop overhead. Remove the isolated-cost/clean causal
separation and cost-floor assertions. Do not infer an upper or lower bound
from omission of warm-up. A method/result interpretation return can close
this without rerunning the unaffected LSE arms solely to rename a metric.
The exact Observed wording of claim -18 must state the actual miss, not
assert within-60x in one column and contradict it in another (also identified
by self REV-201). T2's claim about a rare guest operation not dominating
"any realistic instruction mix" lacks a measured frequency/workload model;
preserve 500 ns as the predeclared screening convention, not a demonstrated
guest-affordability guarantee.

### R4 — source and applicability qualifications remain inconsistent

The following are bounded corrections, not reasons to weaken the histogram
rule or require a second machine now:

- Source-backed CLM-01-08-01 and its resolution omit the WB-cacheable-memory
  scope explicitly preceding Intel §11.2.2's principles. Restore it in the
  claim and corresponding mapping; do not present these four directions as
  an unrestricted contract for every guest memory type/access.
- Self REV-201 additionally challenges claim -07's transition from "not
  shown" to universal necessity. Direct rereading confirms the inference
  needs either an explicit proof-obligation formulation or exact positive
  source/counterexample support; absence of proof alone is not that support.
- The investigation now correctly treats the two quoted bob clauses as a
  subset of seven. README and check.py's explanatory comment still call
  `bob = po; [dmb.full]; po | [L]; po; [A]` the definition. Mark that as an
  excerpt/subset or give the full definition. The inspected paper supports
  the strengthened SB prohibition; this correction must not remove I5.
- Alternative explanations says the rule compares the whole distribution
  and measures actual overlap. The implemented decision uses one histogram
  cell. In MP, writer completion before reader execution can also produce
  the both-observed cell; it is not a direct measurement of simultaneous
  execution or schedule equivalence. Keep the accepted conservative
  diagnostic and matching-exposure prerequisites, but remove the stronger
  causal claims, including `the barrier suppressed overlap` and the claim
  that the between-run category flip was `on noise alone`. Neither mechanism
  was independently measured. Bounded corroboration is not exclusion of
  every timing/interleaving alternative.
- The matrix labels eight vCPUs on the ten-core host `oversubscribed`, while
  the actual arm uses eight host threads and controls neither core placement
  nor the scheduling allocation. It establishes no oversubscription cell.
  Keep Q-01-23 liveness/oversubscription debt explicit instead of marking
  that topology as measured.
- As identified in self REV-201 and confirmed against the subject, scope
  tag=1 affinity rejection to the actual request and alignment observations
  to the tested 32-bit instructions/offsets. A single request or six cases
  are not exhaustive unsupported-API/all-address/all-width findings.

Return the documentary source qualification to the source gate and the
interpretation/applicability corrections to method/result review. Record the
newly identified gaps under their existing Q-01-08/Q-02-02/Q-04-01/Q-01-23
owners; no new question identifier is inherently required.
