## Challenge findings

The obvious shorthand, main queue always means main thread, is contradicted
by the manual's explicit dispatch_main compatibility exception. The candidate
therefore preserves the CF main-run-loop condition and excludes dispatch_main
as an affinity proof. The general serial-queue/pthread_self warning is not
erased; any actual instrument must verify constructor and callback identity
and keep failed/missing identity checks rather than select successful samples.

The CoreFoundation header merely establishes an available API surface. It
does not prove that a loop remains alive, when a callback runs, whether any
deadline was met, or how an opaque dispatch timestamp converts to raw ticks.
It is not a replacement for the independent method193/194 return. That method
must retain actual requested-deadline/no-early, strict/non-strict, global-queue,
both-QoS and 1/2/4/8 sustained-cadence obligations without reclassifying missing
coverage as success. A new queue is a distinct cell, not a correction that
can be applied retroactively to existing data or compared as like-for-like.
