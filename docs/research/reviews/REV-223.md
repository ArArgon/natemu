- **R3 — Add an instrument-validity control on the notification path itself.**

  detectability instrument," but delivery into a non-bundled, backgrounded,
  run-loop CLI child is exactly what `CLM-01-21-05` (line 69), `REV-129` R2,

  T5 is a `pthread` read-back and C1 an in-process token. A `not-bracketed`

- **R4 — Make the clock buckets mutually exclusive and state what `frozen`
  and `insufficient-samples` can actually mean.** At line 283, `advanced`
  ("monotonically non-decreasing") is satisfied by a frozen clock, so
  `advanced` and `frozen` overlap. Redefine `advanced` as strictly increasing
  by more than the recorded sampling granularity. Then state which arms can
  reach `frozen` at all: observing `frozen` requires the sampling thread to
  run while the clock does not, which system sleep precludes, so for T1 the
  reachable outcome is `insufficient-samples` and `CLM-01-21-02`'s
  "confirmed-`frozen`" falsifier (line 66) is inert there. Line 286 calls

  state explicitly that it is not evidence of clock suspension and, after R9,
  that it must first be attributed to the harness or the host.

  expected periods," but busy workers have no period: they heartbeat every
  2^16 iterations (lines 141–142), so their cadence varies with the throttling

  manipulated variable, and "slow" is not separated from "suspended." Define a
  worker gap criterion not derived from the arm's own manipulated variable,
  and name which of the five clocks measures each gap: a T1 gap measured on
  `mach_absolute_time`, which does not advance during sleep, classifies a real
  suspension as `continuous`, while the same gap on `mach_continuous_time`
  classifies it `paused-then-resumed`. State in the same place that the
  qualitative buckets are therefore not clock-free — they use the under-test
  clocks as a coarse ordinal device — which bounds, without violating, the
  no-`INV-01-07`-dependency statement at lines 96–101.

## Verdict

- Verdict: `revise`
- Rationale: `M21-1` is a serious, well-bounded proposal — the same-host
  applicability statement, the diagnostic-interval quarantine, the
  never-deleted denominator, the non-simulated `not measured` fallback, the
  refusal to induce thermal pressure artificially, and the explicit IOKit
  supplement declaration are all correct, and mandatory check (10) is
  confirmed: no claim or classification depends on the unaccepted `INV-01-07`
  instrument. It cannot be accepted as written. Three defects are structural
  rather than editorial. First, the method's sole detectability instrument is
  a notification path whose delivery into this exact process configuration the
  record's own accepted source claims leave unresolved, and no control
  discriminates a dead instrument from a host that does not notify — so
  `CLM-01-21-03`'s falsifier would be charged to the host on harness evidence
  (R3, R8). Second, the classification buckets are not mutually exclusive and
  the progress threshold is undefined for the busy workers and unanchored to a
  named clock, so the central "suspended versus slow" decision is not
  decidable as specified and can invert with the choice of clock (R4, R5).
  Third, several load-bearing mechanisms — `pthread` QoS, `clock_gettime` and
  its clock IDs, the dispatch timer, `pmset`, `LSUIElement` — sit outside the
  accepted packet while line 176–181 states the opposite (R1, R2). Thirteen
  required changes remain unresolved, so `accept` is prohibited by the
  critique template and the evidence policy's gate-completion rule.
- Applicability limitations: method-proposal review only, for the single
  available `Mac16,10`/macOS 26.6.2 (build `25G83`)/SDK 26.4 host. This review
  approves no code, no execution, no observation, no App Nap, forced-sleep or
  lifecycle guarantee, no timing or cost number, no P1 or platform-wide
  statement, and no synthesis or implementation authorization. The accepted
  source packet (`REV-156`) is untouched and is not widened here. Independent
  code review and the result gate remain required after a corrected method is
  independently accepted.
