## Required changes

1. `INV-01-07` owner, return to code gate (jointly with `REV-064` required
   change 1): change `check.py`'s `T3` to the round-trip form the record
   predeclares. The checker computes
   `bp99 = min(s["p99_ns"] for s in signal if …)` and tests `bp99 < 100000`,
   labelling it "one tenth of the 1 ms guest tick period"; the record's
   Metrics table and `CLM-01-07-15` define `T3` as round-trip p99 < 200 µs
   ("one fifth of the 1 ms guest tick period") and state that the one-way
   figure "is **not** a standalone threshold". `roundtrip_p99_ns` is present
   in the JSON and is read by rule `I17`, so the fix is to evaluate `T3`
   against it. The two are not interchangeable: `I17` only requires one-way ≤
   round trip, so a run with a one-way p99 of 90 µs and a round-trip p99 of
   250 µs would print MEET while missing the record's threshold. Fix before
   any evidence run, since the record forbids changing a threshold after data
   exists.

- Rationale: thirteen of the fourteen `REV-045` required changes are closed,
  and each was re-derived by execution rather than by reading the gate table.
  The disqualifying defect is gone: the reviewer's own injection of an
  architecture-forbidden SB relaxed outcome under `STLR`/`LDAR` now fails

  standalone one-way latency that the record explicitly says is not a
  threshold, at a bound derived differently from the record's. It is a
  three-line fix, but it must land before any evidence run.
