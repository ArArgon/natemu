## Disposition of REV-178

**R1 (nested same-class witness) — substantively closed, one residual defect.**
Each element the prior reviewer required is now operative rather than implied.
Lines 261–276 give a six-row table naming the handler identity, `sa_mask` and
flags for every participating signal in both configurations; `SA_NODEFER`
appears only in the D fault row, and lines 277–282 state the effective-mask
union and record that same-class BUS-in-BUS and SEGV-in-SEGV are *requested*
rather than assumed to degrade into the other class. Lines 265–269 keep P free
of `SA_NODEFER` and mask both fault classes during R recovery, so the admitted
positive discipline is not silently altered by the diagnostic. Terminal depth
is distinct from the two-positive-depth rule at 296–306: positive depth counts
only normal-return A/R handlers to a maximum of two, D reserves a terminal
depth of parent+1 up to three, depth three never returns, repairs or re-arms,
and a fourth entry or wrong parent takes a fail-closed `_exit` that lines
305–306 explicitly deny as denial evidence. Witness storage is unique per
worker, event and parent depth at 322–331, with immutable execute stubs held
separately from any slot the Q18 test may patch or reclaim. Crash-as-success is
refused in four independent places (lines 305–306, 345–347, 351–353, 371–376,
and again at the stop criteria, 597–601). Lines 386–397 add the honest
consequence the prior critique did not ask for: because P and D masks differ, D
permission samples are configuration-qualified and cannot be borrowed to
classify a P cell. Line 333–334 removes the other obvious misattribution by
requiring the deliberately PROT_NONE arena phase to predict both accesses
denied rather than a per-thread transition.

The residual defect is documentary, not structural. The whole D contract rests
on two facts — the `SA_NODEFER` meaning and the mask-union rule at 277–289, and
(for the depth-2/3 stack) the alternate-stack switch rule — that are present in
the accepted captures but are not registered as inspected sections in the
source table (lines 63–64) and are carried by no claim (lines 108, 109, 114).
By the method's own rule at 296–299, a cell whose required mask setup cannot be
validated against the source/API baseline is blocked; as filed, that rule reads
against the D cells themselves. RC1 and RC2 below fix the registration.

## Independent findings

*Async-signal safety of the in-handler surface — clear.* Lines 182–197 confine
handlers to scalar automatic locals, read-only context accessors and audited
inline lock-free atomics, verified by compile constraints and normal-context
`atomic_is_lock_free` checks, with disassembly required to reject out-of-line
atomic helpers, TLS resolution, lazy binding and compiler-emitted copy/stack
helpers. `_exit` is the only permitted library call and is present in the
captured Base Interfaces list (capture lines 199–206), so the one permitted
call is genuinely source-backed. Telemetry deliberately avoids a libc write
path, which removes the usual pipe-atomicity argument. Two residual limits
worth recording, neither blocking: the libc signal trampoline that runs before
the handler is not part of the audited call graph, and a handler that spins on
its own acknowledgement word (lines 234–237, 355–360) depends on helper
progress, which the method bounds only by the external watchdog — a starved
helper costs coverage rather than producing a false pass.

*Alternate stack — sizing is adequate but the nesting assumption is unstated.*
Lines 463–466 require a distinct prefaulted per-worker stack of at least
`max(64 KiB, 4*MINSIGSTKSZ)` with guard pages and registered address/size, and
lines 467–468 check entry SP against the registered range plus canaries after
return. The size budget is not the problem. The unstated part is that depth 2
and depth 3 do not get a fresh stack: the cited `sigaltstack(2)` capture states
that the system switches to the signal stack only if the process is *not
currently executing on that stack*, so P's depth-two positive nesting (472–478)
and D's depth-three terminal witness (296–301) all run down one alternate
stack, carrying three nested arm64 saved contexts. M19-2 never names this, never
requires the SP relationship between depths to be checked (only that each SP is
in range), and never registers the source clause that makes it true. If the
platform behaved otherwise, a depth-two entry restarting at the stack base
would silently clobber the outer frame that the method requires to return
normally — the exact failure P's nesting oracle is meant to detect. RC2.

*Fork-per-cell isolation — clear.* Lines 172–177 require a fresh *executable*
child per cell/repetition/negative arm and explicitly forbid forking a running
multithreaded JIT process, which is the right call given the callback contract
and the arena. Pre-arm identity and state are recorded durably by the parent
before the child arms, and exit/signal/timeout are recorded even when the child
cannot flush (173–176). Inherited signal masks are not assumed empty (271–272),
which is the correct handling for a mask that survives `exec`. Sacrificial
children die by `_exit` on the D path rather than by crashing, so the heavy
diagnostic population does not depend on crash capture; where a child does die
by signal (the blocked-delivery containment arm, 347–350), crash-reporter
interference can delay reaping and trip the 5-second no-progress watchdog, but
that outcome is recorded as coverage/integrity debt (597–601) and cannot become
a pass.

*Per-thread JIT state observed from a handler — coherent, with one storage gap.*
Lines 378–383 correctly refuse to treat
`pthread_jit_write_protect_supported_np` as a state query and fall back to
access probes: an aligned store to a dedicated non-code arena word and
execution of an immutable pre-validated stub, in disjoint slots, each in a
separately armed D sibling. Because a handler runs on the interrupted thread,
those probes do observe that thread's state; the alternate stack changes the
stack, not the thread, and the method's identity route (198–204) locates the
handler by the automatic-local address within the registered alt-stack range
rather than by any TLS query, so nothing in the identity path assumes
otherwise. The gap is that the method never states where the instrumentation
itself lives. Lines 176–178 create alternate-stack storage, trace slots and
descriptors "in normal context" without requiring them to be outside the
MAP_JIT arena. If any of them were inside it, every handler store — the very
mechanism recording the result — would itself depend on the per-thread write
state under test, and a P-lane trace commit could fault or silently succeed for
the wrong reason. This is one sentence of method text and belongs in RC2.

*R-lane PROT_NONE retry, TLB and multiple workers — one real hole.* The repair
path is well separated: the handler only release-publishes a request and waits
on its own acknowledgement, while a normal-context helper (not a stopped vCPU)
calls `mprotect` on that worker's dedicated data page and publishes the
acknowledgement only on a successful return (lines 234–239). What is missing is
what happens when the retried instruction faults a second time on the same
descriptor. The method's identity rules (229–233, 314–320) consume the witness
token once and treat a repeat as replay, so a benign second fault — a
permission upgrade not yet visible to the faulting core, or any lazy
revalidation after the cross-core shootdown — lands on the fail-closed `_exit`
path and is scored as failed coverage rather than as a bounded, expected
observation. The method needs an explicit bounded re-entry policy that
distinguishes a re-fault at the identical PC/address on a live repaired
descriptor from replay and from a failed repair, and it should require the
same-cell no-JIT retry baseline (line 241) to report whether re-faults occur
before the composition cells run. Related and cheap: with 2/4/8 workers each
holding a private page and each helper calling `mprotect`, the method should
require those pages to be page-aligned in distinct recorded extents, so that no
helper's protection change can alter another worker's expected permission
through extent coalescing or splitting. RC3.

*Stop criteria, sample and watchdogs — sound per cell, unbounded in aggregate.*
Per-cell counts (lines 571–577: three fresh children, ten tagged warm-ups and
one hundred checked events, with warm-up errors still failing correctness) are
honestly labelled coverage conventions rather than reliability bounds, and the
seed rule at 578–582 shuffles only independent cells while forbidding pooling
across host/signing/API/topology/discipline/fault-class strata. Stop criteria
(593–601) preserve missing injection, ambiguous denial and malformed traces as
debt and forbid rerunning until they disappear, which is the right anti-p-hack
rule. The 5-second no-progress and 30-second child ceiling (584–590) are
adequate for a 110-event child and are correctly described as operational
budgets rather than liveness guarantees. What is absent is any bound on the
manifest as a whole: lines 563–570 cross host/signing/API branch × n ×
retained Q18 discipline × role/checkpoint × lane × single/rotated/simultaneous
target, which is a four-figure child count before negative arms, on the single
available host (line 136 records P1 as unavailable to this session). No
staging order, cardinality estimate or total budget is stated, and the method
gives no rule for which cells run first when the campaign cannot complete in
one sitting. RC6.

*Falsifiers versus the P/D split — now internally inconsistent.* Lines 127–130
still predict "allowed-write / denied-execute samples in supported write
windows, the opposite after normal callback return" as though one lifecycle
produced the pair. Lines 386–397 forbid exactly that: the allowed-only witness
runs a complete P lifecycle, complementary denial evidence comes only from D
siblings whose masks differ, and the two must remain separate. The falsifier
list at 123–126 and the claim applicability column at 103–106 were not updated
for the correction, so the record does not say what P alone or D alone can
actually falsify for CLM-01-19-01 and -02, nor what the maximum achievable
conclusion is (a P-qualified allowed-witness lifecycle plus a D-qualified
denial witness, never a single-configuration proof of both). This is not a
defect in the P/D design; it is the falsifier text lagging behind it. RC4.

*What falsifies the claims, as the method now stands.* CLM-01-19-01 is
falsified by a P allowed-witness that faults, by a post-return checkpoint whose
allowed/denied result contradicts the write-window prediction under either
configuration, or by any wrong-state observation at entry or return; it cannot
be *established* beyond a configuration-qualified pair. CLM-01-19-02 is
falsified by any event that fails the class/PC/address/operation/nonce/thread/
phase conjunction yet is admitted as guest-classified, and by any unmatched
host fault that does not become terminal (lines 229–233, 250–254). CLM-01-19-03
is falsified by any matrix-row invariant violation at 415–423, by a wrong-depth
or out-of-range positive (metrics table), or by a deadlock inside the watchdog
budget; note that it depends on the Q18 pin and is therefore currently
unexecutable (RC5). CLM-01-19-04 is not addressed by M19-2 at all — the cost
metric row defers to a separate method amendment — which is consistent, and the
gate table (668–674) should not be read as advancing it.

*Can M19-2 be executed on the single available host without INV-01-18 results?*
Not as a composition. Lines 145–151 require the accepted Q18 protocol/code
revisions pinned in the manifest and state that Q18 code, validation and result
prerequisites are not supplied by `REV-180` and remain required before
composition execution; line 177 puts the Q18 arena/protocol in every child's
setup; and every row of the publication/patch matrix (405–433) inherits an
exact M18-2 arm and its hook manifest. Fixing the discipline to one accepted
arm does not escape any of those: the arm *is* the Q18 protocol, and INV-01-18's
own code gate is still open (`REV-199` self-accepted, independent `REV-200`
pending, per its gate table at 806). A first stage of "lanes A/R/F/X with
discipline fixed to one accepted-by-method arm" is therefore **not admissible**
under M19-2 as written; declaring it admissible would be a method change owed
to the author, and it would additionally need its own coverage manifest plus an
explicit statement that it discharges no matrix row.

There is, however, a genuinely protocol-free subset already inside the method,
and it is the correct first stage: the same-cell baselines and controls that
name no Q18 object — "exact-PC A normal return without JIT" and "dedicated-page
R retry without JIT" (lines 515–518), the no-JIT retry baseline required before
R composition (line 241), the D preflight controls that induce an owned non-JIT
protected-page fault at depths 2 and 3 using D's actual dispositions (337–346),
the mask/delivery/context-size preflight the method already makes a
precondition (295–299), the alternate-stack and no-`SA_ONSTACK` diagnostics
(463–471), and the offline checker mutations, which are required to be detected
before any runtime work at all (521–527, 575). None of these touch the arena,
the protocol or an INV-01-18 result, and the last two groups are prerequisites
the campaign owes regardless. Running them first is sequencing within the
accepted method rather than a new stage — but the record does not currently say
so, and RC6 asks the author to say it explicitly, because "first stage" is a
scope statement that a code or result reviewer must be able to check. All of it
still sits behind method acceptance and the code gate: line 608 forbids
implementation before an accepted method, and lines 610–614 require code review
of the handler call graph, disassembly, atomics, exact faulting instructions
and classification table before anything executes.
