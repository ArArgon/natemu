## Verdict

- Verdict: `revise`
- Rationale: both trees are small, dependency-free, warning-clean, and honest
  about the raw-artifact contract — this reviewer built both, ran both
  `validate.sh` scripts (PASS), ran normal and `--negative` modes for both,
  confirmed each checker rejects its injected defect on exactly the predeclared
  rule, and confirmed every `run.sh` refusal path (unset, non-existent, and
  inside-repository `NATEMU_RAW_ROOT`) exits 2 while writing nothing under
  `experiments/`. The measurement design is also better than most in the ways
  that matter: raw fields are recorded separately rather than collapsed into
  booleans, the busy loop is `volatile` and its stores survive `-O1` by
  disassembly, and the `set_ok`/`enforced` split proved to be exactly the
  distinction the run needed. `accept` is nevertheless prohibited. Thirteen
  required actions are open, and several would make a PASS misleading:
  `INV-01-09`'s checker hard-fails an outcome its own record calls open, so a
  truthful run can be scored a failure; both runners score a checker crash as a
  successful fault injection; `INV-01-14` asserts a field that can never be
  false, omits the field its own Metrics table declares the descriptor oracle,
  and cannot record a process death as anything but corrupted JSON. Three
  defects are undefined behavior or an unhandled live path: the unsynchronised
  `__block` reads on the vmnet timeout path, the four unchecked `getrlimit`
  calls feeding an uninitialised structure back into `setrlimit`, and the
  "only reachable if" branch that this reviewer's run actually reached. On the
  two hazards this review was asked to probe specifically: the `RLIMIT_CPU`
  arm does not hang or kill the harness as written — the handler is installed
  before the limit, the hard limit is left untouched so no `SIGKILL` follows,
  and a 10-second wall-clock cutoff bounds the loop, which completed in 1.26 s
  for this reviewer — but the restore order is wrong (the default `SIGXCPU`
  disposition is reinstated at line 140 while the 1-second limit is still in
  force until line 141, and `SIGXCPU` is re-raised while over the soft limit),
  which is folded into required change 11's call site review and should be
  fixed by restoring the rlimit first; and the `RLIMIT_AS` arm neither hangs
  nor kills, because on this host `setrlimit` refuses the request outright with
  `EINVAL` — an outcome the code records but, lacking the prior limits, cannot
  interpret.
- Applicability limitations: this verdict covers the code in
  `experiments/INV-01-09/` at `ba66757` and `experiments/INV-01-14/` at
  `5fe6a68` only. It approves no source claim, no method, no raw result, no
  replication, no adversarial finding, and no synthesis outcome; it establishes
  no macOS behavior and no `KA-08`/`KA-13` disposition; and it authorizes no
  evidence run, no planning, and no implementation. Every execution reported
  here was a scratch smoke run made to test the code's own claims about itself:
  it produced no artifact under the raw root, no manifest, and supports no
  Observed claim. The observations quoted (a non-NULL `vmnet_start_interface`
  return with `VMNET_FAILURE`, `getentropy` failing at 257 bytes with `EINVAL`,
  `setrlimit(RLIMIT_AS/RLIMIT_DATA)` failing with `EINVAL`, `EMFILE` at the
  lowered descriptor limit, `SIGXCPU` delivered within one wall-clock second,
  and a 1,074,299,672-byte `phys_footprint` rise) are code-review evidence
  about the probes, not evidence about the platform.
