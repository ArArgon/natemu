## Required changes

1. **M1 — `INV-01-10` owner, return to method gate.** Reconcile the definition
   of "sustainable" with what the method measures. Either (a) restate the
   record's scope as *existence on this host/OS cell at this CLT build*, and
   route cross-release, public-distribution availability to the `P1` run plus a
   documented-availability source check (Apple's CLT download page and
   Homebrew's own supported-release statement, the latter already captured as
   `SRC-061`); or (b) add the missing procedure. As written, the record defines
   a property it does not test, and the "SDK coexistence" metric treats locally
   installed SDK directories as evidence for it.
2. **M2 — `INV-01-10` owner, return to method gate.** Add a provenance
   classification to the probe's output and to the metric — CLT / OS / Homebrew
   / user-local — and predeclare that a user-local resolution does not count
   toward `KA-09`. Then correct `CLM-01-10-04`, which predicts that all seven
   listed tools "resolve … under CLT": on this host `rustc` resolves under the
   user's `~/.local/bin` and `codesign` under `/usr/bin`. This is the difference
   between "a tool exists on the author's machine" and "a tool is publicly
   available on the supported hosts", which is the question.
3. **M3 — `INV-01-10` owner, return to method gate.** Redefine the code-gate
   validation outcome so it is not satisfied by a run in which the kill
   assumption failed. Name the fields `check.py` must *require* true for a
   positive run to count as informative — at minimum
   `tools.clang.present`, `tools.python3.present`, `tools.git.present`,
   `tools.codesign.present` — matching the Metrics threshold that already
   exists but is enforced nowhere. See `REV-054` C1 for the code change.
4. **M4 — `INV-01-10` owner, return to method gate.** Tie the `xctrace`
   functional test to the resolved binary rather than to a fresh `PATH` lookup,
   and record the captured failure message in the JSON so the record's quoted
   reason ("tool 'xctrace' requires Xcode") is verifiable from the artifact
   instead of asserted in prose. On this host `xcrun --find xctrace` fails while
   `command -v xctrace` succeeds, so the divergence the fix guards against is
   already live.
5. **M5 — `INV-01-10` owner, return to method gate.** Make the predeclared
   exclusion executable or delete it. "A tool version reported from a shell
   environment that does not match `run.sh`'s own invocation environment" has no
   second reading to compare against and no definition of "match". If the intent
   is to detect a PATH-dependent reading, state the comparison concretely (for
   example, re-resolve each tool under a normalized `PATH` and exclude the run
   if the two resolutions disagree).
6. **M6 — `INV-01-10` owner, return to method gate.** Either add a Homebrew
   formula-availability check for the tools later tracks need (`cmake`, `ninja`,
   `qemu-system-x86_64`) so the Homebrew limb of the `KA-09` falsifier has an
   observable, or predeclare that limb as out of scope for this record and name
   the question that owns it (`Q-05-05` already owns QEMU version pinning).
   At present the falsifier names a failure mode the method cannot detect.
7. **M7 — `INV-01-10` owner, return to method gate.** State that any `KA-09`
   disposition this record supports covers the build/test/debug limbs only, with
   the profiling limb open pending the `Q-01-01`/`Q-06-03` scope decision the
   falsifier already routes. A partial disposition recorded as partial is fine;
   a partial disposition recorded as `KA-09` surviving is not.
8. **M8 — advisory, not a required action.** The probe already captures the CLT
   package build identifier (`pkgutil --pkg-info=com.apple.pkg.CLTools_Executables`,
   observed `26.4.0.0.1774242506`). Predeclaring it in the sample plan as the
   version key for this inventory would make the named CLT auto-update
   confounder detectable across runs rather than merely recorded.

## Verdict

- Verdict: `revise`
- Rationale: The method is replicable and several of its choices are better than
  the question strictly required — capturing `$PATH`, `xcode-select -p`, and the
  CLT build identifier specifically to exclude a PATH-dependent false absence;
  testing `xctrace` for *functionality* rather than mere presence; stating the
  positive control in both directions; routing profiling, QEMU pinning, and the
  Xcode.app distribution question out to the questions that own them; and
  keeping every inventory claim Hypothesis rather than letting a development
  smoke test become evidence. `accept` is nonetheless prohibited. The central
  defect is that the record defines "sustainable" as public-distribution
  availability across both accepted macOS releases and then measures presence on
  one host, one release, one CLT snapshot — and records no provenance, so two of
  the seven tools it counts as satisfying `KA-09` in fact resolve from the OS
  and from the author's own home directory rather than from any public
  distribution, a distinction the probe's captured paths reveal and the method
  never reads. Around it: the checker outcome the code gate is asked to rely on
  is satisfied by a run with `clang` absent, which is the record's own stop
  condition; the `xctrace` functional check invokes a `PATH` lookup rather than
  the resolved binary, on a host where those two routes demonstrably diverge;
  the Homebrew limb of the falsifier has no observable in the method; the
  predeclared exclusion cannot be applied by anyone; and `KA-09`'s profiling
  limb is conceded as open in the predicted outcome without being recorded as a
  partial disposition. Every required change is concrete and checkable against a
  named section.
- Applicability limitations: This review adjudicates the method of `INV-01-10`
  only, at revision `c497cf3`. It does not adjudicate `INV-01-11`, which
  proposes no experiment. It establishes no toolchain fact and no `KA-09`
  disposition: the tool paths, `xcrun` behavior, and CLT build identifier quoted
  above come from reviewer smoke and fault-injection runs in a scratch
  directory, are not evidence, support no claim, and were not written to
  `/Users/liaozping/orca/natemu-raw`. Observations are bounded to `Mac16,10`
  (M4) / macOS 26.6.2 (`25G83`) / CLT build `26.4.0.0.1774242506` on
  2026-09-04; `P1` remains owed. This review does not accept the sources
  (`REV-052`) or the code (`REV-054`), and nothing here authorizes an evidence
  run, planning, or implementation.
