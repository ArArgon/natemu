## Method challenge and explicit limitations

M06-M1 selects an **experimental candidate**, not a product mechanism:
per-worker receiving ports with EXCEPTION_STATE|MACH_EXCEPTION_CODES and
ARM_THREAD_STATE64. It avoids assuming that the state-only message carries a
thread port. Attribution instead combines the registered receiving port with
an independent assembly cookie, exact PC/SP range, event nonce and address.
This is not malicious-peer authentication; no receive/send capability is
exported by an evidence child, and synthetic message fixtures cannot count as
kernel deliveries. Protected-identity and arbitrary prior-handler support
remain separate source/method questions, not implicitly tested features.

The positive path repairs only a dedicated data page and returns an exact
copy of delivered general state, using no thread_set_state or PC mutation.
An assembly continuation checks the original load/store completed with the
right data, unchanged sentinels/SP and exactly one commit. The tagged XNU
reference explains why this candidate is worth testing but cannot establish
behavior of the running kernel or per-thread JIT state. Successful RPC status
alone is not the restart oracle. Only immutable prepared code is in scope;
faults during callback writing remain the consumer's distinct composition run.

Prior-handler handling is intentionally closed-world and fail-closed. Unknown
overlapping thread handlers block a positive baseline, task handlers remain
untouched, and only an owned same-flavor one-hop chain is forwarded. Returning
failure is not claimed to call a saved same-level handler. Normal teardown
waits for disarm/drain, restores exact saved semantic mask/port/behavior/flavor
state, and proves the owned prior handler receives a later event. Server death,
lost reply or restore failure ends the owned child; no automatic safe fallback
is inferred from it. This narrow baseline cannot establish arbitrary debugger
or crash-reporter coexistence.

The method requires two service topologies and actual 1/2/4/8 worker counts.
Shared-server holds may legitimately queue other faults, whereas independent
eligible servers should make scheduled progress. No service path may require
the blocked worker's lock, grant or acknowledgement. Identity and right-lifetime
checks, exactly-once replies/commits, malformed records and restore mutations
are distinct controls. Deterministic holds are finite coverage, not proof of
all interleavings or simultaneous core execution.

Exact generated wire offsets and cleanup branches are deliberately code-gate
artifacts: the method fixes the input IDL, defines, semantic fields and count
rules, then requires newly generated MIG output, its full include chain and
an independent right-ownership/error-path audit. No code may be produced on
the basis of self acceptance. A missing or unsuitable public cleanup/forwarding
contract discovered there returns to source/method review; it is not filled
with private IPC primitives or an inherited server implementation.
