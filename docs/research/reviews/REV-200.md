### Mandatory check 1 — actual machine instructions

The exact SDK the packet demands **is present** on this host:
`/Library/Developer/CommandLineTools/SDKs` contains `MacOSX.sdk`,
`MacOSX15.4.sdk`, `MacOSX15.sdk`, `MacOSX26.4.sdk`, `MacOSX26.sdk`. `build.py`'s
hard refusal (`build.py:22-24`) is therefore neither a defect nor a recapture
obligation on this host; the fallback path was not needed. `make syntax`,
`build.py` and `codesign` all succeeded; host is `Mac16,10` M4, 10 logical CPUs,
`Darwin 25.6.0`, `Apple clang 21.0.0`, host page size 16384.

Findings from `otool -tV` / `llvm-objdump -d` of `protocol-A`:

- **Entry/hazard SC operations.** `entry[][]`, `page_version[]`, `life[]` and
  `hazard` are `_Atomic` with default (seq_cst) accessors and lower to `ldar` /
  `stlr` / `ldarb` / `stlrb` (73 `ldar`, 110 `stlr`, 26 `ldarb`, 16 `stlrb`).
  `atomic_fetch_add` lowers to `ldaddal`, `atomic_compare_exchange_strong` to
  `casal`, `atomic_exchange` to `swpal` — all acquire-release RMW forms, no
  relaxed variant on a protocol object. `_retire`'s hazard scan is a real
  per-worker `ldar x13,[x12]` loop at `0x957c` accumulating the token mask, and
  `still_current` is inlined as `ldar` loads of `entry`. The explicitly relaxed
  accesses are confined to the trace ring (`ldapr` for `memory_order_acquire`,
  `stlr` for release), which is a single-producer/single-consumer buffer, not a
  protocol object. This matches the M18-2 requirement that all entry/hazard
  accesses are SC.
- **Callback placement and return.** `_write_callback` (`0x688`–`0xab8`) has a
  single entry, a single `ret` at `0xab4`, and three `brk #0x1` bounds traps
  (`__builtin_trap`) for token, slot and `cfg.size+code_offset>stride`. `cbz x0`
  at `0x6a8` short-circuits the null-context restoration candidate straight to
  the epilogue. There is no recursion into
  `pthread_jit_write_with_callback_np`, no `longjmp`, no `exit`, and no signal
  primitive inside it. The prologue words are emitted as one 16-byte vector
  store plus one word (`0xa8c17bfd`), the eight MOVZ/MOVK immediates as two
  16-byte vector stores, and `0xd65f03c0` (RET) is stored at word
  `cfg.size/4 - 1` after the NOP fill. `PTHREAD_JIT_WRITE_ALLOW_CALLBACKS_NP`
  registers exactly this function.
- **Cache range covers every published byte and nothing outside the slot.**
  Five `sys_icache_invalidate` sites. At `0x6828` (`build_code`) and `0x8740`
  (`early-cache-publication`) the arguments are
  `x0 = arena + stride*desc[t].slot + code_offset`, `w1 = cfg.size` — exactly
  the range `write_callback` writes, and `cfg.size + code_offset <= stride` is
  trapped in the callback, so the range can never leave the slot. At `0x66cc`
  (`mapping_change`, `jit-protect`) it is `x0 = arena`, `w1 = 0x1000000` — the
  whole 16 MiB arena, correct after a whole-arena protection round trip. The
  two remaining sites are in the sacrificial `protection_control` child.
- **Reader ISB and compiler barriers.** Exactly two `isb` instructions exist in
  the binary. At `0x3ed8` (`_reader`) the ISB is emitted after the `admit`
  trace record's release store (`stlr x8,[x24]`, `0x3ea4`) and before the
  **single** `blr` in the whole reader function (`0x40e4`, the generated-code
  call); it is skipped only on the deliberate `omit-isb` sensitivity arm. The
  `__asm__ volatile("isb" ::: "memory")` clobber is present in source, so it is
  a compiler barrier as well as an architectural one. As `REV-199` already
  states, ordinary host arithmetic (the inlined `expected()` mix and the
  baseline `strcmp`s) sits between the ISB and the `blr`; I confirm this and
  likewise make **no** claim of literal instruction adjacency. At `0x32fc`
  (`protection_control`) the ISB immediately precedes `blr x8` into the restored
  arena.
- **STOP/ACK/RESUME.** `_request_epoch` release-stores each `workers[i].req`
  (`stlr`) and acquire-loads each `ack` (`ldapr`) in a bounded spin; `resume_all`
  release-stores `resume`; `service_epoch` acquire-loads `req`, asserts
  `hazard==0`, records the floor, release-stores `ack`, then blocks on the
  matching `resume` for stop epochs only.
- **Bounded generated hold.** The hook prologue is a fixed five instructions
  (`stp x29,x30,[sp,#-16]!` / `mov x16,x0` / `mov x0,x1` / `blr x16` /
  `ldp x29,x30,[sp],#16`) calling the ordinary out-of-line host helper
  `_held_call` (`0x8868`: `ldr w1,[x0]; adrp/add x0,"reader-in-call"; b _hook`),
  which reads the atomic release flag. No machine-code atomic is hand-invented; the generated block
  itself is a fixed instruction count for every size.
- **Version recheck.** `publish_one` performs
  `REQUIRE(desc[t].version==atomic_load(&page_version[page]))` between the
  `translator-before-check` and `coordinator-after-check` hooks, inside the
  coordinator's serialization domain, with no ownership release between the
  check and the SC entry store.
- **Mapping syscall path.** `mmap` at `0x6308` is called with `w3 = 0x12` =
  `MAP_PRIVATE|MAP_FIXED`, `w2 = 1` = `PROT_READ`, the recorded owned
  `data_window`/`data_length`, the prepopulated backing fd and a computed
  immutable offset; the return is compared against `data_window`. `mprotect`
  at `0x6294` uses `w2 = 0`, and the restore at `0x64bc` selects
  `w2 = 7` (`PROT_READ|WRITE|EXEC`) for the arena and `w2 = 1` otherwise, i.e.
  the documented original protections. Only one `MAP_JIT` region is ever created
  per process: `protection_control` returns from `main` before the main arena is
  mapped, so the sacrificial child and the instrument child never coexist —
  consistent with the `CLM-01-04-06` single-`MAP_JIT`-region constraint.
- Signing cells verified with the packet's own `run.signatures()`: A
  `flags=0x2(adhoc)`, no entitlements, no hardened runtime; B
  `flags=0x10002(adhoc,runtime)` with `allow-jit` only; C additionally
  `jit-write-allowlist`. All ad-hoc, `TeamIdentifier=not set`, no App Sandbox.
  `pthread_jit_write_protect_np` (the toggle API) is **absent from the binary**
  in every cell — only `pthread_jit_write_with_callback_np` and the
  `_supported_np` capability query appear — satisfying M18-N1's "C still never
  calls the toggle API".

### Mandatory check 2 — genuine held-retired setup (M18-P1)

Traced end to end in `reserve_pressure_slots` (`protocol.c:786-803`) and
`pressure_diagnostic` (`protocol.c:820-871`). The chain is real, not labelling:
each H member is allocated at an explicitly forced slot, built through the arm's
ordinary callback and cache path, published into the arm's SC entry, **called by
its intended reader set** (`witnessed_calls` blocks on `last_seen[i][page]`,
which is stored only after a checked call), then removed by a full `invalidate`
transaction — version increment, entry zeroing, exact epoch request, all ACKs
acquired, arm-specific retirement including I's empty hazard scan — before
`hold_retired` asserts `life==RETIRED && !still_current` and moves the slot out
of the free pool. Hooks are disarmed throughout (`writer_round` is 0 during
setup and `hook_arm_round` is 3 or 4), so no setup transition can satisfy a hook
obligation. Near-full replacement (step 5) drives the **real** allocator:
`publish_one` finds every slot ineligible (actives are PUBLISHED, the second
scratch is BUILDING and `retire` refuses BUILDING, retained slots are
`UINT32_MAX`), emits `backpressure`, releases one genuinely retired H member
under `REQUIRE(life[held]==RETIRED)`, allocates there, and `allocate_desc`
advances the nonce until all eight 16-bit fields differ from the physically
replaced generation. V keeps the released member's recorded owner as builder,
executor and page-0 replacement target; no cross-worker transfer exists in the
code. `REQUIRE(held==setup_held)` re-checks the retained count after the swap.

### Mandatory check 3 — cap accounting

`protocol.c:1031-1042` computes `tokens = total*(V?n:1) + |H| + scratch +
replacement + 1` and `request_cap = total*3 + 16 + 2|H| + 2*replacement`, i.e.
the exact `|H|` descriptors, two scratch, one replacement and up to `2|H|+2`
setup epochs M18-P1 names. `bytes` uses compiled `sizeof` values throughout and
**does** include the trace buffers (`sizeof traces` = 13 × 229,392 B ≈ 2.84 MiB;
the constant `0x38010` is visible in the disassembly), `sizeof workers`
(≈1.28 MB, dominated by the two 10,000-entry clock arrays), the per-slot

### Mandatory check 4 — M18-N1 controls

`protection_control` (`protocol.c:882-947`) runs in a fresh sacrificial child

normal-data object, with an explicit runtime check that neither the function nor

## Required changes

- **R1 — the 256 MiB cap accounting is entirely self-reported; the checker

  `require(allocation[2] <= allocation[3] == 256 << 20, "ALLOCATION_CAP")`, and
  `check.py:341` checks only `sizeof` layout. Nothing recomputes the plan.

  record's values to `[1, 1, 0, 268435456, 24, 16]`; a trace with 42

- **R2 — a token recorded as retired can be admitted and called with no

  The only defence is the in-process `protocol.c:410`

## Verdict

- Verdict: `revise`
- Rationale: the packet is a genuine, complete and largely careful
  implementation of M18-2 with M18-P1 and M18-N1, not a scaffold. The machine
  code does what the method demands — SC entry/hazard operations, a
  single-entry non-recursive write callback, an invalidation range that exactly
  covers the published bytes and never leaves the slot, an ISB dominating the
  one indirect call into the arena, the STOP/ACK/RESUME and epoch edges, the
  serialized version recheck, and the exact `MAP_FIXED`/`PROT_NONE`/restore
  syscall path with one `MAP_JIT` region per process. The held-retired pressure
  chain is real rather than labelled, the checker rejected 19 of my 21
  adversarial mutations including every M18-P1 corruption, and `model.py` is
  independent and mutation-sensitive. Six required changes nonetheless remain
  open, and two of them are oracle gaps rather than documentation: the metadata
  cap is unverifiable (R1) and a retired-then-called trace is accepted (R2).
  Both bear directly on the lifetime and capacity properties this experiment
  exists to test, so `accept` is prohibited.
- Applicability limitations: **no native evidence.** No mode of the instrument
  was executed by this review — no preflight, no protection child, no hook,
  negative, sensitivity, correctness or cost run. Nothing here establishes that
  the candidate protocols work, that any arm is feasible, that whole-arena JIT
  protection composes, or that cross-PE CMODX is achieved on this or any host.
  **No cost claim.** The timer prerequisite is unmet, no calibration or timed
  sample was taken, and nothing here says anything about latency, throughput or
  batch cost. **Same host only.** All build, signature, disassembly and
  environment observations are for one `Mac16,10` (M4, 10 logical CPUs) running
  `Darwin 25.6.0` with SDK 26.4 and Apple clang 21.0.0, in three ad-hoc signing
  cells; nothing extends to Developer ID, notarization, the App Sandbox, another
  Mac, another macOS build or another architecture. Findings are static
  inspection, disassembly, and synthetic-fixture behaviour only; a finite set of
  passing oracles is not a proof of any native interleaving, cache effect,
  scheduling behaviour or emitted trace. This review authorizes nothing beyond
  reopening the code gate.
