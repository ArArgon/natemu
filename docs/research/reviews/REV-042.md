## Verdict

- Verdict: `revise`
- Rationale: The infrastructure around these experiments is right and should be
  kept. All four build clean at `-O1 -Wall -Wextra -std=c11` with no
  diagnostics; all four `run.sh` scripts refuse correctly in every required way,
  verified by execution rather than by reading — unset variable, non-existent
  directory, a root inside the repository, and the awkward case of a root equal
  to the repository root, which the trailing-slash comparison catches — and four
  end-to-end runs into a scratch raw root left `git status` for these four
  directories byte-identical, printing `normal: PASS` and `negative: FAIL` each
  time. Every negative control fires with the intended message. The design
  choices that matter are sound: timing uses `mach_absolute_time` throughout, a
  monotonic clock; the stubs are reached through function pointers into
  run-time-written `MAP_JIT` memory so no result can be a folded constant; the
  checkers keep platform findings as `NOTE`s and probe defects as `FAIL`s; and
  `INV-01-06`'s checker refuses to let the probe claim a Mach delivery it never
  performs. `accept` is nevertheless prohibited, and not on style. `INV-01-06`'s
  handler turns any fault anywhere in the process into a successful-looking
  resume, demonstrated here by injecting one stray write and watching the probe
  exit 0 with a `PASS`; that single defect makes every `PASS` from that
  experiment uninformative about whether the probe itself misbehaved, and the
  correct guard already exists in the sibling experiment. `INV-01-05` executes
  undefined behavior — confirmed by the compiler's own sanitizer — in exactly
  the two loops whose difference `CLM-01-05-13` rests on, and its checker
  declines to fail on a defect its own comments identify. `INV-01-04`'s batched
  timing divides by the batch factor in ticks and lands its median on exactly
  one quantum, so the measurement added to escape the clock resolution has worse
  resolution than the one it was added to fix. And two of the three concurrency
  controls cannot fail for the reason they are given: removing thread A's write
  acquisition from `INV-01-04` changes nothing in the output or the verdict, and
  `INV-01-05` records no thread identity at all, so its per-thread attribution
  is satisfied by construction. Twelve required changes are open, each naming
  its file, its line, and its return gate.
- Applicability limitations: This review decides the code gate for
  `INV-01-03`, `INV-01-04`, `INV-01-05`, and `INV-01-06` and nothing else. It
  accepts no source, no method, no result, and no replication, and it authorizes
