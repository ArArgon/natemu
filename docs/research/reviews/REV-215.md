## Finding and proposed resolution

The original sentence requires readable-neighbor controls but does not specify
whether the whole-arena JIT limb requires physical adjacency. A data page next
to a smaller dedicated protected extent can be owned and kept readable. No
page *inside the entire protected JIT arena* can simultaneously be an outside
readable neighbor. An unrelated AOT/data control must not be silently called
adjacent, and data-limb success cannot cover JIT restoration or other mappings.

M18-N1 therefore explicitly requires physical adjacency for the data limb,
using the scheduled full one/four-page extent plus an owned adjacent readable
extent. It names the JIT limb's actual before/after unrelated AOT-function/data
read, with exact out-of-arena addresses and the full arena still PROT_NONE for
the second read. It preserves the forbidden and restored JIT calls as separate
fresh-child controls, the callback restoration candidate, whole target,
signing/no-toggle rule, raw/exit validation and repetitions. It claims no
physical-neighbor coverage for JIT and no guarantee about other mappings.
This is a narrow applicability clarification, not an experiment waiver or a
second-machine request. It adds no public API or source-backed guarantee.
