## Stack-buffer accounting (closes REV-196's preliminary native accounting note)

REV-196 R2's note: `maximum_owned_buffer_bytes` counted global metadata and
heap sample/trace arrays but omitted simultaneous local buffers — main's
`struct json out` (65544 bytes as REV-196 counted it; 65544 is also this
review's independently compiled `sizeof(struct json)`, confirming REV-196's
figure), preflight's own `struct json out`, and `clock_cell`'s
`elapsed[200]`/`temporary[4]`.

`preflight()` (lines 571-603) now also sums a `named_stack` term over every
named local declared anywhere in `producer.c`, summed as though all could be
simultaneously live even across functions whose call scopes cannot actually
overlap (a deliberate over-count, not a call-graph-dependent one), and
`demand()`s `named_stack <= STACK_BUFFER_RESERVE` (1 MiB) before any array is
allocated. `maximum_owned_buffer_bytes` (`resources.json`'s
`peak_owned_buffer_upper_bound_bytes`, and `preflight.json`'s
`maximum_owned_buffer_bytes`) is `sizeof metadata (1310720) +
STACK_BUFFER_RESERVE (1048576) + max(single clock_cell heap allocation,
single contention_cell heap allocation) = 40759456`, so every named local is
covered by the flat reserve term rather than folded into per-cell heap math.

Independently re-deriving the true worst case from a plain per-function
reading of `producer.c` (not from the producer's own formula), using real
compiled sizes for this toolchain/ABI (`sizeof(struct json)=65544`,
`sizeof(struct quality)=24`, `sizeof(struct scan)=32`,
`sizeof(struct contention)=744`, `PATH_MAX=1024`):

`1048576`-byte reserve and comfortably above the true independent sum). The

`struct json` instances counted even though `preflight()` returns before

(`array()`'s `digest[32]` and `clock_failure()`'s `record[256]` are not

## Gate schema v2 (closes the ledger-facing defect this session found)

`GATE_SCHEMA` is now `INV-01-07-clock-c1-gate-v2`. `load_gate` requires,
separately: `reviews.193`/`.195` self-`accept`, `reviews.194` independent-
`accept`, `reviews.196` independent-`revise` (present as the critique being
returned against, never required to read `accept`), and a new
`independent_return` gate field — `{review_id, file, sha256,
expected_verdict, independence}` — supplied by the gate JSON itself because
the review number that finally accepts the packet (this packet reserves
`REV-219`) is not known until it is written. `independent_return_record()`
re-verifies every one of those fields against the real file independently of
what the gate JSON claims: the number must not reuse one of the four fixed
numbers; `file` must equal `docs/research/reviews/REV-<review_id>.md`; the
review must read `Independence: independent` and `Verdict: accept`; and its
text must mention `REV-196` (the critique it returns against). The C1
source/build/method-hash receipts move from `REV-196`'s text (which can
never carry them, since 196 stays `revise`) to the independent return
review's text. `test_gate_requires_accepted_independent_return_against_
critique196` in `test_runner.py` exercises: gate missing `independent_return`
→ `gate-fields`; a real return review that is `revise` → `review-not-
accepted`; a real return "review" whose `Independence` is `self` →
`review-independence`; a return that never mentions `REV-196` →
`independent-return-not-against-critique`; a return reusing a fixed review
number → `independent-return-review-id`; and a `file` path mismatched with
its own `review_id` → `independent-return-file`.
