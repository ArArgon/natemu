## Independent claim-level findings

Claim -21 is supported. The header makes nonspecial encodings opaque, and
the manual explicitly disallows integer arithmetic/comparison on the
internal representation and reserves its ability to change. A uint64_t typedef
does not document interchangeability with a raw Mach timestamp. This is a
public-contract limit, not evidence that any particular private encoding
currently differs or a claim about libdispatch implementation internals.

Claim -22 is supported. The documents define nanosecond offsets to milestones,
DISPATCH_TIME_NOW selecting current default host time, and that default as
based on/obtained from mach_absolute_time on Apple platforms. The manual
expressly specifies overflow to FOREVER and underflow to the smallest
representable clock value. No inspected section supplies the hidden numeric
conversion algorithm, a precision/error bound, callback error distribution
or cross-thread clock calibration. The claim preserves all those limits.

Claim -23 is supported only with its now-integrated qualification. The first
candidate repeated source.h's blanket statement that dispatch_time-created
milestones choose uptime. That loses the explicit time.h/manual cases
dispatch_time(DISPATCH_WALLTIME_NOW, delta) and an existing wall-clock
milestone base. The corrected claim and two qualifying ledger rows now
reconcile them: NOW/default-clock construction selects uptime, while
walltime-created or wall-based milestones select wall time. This qualification
is necessary, not cosmetic. Source.h additionally specifies the nanosecond
interval, FOREVER for one-shot operation, system-controlled lower delay and
strict best effort with residual delay. No hard callback delivery bound is
implied by the permitted-delay parameter rules.

Existing SRC-100's manual wording is consistent with the same qualified
reading; it is not silently renumbered or replaced. SRC-101 is QoS/core-type
tendency and spin-wait guidance, not a dispatch timestamp encoding source,
and supplies no missing clock-comparability premise here.

Canonical integration now exactly matches the corrected candidate packet and
all seven support/qualification rows. The earlier source-content issue is
closed. No bracketing algorithm is accepted by this source return: any later
method must separately justify the relation between its actual constructor
and callback clocks, handle sentinels/overflow and interval uncertainty, and
must not infer cross-thread calibration from I17's diagnostic pass or treat
a setup mean as the actual requested deadline.
