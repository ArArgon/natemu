## Independent findings and closure

Claims15–18 are supported as bounded declarations. State-only IDL has no
thread/task identity argument, in contrast to the distinct identity variants.
Optional token-related extensions remain explicit, not presumed active in
the proposed generation settings. The variable state array is not a promised
kernel context; the arm64 general-state count and flavor do not include the
separate exception or NEON state. Port and server declarations do not supply
automatic chaining, cleanup or liveness guarantees.

Claim19 required a correction. The tagged code skips state installation for
EXC_CORPSE_NOTIFY after a successful state-only RPC. The author now limits the
positive statement to EXC_BAD_ACCESS and explicitly notes that exception.
This is source accuracy, not a change to the already BAD_ACCESS-only method.
The inspected triage checks thread, task and host handlers conditionally and
stops on success or MACH_RCV_PORT_DIED; it does not prove ordinary forwarding
after every failure on the current host. R1 is closed in the pinned subject.

Claim20 preserves the article's conditional security scope and warning against
thread_set_state. The article's generalized identity-token sentence does not
override the exact state-only IDL. The discrepancy remains visible instead of
inventing a token field or asserting capability on a signing cell. Claim21 is
supported for timeout units/options and structures only; no whole-operation
time bound or server-failure recovery follows.

Primary inspection also refuted the original claim05's iff wording: opaque
arm64 layout can be selected explicitly without ptrauth_calls. The author
corrected the claim and reopened that documentary assertion, and root replaced
the old mapping with the exact supplied support/contradiction row. The new
statement matches the header's override/default branches. R2 is closed. This
does not change the actually recorded original nonopaque/no-ptrauth build or
establish a new PAC-enabled runtime result. The original observation gates
are not reapproved or invalidated by this bounded source correction.
