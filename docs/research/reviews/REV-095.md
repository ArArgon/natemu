## Verdict

- Verdict: `accept`
- Rationale: Both claimed results reproduced, and reproduced more strongly than
  the replication gate requires. Working from the approved code extracted at the
  reviewed revision `6c0acf5` with `git archive` — so no working-tree state could
  leak in — and using a runner and checker this reviewer wrote rather than the
  author's, all 16 independent checks for `INV-01-01` and all 10 for `INV-01-10`
  passed. Every value the records make Observed came back identical: the
  entitlement discriminator in both directions (`0xfae94007` unentitled,
  `0x00000000` entitled, with the positive control recomputed here rather than
  read from the author's file), `hv_vm_get_max_vcpu_count_value` 64,
  `id_aa64mmfr0_el1_raw` `0x000010000f100022` with no decoded field present,
  the `42` toggle constant and the distinct `43` callback constant,
  `mach_vm_remap` aliasing, `thread_policy_set` returning `46` on all three runs,
  and the full `INV-01-10` inventory including the `CLT`/`OS`/`user-local`
  provenance labels that `KA-09`'s reading turns on. The five probe outputs are
  byte-identical to the author's — same SHA-256 in every case, confirmed for
  `tools.json` by a byte-level diff as well — which additionally establishes
  that both programs are deterministic on this host. The entitled arm was signed
  ad hoc with the approved entitlements plist exactly as `build.sh` does, and
  the reviewer's own `codesign` captures confirm both signing states. Because
  `accept` here is a statement about reproducibility only, the applicability
  limits below are the operative part of this verdict.
- Applicability limitations: This replication ran on the **same physical host**
  as the original runs — `Mac16,10` (M4) / macOS 26.6.2 (`25G83`) / SDK 26.4 /
  CLT `26.4.0.0.1774242506` — because it is the only machine available this
  session. It therefore establishes that the procedure and the results are
  reproducible by an independent executor with independent code, and nothing
  about portability: applicability stays exactly where it was, this host only,
  ad-hoc signing only, and `P1` (M1 Pro / Sequoia 15) replication remains owed
  before any platform-wide use, per the executor guide's incremental-replication
  rule. Byte-identical outputs are evidence of determinism on this host, not of
  generality; a different host could legitimately produce different values
  without contradicting anything here. This replication establishes no `KA-01`,
  `KA-02`, `KA-09`, or `KA-10` disposition beyond what the underlying records
  claim, supplies no adversarial outcome (`REV-096`), and authorizes no planning
  or implementation.
