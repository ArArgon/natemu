## Required changes

1. `INV-01-08` owner, return to method gate: specify the zero-denominator case
   in rule 1. The band is defined by a ratio of both-observed fractions, and
   that ratio is undefined when the plain arm's fraction is exactly 0 — which
   is the case for `SB`/`LDAR`-`STLR`/user-interactive and
   `SB`/`DMB ISH`/user-interactive in both runs. The frozen checker's
   `max(lo, 1e-9)` guard happens to give the right verdict, but the amendment
   explicitly does not govern the checker and the code change is owed against
   the method text. State the rule: for example, that a pair whose plain
   both-observed count is zero is treated as an unbounded ratio and reported
   INCONCLUSIVE, since a plain arm that never overlapped cannot be compared
   with one that did. Two of the four pairs carrying this record's headline
   negative depend on it.
2. `INV-01-08` owner, return to method gate: state that rule 2 was applied to
   every pair, not only the straddling one. A second run of every arm now
   exists in `MAN-01-08-03`, so rule 2's pooling requirement is live for all
   eight pairs; the Results table currently reports single-run verdicts for
   seven of them and pooled reasoning for one. This reviewer recomputed the
   pooled verdicts for all eight and they match the table — SB pairs remain
   INCONCLUSIVE, both MP `LDAR`/`STLR` pairs remain COMPARABLE at pooled
   ratios of about 1.0 and 1.08, `MP`/`DMB ISH`/user-interactive remains
   INCONCLUSIVE at about 5 460×, and the straddling pair pools to 13.7× and
   stays INDETERMINATE — so no verdict is misreported. Record that the check
   was made and its outcome, so a later reader is not left to wonder whether
   the record's own new rule was applied to its own table.

## Verdict

- Verdict: `revise`
- Rationale: the amendment is a good rule, written the right way round. It
  does not move the 10× boundary, it forbids moving it after data exists, and
  — the test that matters for a rule written after seeing the data it
  adjudicates — it cannot rescue any zero. I recomputed all eight pairs under
  both rules: exactly one verdict changes, from INCONCLUSIVE to INDETERMINATE,
  and nothing enters COMPARABLE. In the replication the amendment strictly
  *removes* a corroboration the unamended rule would have granted, which is
  the opposite of self-serving. The decision not to touch the frozen checker,
  and to declare the code change as owed while directing readers to apply the
  band by hand, is correct sequencing. `accept` is prohibited by two
  specification gaps in the new rule's text: it does not say what a zero
  denominator means, though two of the four pairs carrying the record's
  headline negative have exactly that shape, and its pooling requirement is
  live for all eight pairs but is only visibly exercised on one. Both are
  text-level and neither changes a verdict.
- Applicability limitations: this verdict covers the `INV-01-08` method
  amendment at `21dc5e5` only. It approves no source claim, code, result, or
  replication, and it does not authorize the checker change the amendment
  declares owed. Every ratio quoted here was recomputed from
  `MAN-01-08-01` and `MAN-01-08-03`, both of which are this host only —
  `Mac16,10` (M4) / macOS 26.6.2 (25G83) / SDK 26.4 — with `P1` replication
  still owed. The size of the band (a factor of three) rests on two runs of
  one pair on one host and is not established as the right width; this review
  accepts it as a conservative predeclaration, not as a calibrated constant.
