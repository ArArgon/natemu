    Neither is exercised by the shipped guest; both are in the discrimination

    (120 s) with the method's frozen 180 s.

## Verdict

- Verdict: `revise`
- Rationale: The code is well built for what it is and much of it survived
  adversarial checking rather than being taken on report — I reassembled all
  fifteen emitted ordering and atomic encodings and every one is byte-identical
  to the assembler's; the read-modify-write path resolves write permission in
  `hrmw` before the atomic executes, so a faulting `lock xadd` genuinely does
  not perform its read side twice, which is the harder case the breadth pass
  demanded; the interrupt frame order, error-code position, CR2, and pushed RIP
  are correct and observed correct in five runs; `IF` gating, `HLT` wake, and
  IPI targeting all work; the per-vCPU `MAP_JIT` regions and per-thread
  write-protect toggling avoid a shared-code-cache race by construction and the
  toggle is restored on every unwind arm; `--inject-stale-cache` disables
  exactly the self-modifying-code flush and nothing else; all four load-bearing
  controls produce a checker FAIL with exit 1; and `run.sh` refuses in all five
  configurations I tried and writes nothing under `experiments/`. Eleven
  required changes nonetheless block `accept`, and four are serious. Restart is
  not exactly-once for the push and call forms, which I demonstrated by
  producing a silently corrupted guest that no invariant sees. There is no
  nested-fault handling, so a fault on any stack access livelocks until the
  watchdog — which is also why the first defect is unreachable in the shipped
  guest, and why "it passed" cannot be read as "it is correct". ThreadSanitizer
  reports eight data races on the positive run, six of them a non-atomic
  accessed/dirty update on page tables shared by both vCPUs, inside the exact
  mechanism this record claims composes. And the `LDAR`/`STLR` emission rule is
  undefined for unaligned guest accesses past a 16-byte granule, where the
  failure is a host SIGBUS that writes no artifact at all. Alongside those, six
  confirmed oracle holes mean a passing document does not establish that
  `MAP_JIT` was used, that the frozen loop counts ran, or that any translation
  was cached. `accept` is prohibited while those actions are open.
- Applicability limitations: This review judges the `INV-01-12` experiment code
  only. Every observation was made on `Mac16,10` (Apple M4) / macOS 26.6.2
  (25G83) / SDK 26.4, in a scratch directory outside the repository, with
  `NATEMU_RAW_ROOT` never set to the real raw root and nothing written under
  `experiments/` or the raw root. No run reported here is evidence, none
  supports any claim in any record, and none may be cited as a result — the
  result gate is untouched and no evidence run exists. This review accepts no
  source mapping (`REV-049`), no method (`REV-050`), and no `KA-04`, `KA-06`,
  or `KA-11` disposition. The defects found are ordinary implementation defects
  and, per `INV-00-06` family kill 3, none of them is evidence of structural
  impossibility for `F2` or for any family. Nothing here authorizes planning or
  implementation.
