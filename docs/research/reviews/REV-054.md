## Required changes

1. **C1 — experiment owner, return to code gate.** Give `check.py` at least one
   rule that a falsified `KA-09` violates. Require `tools.clang.present`,
   `tools.python3.present`, `tools.git.present`, and `tools.codesign.present`
   to be true for a non-`--negative` run (keyed on `negative_control`, which the
   output already carries), matching the Metrics threshold the record states.
   As shipped, a run with `clang` absent — the record's own stop condition —
   is reported PASS, so the code gate's stated evidence ("a truthful run must
   pass `check.py`") distinguishes nothing.
2. **C2 — experiment owner, return to code gate.** Invoke the resolved binary in
   the `xctrace` functional check — `"$XCTRACE_PATH" version` — rather than bare
   `xctrace`, matching how every other tool in the script is invoked, and record
   both the exit code and the captured message in the JSON instead of deleting
   the temp file. On this host `xcrun --find xctrace` fails while `command -v`
   succeeds, so the two resolution routes already differ and the current code
   can attribute a `PATH` miss to Xcode.
3. **C3 — experiment owner, return to code gate.** Wrap `json.load` in
   `try/except json.JSONDecodeError` and report a malformed probe output as a
   distinct, named failure with its own exit status, so a reviewer reading
   `tools.check.txt` can tell "the checker's rules were violated" from "the
   probe did not emit JSON". This path is reachable by design, since
   `json_escape` escapes only backslash, double quote, and newline — as the
   record's own "Open correctness risks" note says.
4. **C4 — experiment owner, return to code gate.** Delete `chmod +x
   src/tools.sh` from `run.sh` and invoke the script through its interpreter
   (`sh src/tools.sh`). The line is the only write to `experiments/` in the
   script and contradicts the script's own header and the `README.md`.
5. **C5 — experiment owner, return to code gate.** Harden the out-of-repository
   guard as in `REV-039` C8: resolve the path first
   (`NATEMU_RAW_ROOT=$(cd "$NATEMU_RAW_ROOT" && pwd -P)`) before the `case`, and
   derive `REPO_ROOT` from `git -C "$(dirname "$0")" rev-parse --show-toplevel`
   rather than from `cd ../..`. A symlink into the repository currently passes
   the guard, and a relocated script compares against the wrong root. Fixing
   both `run.sh` scripts in one change is the smaller diff.
6. **C6 — experiment owner, return to code gate.** Emit `codesign`'s version as
   `null` with a separate `version_unavailable_reason` field carrying the
   existing explanatory string, and exempt that tool from the non-empty-version
   rule explicitly. That keeps the honest disclosure the code already makes
   while removing a rule that cannot fail and a field a reader can mistake for a
   real version.
7. **C7 — experiment owner, return to code gate (minor).** Report rather than
   silently perform the newline flattening in `json_escape` (or escape `\n` as
   `\\n`); either use `tool_field`'s `name` argument or drop the parameter; and
   state in a comment that `run.sh`'s `shasum -a 256 -- *` depends on glob
   expansion preceding the redirection, so a later edit does not accidentally
   include `SHA256SUMS.txt` in its own digest listing.

## Verdict

- Verdict: `revise`
- Rationale: This is a small, honest, dependency-free script and several things
  about it are right: it runs clean under `sh -eu`, emits valid JSON on both
  invocations, resolves each tool through the `xcrun`-first order the method
  describes, captures `$PATH`, `xcode-select -p`, and the CLT package build
  identifier specifically so a reviewer can rule out a PATH-dependent false
  absence, records `codesign`'s missing `--version` plainly instead of
  fabricating a string, and refuses to run with `NATEMU_RAW_ROOT` unset or
  pointing at a non-existent directory — both verified, both firing before
  anything is written. The declared negative control also behaves exactly as
  documented: `--negative` empties `clang`'s version and `check.py` exits 1 with
  precisely the one predicted violation. `accept` is nonetheless prohibited,
  because passing this checker does not mean what the investigation needs it to
  mean. Every rule in `check.py` is an internal-consistency rule, so a run in
  which `clang` is absent — `KA-09` falsified on this cell, the stop condition
  the record itself names — is reported PASS, which this reviewer demonstrated
  by injection; the same defect appears in this author's `INV-01-01` checker, so
  it needs fixing as a pattern, not as one bug. Beside it: the `xctrace`
  functional test invokes a `PATH` lookup rather than the binary the script
  resolved, on a host where those routes demonstrably diverge, and discards the
  message the record quotes; `check.py` aborts with a traceback rather than
  failing cleanly on malformed input, a path `json_escape`'s documented minimal
  escaping leaves open; `run.sh` contains a `chmod` write to `experiments/`
  while asserting it writes nothing there; and the out-of-repository guard is
  bypassable by a symlink. Every required change is a small edit to a named
  file and line.
- Applicability limitations: This review adjudicates the code of
  `experiments/INV-01-10/` only, at revision `c497cf3`, run on `Mac16,10` (M4) /
  macOS 26.6.2 (`25G83`) / CLT build `26.4.0.0.1774242506`. It does not
  adjudicate `INV-01-11`, which produces no experiment code. It establishes no
  toolchain fact and no `KA-09` disposition: every run performed here was a
  reviewer smoke or fault-injection run in a scratch directory, it is not
  evidence, it supports no claim, and nothing was written to
  `/Users/liaozping/orca/natemu-raw`. Tool paths, versions, and `xcrun` behavior
  quoted above are cited to show what the code does with them, not as findings
  about the host. This review does not accept the sources (`REV-052`) or the
  method (`REV-053`), and nothing here authorizes an evidence run, planning, or
  implementation.
