# INV-01-22 — guest time-base policy admissibility

## Current summary

**Question — Q-01-22.** Which guest time-base policies are admissible and what do they
mean for timeouts, correctness and measurement?

**Conclusion and applicability.** Open source/policy investigation. The bounded
source packet (REV-157) distinguishes Linux clocksources, clock events, host
sleep behavior and LAPIC mechanisms. The conditional four-policy matrix,
four satisfiable toy cases and six negative witnesses now have independent
[findings acceptance](../reviews/INV-01-22-findings.md). No host-slaved,
rate-scaled, virtual/execution-driven or pause-on-suspend policy has been

supplies risks and alternatives only; it proves no NatEmu or stock-guest behavior.

**Material blockers and limits.** Exact guest/kernel/clocksource and CPUID/MSR contract,
qualified host clock/timer inputs, lifecycle evidence, external-I/O behavior and

clocksource/clockevent/CPUID-MSR contract with Q-01-13/Q-02-03, then apply the
accepted conditional matrix to its actual calibration, halt, lifecycle and

#### Definitions and exact assumptions

Let H be an ideal, nondecreasing reference elapsed time in seconds, including
host sleep; it is a mathematical input, not a claim about a qualified API.
Let S be cumulative whole-VM paused time on that same reference, with
0 <= delta S <= delta H. Let E be one globally ordered, nondecreasing logical
execution/event counter. Define E(H0)=0 and S(H0)=0 at the common epoch, so
each formula below satisfies G(H0)=G0. All vCPUs read the same timeline and epoch. Ignore
finite-width wrap only within these bounded examples; actual width/wrap/reset
semantics remain a required input. Define four representative policies:

| Family | Exact representative used for analysis | Required distinction |
| --- | --- | --- |
| H: host-slaved | G = G0 + H - H0 | Includes host sleep because H does; choosing an uptime reference would create a different lifecycle cell. |
| R: rate-scaled | G = G0 + a(H - H0), constant a > 0 | Example a=2; neither time-varying scaling nor a=0 is silently admitted. a=1 overlaps H. |
| V: virtual/execution-driven | G = G0 + qE, q > 0 | Example q=1 ms/event; all-vCPU halt advances no time unless an explicit idle/event rule is added. Per-vCPU counters are not this representative. |
| P: pause-on-host-suspend | G = G0 + (H - H0) - S | One common pause interval/epoch for the entire VM; host sleep detection and guest-visible resume semantics are separate implementation inputs. |

The families overlap and can be composed; these definitions make the submitted
cells falsifiable without claiming an exhaustive implementation taxonomy.
Use **supported** for a predicate proved under the stated toy assumptions,
**contradicted** for the explicit counterexample, and **unknown** for a missing
actual input. Each cell's scope is part of its disposition.

#### Four satisfiable toy contracts

For each toy, choose n=2,4 or8 independent readers of one atomic logical G,
G0=H0=0, a counter C=1000000G (cycles), a second calibration counter B=100000G,
and one deadline D=0.005 seconds. At the first event-service opportunity with
G>=D, issue exactly one recorded event; do not issue early. Assume an ideal
service opportunity at every stated sample, no host delay, no real I/O,
no finite-counter overflow and no clocksource-selection algorithm. These are
mathematical assumptions, not implemented atomicity or host observations.

| Toy | Input sequence | Satisfied clauses and explicit measurement meaning |
| --- | --- | --- |
| H | H=0,1,...,10 ms | G=H; event at H=5 ms; C/B rate ratio10, common time, unit host-elapsed measurement. |
| R | a=2; H=0,0.5,...,5 ms | G=0,1,...,10 ms; event at H=2.5 ms; both virtual counters calibrate to ratio10; guest elapsed is scaled time, delta G/2 is host elapsed. |
| V | q=1 ms; E=0,1,...,10, delivered as a global event sequence | G=0,1,...,10 ms; event at E=5; ratio10; guest elapsed is logical-event time. No assumption of host duration or progress after all execution stops. |
| P | H=0,1,...,10 ms; S grows only during [3,7] ms | G rises to3 ms, holds until H=7 ms, then rises to6 ms; event at H=9 ms, G=5 ms; ratio10 on active intervals; measured G excludes4 ms of pause. |

Each toy has a satisfiable internal contract; none executes Linux, exercises
CPUID/MSRs, proves timer hardware or addresses real peer deadlines. The V toy
is deliberately a progressing workload, not a claim that an idle guest can
wake itself. Adding idle advancement would require a new defined policy cell.
