### Host, actors and bounded records

Only Mac16,10/M4, macOS26.6.2 build25G83, SDK26.4 is in this campaign. Signing,
entitlements, launch context, power source, thermal/Low Power Mode state, build
and actual host identity are retained. P1, another generation/release, product
guest policy and actual P/E placement remain unmeasured. Inventory topology
with hw.nperflevels and available hw.perflevelN counts, recording unavailable
fields honestly. No CPU-placement inference follows from thread count or QoS.

Each slot uses a fresh exec child, N dedicated busy worker pthreads, one dedicated
timer pthread and one main control thread/run loop. Framework callback threads
are additional uncontrolled actors, not counted as N. N is 1/2/4/8; no guest
vCPU execution is claimed by these host workers. Begin with requested
USER_INITIATED QoS and check every API return/read-back. Each worker increments
its private uint64 counter with checked overflow and polls stop/demote flags.
On a demotion request it sets its own BACKGROUND QoS exactly once and records
request, actual API result and read-back. The timer polls before each sleep and
after each return, including EINTR; it demotes only itself. Other actors retain
their declared QoS. A set/get match proves requested QoS only.

Every worker reads mach_continuous_time after every loop iteration. **Before
the density gate**, compare the new raw value with the immediately preceding
raw read. On a decrease, retain the first pair, their adjacent loop indexes,
actor and an anomaly count in a dedicated bounded witness; signal invalid-clock
observation to the controller. Then apply a checked normal gate: at most one
heartbeat when at least100ms of nonnegative converted elapsed time has passed
since its last recorded heartbeat. No unsigned negative subtraction, unchecked
multiplication or catch-up writes. Retain raw ticks and the nonzero timebase;
use sufficiently wide checked integer conversion. Every observed reversal is
counted before admission, even if ordinary heartbeats omit that read. Sampling
still cannot discover an unobserved transient. Counter/conversion overflow or
invalid timebase is an instrument error, not a host discontinuity.

Heartbeat/fire records contain actor, sequence, iteration/fire counter, five
clock readings (Mach absolute/continuous and CLOCK_MONOTONIC/MONOTONIC_RAW/
UPTIME_RAW), requested QoS and status. Read them in a fixed declared order;
they are sequential samples, not simultaneous. Read failures invalidate the
affected record. The timer applies the same reversal check between its own
actual continuous-clock reads. Check all five streams for observed decreases;
only the continuous-clock oracle participates in the existing bounded
clock-failure test. Other clocks remain diagnostic until separately admitted.

There are eight notification sources: system sleep/wake, screen sleep/wake,
session inactive/active, thermal and Low Power Mode. Each callback stores
source, reported value, actor identity, local reservation sequence and the
same clock snapshot. Each worker/timer has32768 fixed slots; each notification
source also has32768 slots. Each slot, including commit metadata, is at most

Controller/operator markers have4096 slots of at most256 bytes (1MiB), and

Total declared record storage is at most70MiB; all application-owned buffers,
scratch and serialization storage together are capped at128MiB. The build must
assert actual layouts and account allocations before native review. This cap
does not claim to bound private AppKit/system allocations or total process RSS.

Capacity never wraps or overwrites evidence. Normal30-minute awake sampling
admits at most18001 boundary-inclusive records/actor at the requested density;
callbacks have no assumed rate. Any capacity exhaustion increments a checked
dropped count and invalidates the cell. Dropped-counter overflow also invalidates.
No worker heartbeat performs file I/O; collection perturbation remains a limit.

### Callback publication, shutdown and kill evidence

A mutex guards callback admission and the active-callback count. A callback
acquires it, checks admission, increments active if admitted, then releases it.
Rejected late callbacks may only use process-lifetime admission state. Admitted
callbacks reserve a unique bounded slot, write their payload, release-store a
per-slot committed flag, then decrement active under the mutex and signal its
condition variable. Acquire-reading a committed flag is required before any
consumer reads that payload. Reservation order is not completion order or a
cross-thread temporal order. An uncommitted reserved slot is never a record.

Shutdown first closes admission under that same mutex, removes observers and
stops workers/timer. It waits for active callbacks to reach zero and joins all
dedicated writers before serialization. Observer token removal alone is not a
drain proof. Admission state, captured callback context and buffers remain
allocated until process exit, including for callbacks arriving after removal;
there is no freed context for a late callback to touch. Shutdown has a60-second
awake ceiling within the per-child overhead budget. A stuck admitted callback,
join or serialization yields drain-incomplete/timeout, never normal finalization.
Code review must inspect the actual framework capture lifetime and synchronization.

Parent-owned external schedule, child launch/exit status, phase markers and
operator/pmset captures are written incrementally and survive a child kill.
Worker/notification buffers are private until orderly final serialization.
**A killed child cannot flush them:** its terminal outcome explicitly records
missing in-memory trace and has no continuity/detectability finding from those
lost records. The parent retains and hashes any existing file prefix, including
an incomplete serialization file, without treating it as a completed trace.
This method makes no power-loss durability guarantee. An external streaming
instrument would be a separately reviewed improvement if missing terminal
evidence blocks a load-bearing question; it is not silently reconstructed.

Use parent-owned phase IDs and receipt order, not equality of unsynchronized
second-device and host clocks. Operator entries identify the active phase and
record original external times plus parent receipt time. An uncertain external
association is unresolved; never invent a numerical alignment. Install and retain

removal results checked. Screen controls exercise their own observers at two

1. After ARMED, enter pre-screen phase. The operator performs

2. Before the system-sleep request write an induction-start marker and capture

   records, regardless of whether didWake was received. It immediately starts

   the original observation ceiling; otherwise the transition is unresolved.
   No target callback is required to advance this phase.
4. At that cutoff freeze the target bucket; start a post-screen phase and repeat
   the same screen control with its own120-awake-second deadline. Late target

   independent induction/wake is confirmed, and the child completes its drain.

Target bracketed means exactly one willSleep then exactly one didWake received
