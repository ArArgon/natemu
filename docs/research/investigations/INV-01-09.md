## Question and decision relevance

- Question ID and text: `Q-01-09` — Can the minimal headless device set
  (timer/APIC, serial, block, network, entropy, shutdown) be backed by public
  macOS APIs without restricted entitlements or privileged helpers?
- Decision(s) affected: device feasibility, the machine-contract option set
  `Q-01-13` may select from, and the containment method `Q-02-04` builds on.
- Why this must be resolved now: `KA-08` — "Each mandated device class has an
  unprivileged public host backing" — gates project stop input 3 for any
  failing class, and `Q-01-13` cannot select among machine-contract options
  that depend on a device backing this question has not yet cleared.

## Assumptions

- Declared assumptions: the minimal device set fixed by
  [Scope and success](../tracks/00-scope-and-success.md) — timer/APIC,
  serial, block, network, entropy, shutdown — is the target set; timer/APIC's
  host-clock mechanism is `Q-01-07`'s scope, not repeated here; shutdown
  (process exit) needs no capability probe; no production machine design is
  selected here (`Q-01-13`'s and Track 03's job).
- Assumptions to challenge: that `vmnet.framework` is the only network
  backing worth checking; that an entitlement's "restricted" documentation
  status predicts a specific `vmnet_return_t` failure code rather than, for
  example, an outright process termination under an unauthorized restricted
  entitlement; that POSIX file-I/O primitives (`F_NOCACHE`, `F_FULLFSYNC`,
  `F_PUNCHHOLE`) carry no hidden privilege requirement; that `getentropy`'s
  documented per-call limit is enforced rather than silently ignored.

## Hypothesis and falsifier

- Hypothesis: every device class in the minimal set except timer/APIC
  (`Q-01-07`'s scope) has at least one unprivileged public host backing on
  this host/OS: network via ordinary BSD sockets (`vmnet.framework` may or
  may not be usable without Apple-granted provisioning, but the envelope
  only needs "BSD sockets or an available `vmnet` mode" per `KA-08`), block
  via POSIX file I/O, serial via `pty`, entropy via `getentropy`, shutdown
  via process exit (no probe needed).
- Falsifier(s): any device class for which every candidate unprivileged
  public backing fails in the evidence run falsifies `KA-08` for that class
  and routes to project stop input 3 for that class specifically. For
  network specifically, the falsifier requires *both* `vmnet.framework`
  (unentitled and entitled-ad-hoc) *and* ordinary `SOCK_STREAM`/`SOCK_DGRAM`
  sockets to fail unprivileged — `vmnet` alone failing does not falsify the
  network class, since `KA-08` accepts "BSD sockets or an available `vmnet`
  mode".
- Predicted outcomes: see the claims above (`CLM-01-09-14`–`19`, `-21`).
  The evidence run (`MAN-01-09-01`) relabelled `-14`, `-16`, `-17`, `-19` as
  Observed MEET; `-15` as Observed MEET via the process-termination
  observable form the claim left open; `-18` as Observed with an honest
  partial miss (the 256-byte limit is enforced, but the observed errno is
  `EINVAL` not the documented `EIO`); `-21` was not exercised (every arm's
  callback fired within the 5 s wait). No claim was refuted outright.

## Method

- Procedure and versions: build `experiments/INV-01-09/src/probe.c` (Apple
  clang, `MacOSX26.4.sdk` headers, `-framework vmnet`). Run four arms, in
  this fixed order, so entitlement enforcement cannot pre-empt the checker
  fault injection: (1) the unentitled binary, normal; (2) the same
  unentitled binary with `--negative` (the fault-injection control, run
  before any entitlement is applied); (3) the binary ad-hoc signed with
  `com.apple.security.get-task-allow` (`src/benign.entitlements.plist`), a
  non-restricted entitlement, normal — the attribution control; (4) the
  binary ad-hoc signed with the restricted `com.apple.vm.networking`
  (`src/vmnet.entitlements.plist`), normal. A normal process exit emits one
  JSON object; process termination in either entitled arm is retained
  through its exit-status (with any termination signal decoded) and stderr
  artifacts, and `codesign --verify --verbose` is captured for every signed
  variant so a signing failure is distinguishable from a runtime kill.
  Comparing arms 3 and 4 is how a termination of arm 4 is attributed to
  `com.apple.vm.networking`'s restricted status specifically, rather than to
  ad-hoc signing with any entitlement or to a malformed plist
  (`REV-047` required change 2). `run.sh` also records the executing `id`/
  `id -u` (`identity.txt`), per `BP-01-09-start`'s measurement-failure-mode
  requirement (`REV-047` required change 3); TCC/permission-grant state is a
  stated method decision not to capture, recorded in `identity.txt` itself,
  because no public unprivileged tool on this OS reads that account's TCC
  database without itself requiring a grant — the `SOCK_RAW` `EPERM` result
  therefore establishes only that the recorded UID lacked raw-socket
  privilege under its ambient state at run time, not what that ambient state
  was beyond the UID. Validate each emitted JSON object with `src/check.py`,
  an independent Python 3 standard-library checker that re-derives pass/fail
  from the raw reported fields rather than trusting the probe's own framing.
- Inputs and configuration: `vmnet_start_interface` is called with
  `vmnet_operation_mode_key = VMNET_HOST_MODE` (the minimal viable
  `interface_desc`, per `SRC-119`'s documented key); sockets use
  `AF_INET`/`SOCK_STREAM`, `SOCK_DGRAM`, and `SOCK_RAW`/`IPPROTO_ICMP`; the
  block-I/O and sparse-file checks write transient temp files under the

## Controls

  block-I/O checks are expected to succeed unprivileged on any conforming
  host; a run where these fail would indicate a probe or environment defect
  rather than a genuine device-backing finding, and must be investigated
  before the result is trusted.
- Negative controls: `socket_raw` (expected `EPERM` unprivileged) is a
  built-in negative control on socket privilege; the `--negative` probe
  invocation is the code-gate's fault-injection control, fabricating

  outcome, which `check.py`'s fixed invariant (`getentropy_over_limit.ok`

- Attribution control: the entitled-benign arm

  identity as the entitled-restricted arm) isolates the effect of the
  restricted `com.apple.vm.networking` entitlement specifically. Without it,
  a termination of the sole entitled arm cannot be distinguished from a
  termination caused by ad-hoc signing plus any entitlement, or by a
  malformed plist (`REV-047` required change 2).
- Baselines: none; this is a capability-presence measurement, not a
  performance comparison.

## Confounders

- Known confounders: (1) the documented `vmnet_start_interface` contract
  ("non-`NULL` on success, `NULL` otherwise", `SRC-111`) and completion-
  handler contract (`SRC-119`) do not state precedence if the synchronous
  return and callback status disagree. The probe records both raw fields
  (`start_returned_nonnull`, `status_code`) unconditionally; `check.py`
  computes `success` from the callback status alone (the only field either
  source actually defines a status *value* for) and does not hard-fail a run
  merely because the two disagree — a disagreement is a real, reportable
  possible outcome given the documented silence on precedence, not evidence
  of a broken probe, so treating it as an automatic checker failure would
  bake an assumption into the code gate that no source here establishes.
  (2) An ad-hoc-signed binary carrying a *restricted* entitlement it was not
  granted by Apple may be refused execution or killed by code-signing/
  entitlement enforcement (AMFI) before or during the vmnet call, rather
  than receiving an ordinary `vmnet_return_t` failure code through the
  completion handler; `run.sh` captures the entitled-restricted arm's raw
  process exit status (`entitled-adhoc.exit.txt`, signal decoded) and skips
  the checker with an explicit note when the process did not exit cleanly,
  rather than losing that distinction, and this behavior was directly
  exercised during development (a scratch-directory dry run, not an evidence
  run and not a claim): the entitled-restricted process was killed (exit
  status 137/`SIGKILL`) while the entitled-benign process
  (`com.apple.security.get-task-allow`, same ad-hoc identity) exited 0 in the
  same dry run, which is the attribution control (Controls, above)
  demonstrating exactly the distinction it exists to make — this observation
  is code-validation evidence about the probes, not an Observed platform
  claim. (3) A probe run under an interactive user account with prior Local
  Network permission grants or other ambient privilege could report a more
  permissive result than a fresh account would; `run.sh` now records the
  executing `id`/`id -u` (`identity.txt`), but TCC/permission-grant state
  itself is a stated method decision not captured (no public unprivileged
  tool on this OS reads that database without itself requiring a grant),
  recorded in `identity.txt`, which is a residual limitation, not a fixed
  confound.
- Mitigations and residual risk: `run.sh` records every signed variant's
  `codesign -d --entitlements -` and `codesign --verify --verbose` output so
  the actual applied entitlement and its signature validity are auditable
  per run; the JSON schema records `start_returned_nonnull`,
  `callback_fired`, `timed_out`, and `status_code` separately so a
  return-value/handler disagreement or a non-fired callback is visible
  rather than collapsed into one boolean. The TCC/ambient-privilege residual
  risk is recorded as an open limitation below, not mitigated by this
  method.

### Implications for `KA-08`/`KA-12`/`KA-13` and families F1–F4 (no design selected)

**Disposition, on this session's single host (`Mac16,10` / macOS 26.6.2
(`25G83`) / `MacOSX26.4.sdk` / ad-hoc signing, unsandboxed), `P1`
replication owed:** `KA-08` **does not fail** for the network class and
**is not yet closed either way** for block/serial/entropy pending
replication, but every observation is a MEET or a benign partial miss —
nothing observed falsifies any device class. `vmnet.framework` failed
(`VMNET_FAILURE`, `status_code: 1001`) unentitled and under both entitled
arms (the restricted arm via `SIGKILL` before any status could be
delivered), but the documented existence of a second, independent network
backing (ordinary `SOCK_STREAM`/`SOCK_DGRAM` sockets, Observed working,
`CLM-01-09-16`) means this cannot by itself fail `KA-08`'s network clause,
which accepts "BSD sockets *or* an available `vmnet` mode" — and on this
host BSD sockets are the surviving backing. **This narrows, not merely
substitutes, what the surviving disjunct can do**: `BP-01-09-start`'s
adjacent-systems coverage already recorded the BSD-socket path as having
"no special entitlement, but no L2 bridging either", and `vmnet` was the
only L2-capable candidate this investigation named. With `vmnet` now
Observed unavailable to an unentitled process and fatal to an
ad-hoc-entitled one, `KA-08`'s network clause survives *only* through the
disjunct that cannot move Ethernet frames. Consequence for `Q-01-13`: any
guest machine contract that exposes a virtio-net device to the guest must,
on this host, be fed by a user-space TCP/IP stack in the host process
rather than by host-level L2 bridging — `INV-01-13`'s decision table
carries this as an Open cell (see `INV-01-13`, Results, Transport row),
and if a third-party user-space network stack is contemplated to fill that
role, its licence compatibility is `Q-01-11`'s question, not this
investigation's (`REV-083` required change 2). For block, serial, and entropy,
no second candidate is named in `KA-08`'s own row; all three were Observed
working (`CLM-01-09-17`, `-19`; entropy's limit enforcement MEETs even
though its exact errno misses), so none of the three device classes this
investigation could falsify on its own was falsified. `KA-08` therefore
survives this evidence run for every class this investigation tested, on
this host, pending `P1` replication before any platform-wide claim. This
investigation supplies `Q-01-13` with the device-backing admissibility
premise its machine-contract option table depends on (`INV-01-13`,

those four classes specifically.

translation-under-Hypervisor.framework, or AOT/dynamic-fallback) depends on
device backing for its *core* translation/paging/exception mechanism; device
