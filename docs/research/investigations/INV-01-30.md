# INV-01-30 — Guest paging under SMP

## Current summary

  through native Arm stage-1 mappings under concurrent vCPU activity?
- **Conclusion and applicability:** **accepted scoped yes for mechanism
  feasibility** on Apple M4 Mac16,10, macOS 26.6.2 (25G83), SDK 26.4 at two

## Assumptions and breadth

The host translator, native TSO memory model and GIC/timer are charter inputs.
Native VM bring-up is shared with ordinary VMs and is not a new feasibility
question or kill assumption. QEMU TCG handles the x86 translation semantics in
software; the design-specific unknown is keeping hardware shadows faithful to
those semantics. Apple's documented controls answer API availability questions;
the starting-point run records configuration and instrumentation readiness.
It cannot establish TSO ordering correctness, guest correctness, or speed.

All future steps keep the starting point active. No inherited code or results
are reused. The M2 Pro/Max is unavailable in this session; applicability cannot
be generalized to it. Device-model completeness, stock guest boot and workload
coverage are downstream; this scratch program is not a product implementation.

For the full question, mandatory cases retained here are leaf and nonleaf
replacement, permission relaxation/restriction, present transitions (including
no-invalidate cases), guest A/D maintenance and clearing, aliases and concurrent
stores, invalidation acknowledgments after remote prewarming, table retirement
and page reuse, address-space switches, large pages and boundary faults.
Tests must operate on actual x86-format tables with an independent walk oracle;
manually changing Arm descriptors alone cannot resolve this question. A
synchronized update-only loop cannot establish concurrent update consistency.
The concrete full-question method and code will be submitted after foundation
readiness; no full-question execution is authorized by this starting-point plan.

Current blockers are in the summary. Downstream owners already exist: `Q-02-02`
for memory-ordering litmus/stress and comprehensive SMP invariants, `Q-03-04`
for paging mechanism selection, `Q-04-03`–`Q-04-05` for cost/tag/A-D analysis,
and `Q-05-02` for widening host coverage. No additional question is opened by
this initial breadth pass. These implications remain unknown, not accepted.

## Supporting contracts and claims

Source claims below retain their stated scope. The finite observation in
CLM-01-30-05 is the accepted native foundation finding. The later independent

- **CLM-01-30-01 — Source-backed:** Apple's current SDK
  `Hypervisor.framework/Headers/hv_vcpu_types.h`, `HV_SYS_REG_ACTLR_EL1`,
  documents EnTSO bit 1 and its TSO effect (macOS 15+). The
  [Apple Rosetta memory-model documentation](https://developer.apple.com/documentation/virtualization/accelerating-the-performance-of-rosetta)
  describes per-thread use. Setting/readback is a bring-up fact; ordering
  evidence belongs to Track 02.
- **CLM-01-30-02 — Source-backed:** SDK `hv_vm_config.h` provides IPA-size,
  granule and EL2 queries. IPA granule (4/16 KiB on macOS 26) is distinct from
  [Arm stage-1 translation granule](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/LearnTheArchitecture-MemoryManagement-101811_0100_00_en.pdf).
  The payload selects TG0=4 KiB in TCR_EL1, maps RAM through L3 pages and
  tests a nonidentity alias adjacent to an unmapped page. The IPA configuration
  retains the framework default; no inference equates it with TG0.
- **CLM-01-30-03 — Source-backed:** SDK `hv_gic.h`, `hv_gic_create`, requires
  creation after the VM and before vCPUs; MPIDR affinity establishes topology,
  and vCPUs may be destroyed only at VM teardown. `hv_gic_parameters.h`,
  `hv_gic_get_intid`, supplies the physical timer PPI. SDK
  `hv_vcpu_types.h` exposes physical timer registers for VMs with GIC.
  [Arm GICv3/4 software overview](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/GICv3_v4_overview.pdf)
  explains distributor, redistributor, ICC interface and acknowledgment/EOI.
  The test uses an EL1 physical per-vCPU timer and SGI 1; it records whether
  expiry causes host exits. It does not test the separate virtual-timer path.
- **CLM-01-30-04 — Source-backed:** [Hypervisor lifecycle documentation](https://developer.apple.com/documentation/hypervisor)
  and SDK `hv_vcpu.h` bind each vCPU to its owning thread. Each worker creates,
  configures, runs and destroys its own vCPU. The watchdog uses the documented
  cross-thread cancellation `hv_vcpus_exit`.
- **CLM-01-30-05 — Observed, accepted:** this payload's own exception vectors,
  native mappings, timer, SGI and shared diagnostics operate together on the
  recorded M4 at two and four vCPUs, with TSO set/read before and after.
  Primary `q30-foundation-05` and replicas 01–03 support only this finite
  starting-point case; see the independent findings review.
- **CLM-01-30-06 — Source-backed, full-question input:** Intel SDM Vol. 3A
  §§4.10.4.3–4.10.5, reproduced in the
  [Intel SDM change document](https://cdrdv2-public.intel.com/789573/252046-sdm-change-document.pdf),
  distinguishes changes requiring invalidation from present-bit additions and
  permission relaxation, describes A/D clearing limits and remote invalidation
  before reuse. Native Arm maintenance is illustrated by
  [Linux v6.12 `__flush_tlb_all`](https://raw.githubusercontent.com/torvalds/linux/v6.12/arch/arm64/include/asm/tlbflush.h):
  store barrier, broadcast TLBI, completion barrier, context synchronization.
  Composing these two contracts is unproven here.

## Method and controls

Starting-point code was the disposable program (its working copy is now
retired; each named run retains its actual producing snapshot):
`shared.h`, `guest.S`, `guest.c`, `host.c`, `run.py`, and entitlements. The
parent authored the guest/host; agent `/root/retained_runner` authored the
retention/build runner. The independent reviewer authored neither.

Layout: 16 MiB RAM at IPA 0x40000000; linked payload including BSS below
0x40200000; host-readable shared structure at 0x40800000; data at 0x40900000;
separate 64 KiB stacks below 0x41000000; GIC distributor 0x10000000 and
redistributors 0x11000000. Virtual alias 0x60000000 maps the data page, with
0x60001000 intentionally absent. The MMU uses a 32-bit lower VA envelope and
4 KiB granule; this is an expedient scratch layout, not the eventual guest
machine layout. Stage-2 RAM is RWX for these controlled inputs and host memory
is RW; no guest-provided host code executes. Isolation validation is not claimed.

Every vCPU sets/reads TSO, enters native paging, loads the alias and checks a
fixed independently known sentinel. With IRQ masked, an intentional adjacent
read must fault at an exact labeled instruction, report current-EL data abort,
L3 translation fault and the exact FAR, execute the installed vector once, and
resume at the labeled continuation. Each vCPU clears GICR_WAKER.ProcessorSleep,
bounded-polls ChildrenAsleep to zero, and retains before/after readback before
configuring its ICC interface. The handler preserves all GPRs and ELR/SPSR;
floating point is disabled by general-register-only compilation. After every
vCPU is ready, each sends SGI 1 to its cyclic successor and starts its own
physical timer. Each must receive exactly one SGI and at least three timer
interrupts, then read TSO again and finish. The timer remains configured; its
interrupt is masked on final stop. This is readiness, not Q-01-32 injection.

Positive control: correct alias sentinel. Negative control: absent adjacent
translation producing exact ESR/FAR/PC and one recovery. Independent host
checks verify per-vCPU counters, status, sentinel, MMU/TG0 and both TSO reads.
Logs include every host exit; per-vCPU 32-event rings and crash fields remain
in `ram.bin` on supervised partial failures. `shared.bin` holds the final
structure. No physical-core placement claim follows from simultaneous threads.

Three fresh two-vCPU runs and one four-vCPU run are planned, no sample exclusion.
Any failure or timeout is retained and stops the batch for diagnosis. A
10-second host watchdog cancels vCPUs; the runner bounds each child to 30 s
wall, 60 s CPU and 64 MiB/file, disables core dumps and kills the child process
group. RAM is fixed at 16 MiB. Builds are from each retained source snapshot,
including the exact executing runner; stock clang/ld/codesign and Python stdlib
are used, no new dependency. Builds may be performed before execution review.

#### Current source contracts and permitted visibility

The direct [Intel SDM Vol. 3A revision 092](https://cdrdv2-public.intel.com/922487/253668-092-sdm-vol-3a.pdf),
also used by the independently reviewed Q31 source work, owns the following
proposed inputs. These **Chapter 5** references replace the older-edition
Chapter 4 locator for this new method; the earlier foundation record is not
rewritten or promoted into new evidence.

- **CLM-01-30-07 — Source-backed:** §§5.5.2, 5.5.4/Figure 5-11 and 5.6–5.8
  define four-level entry formats, leaf page sizes, reserved fields, access
  rights and A/D updates. R/W and U/S combine across the walk; XD combines
  across levels when NXE is enabled. Supervisor writes also depend on CR0.WP.
  A is set on used entries and D on the final leaf for writes; these are guest
  memory bits, not Arm AF/dirty bits. Fault and speculative-walk cases impose
  qualifications, so a generic exact-zero A-bit oracle for every unused entry
  is not justified. The candidate must enumerate its permitted A-bit effects.
- **CLM-01-30-08 — Source-backed:** §5.10.2.2 permits TLB eviction at any time,
  and §5.10.4.1 permits invalidating additional entries. Thus eagerly discarding
  all affected shadows is allowed; x86 software cannot require an old mapping
  to remain cached. §5.10.4.1 also specifies local INVLPG, CR3 and CR4 effects,
  and the invalidation performed by #PF that prevents repeated faults solely
  from a stale relaxed translation. A global flush is not permission to expose
  an invalid walk, lose guest memory stores or acknowledge too early.
- **CLM-01-30-09 — Source-backed:** §§5.10.4.2–5.10.5 distinguish optional,
  delayed and completed invalidations, including nonleaf caches and remote
  CPUs. The exact obligations used by the proposed oracle are below.

**CLM-01-30-11 — Source-backed, atomic fixture contract:** Intel SDM
[Vol. 2A revision 092, CMPXCHG, pp. 3-194–3-195](https://cdrdv2-public.intel.com/922480/253666-092-sdm-vol-2a.pdf)
specifies a destination write on both comparison outcomes. For the selected
REX.W memory form, equality writes the source and leaves RAX unchanged;
mismatch writes back the old destination and loads that value into RAX.
ZF reflects equality and CF/PF/AF/SF/OF reflect the comparison. With LOCK,
the comparison and destination write form one atomic operation. Mismatch is
therefore not a read-only operation: it requires guest write permission and
the applicable mapping A/D effects from Vol. 3A §5.8, including D for a
completed write through a fresh D=0 mapping. Those mapping-entry effects are
distinct from the value of the table entry targeted as the memory operand.

| Guest change and synchronization | Allowed or required observation |
| --- | --- |
| P=0→1 with no earlier retained P=1 translation | No invalidation is required. The shim cannot retain a negative shadow result indefinitely; a subsequent eligible access must discover the new present entry. The qualification matters when the preceding P=1→0 lacked invalidation. |
| R/W=0→1; U/S=0→1 with SMEP=0; XD=1→0 | Without invalidation an old restriction may cause at most one spurious #PF per affected linear address; fault-induced invalidation allows retry against current tables. An eager-refresh candidate may avoid that fault entirely. Repeated stale faults are not allowed. |
| A or leaf D cleared 1→0, no invalidation | A later access need not set the bit again if cached state is used; a clear bit is not evidence that no access occurred. Eager eviction may make the bit be set again. Neither outcome alone falsifies the architecture. |
| A or D cleared, then all relevant invalidations complete | The next applicable successful translation/write must perform the required A/D maintenance; read-only access cannot stand in for the first-write D test. Software changing A 0→1 needs no new invalidation if its previous clear was properly invalidated. |
| P=1→0, frame replacement, rights restriction or nonleaf replacement, before required invalidation | Cached old information may remain usable; tests cannot demand immediate new-only behavior. Eager invalidation may nevertheless choose new behavior. A valid current walk is not required to reproduce stale retention. |
| Relevant local invalidation or coordinated remote invalidations complete | Subsequent affected accesses must not use the invalidated old translation or nonleaf cache. A shootdown acknowledgement must follow the actual invalidation and completion ordering on every relevant target. |
| Empty child table beneath a present parent | Nonleaf information may still be cached even with no successful leaf translation. Replacing that parent can require invalidation; testing only prewarmed leaf entries misses this case. |
| Page-size change plus frame/rights/attribute change | Use Intel's P-clear, invalidate, then install-new sequence for a deterministic new-only oracle. An unsynchronized size change may leave multiple cached translations and is not a clean old-versus-new single-entry experiment. |
| Freed mapping or table memory awaiting reuse | Elapsed time is not invalidation. Reallocation of the linear range/physical frames must wait for required remote invalidations; table-role removal must also account for all remaining structural uses. |

#### Minimal mechanism and explicit fixture envelope

Use actual little-endian x86 PML4/PDP/PD/PT pages in guest RAM. A bounded
four-level walker checks canonicality, present/reserved bits, cumulative
permissions and physical-address width before producing a shadow. Initial
fixtures pin CR0.PG=1, CR4.PAE=1, LA57=0, PCIDE=0, ordinary paging and Normal
WB RAM; NXE, WP, CPL and PGE have explicit variants. SMEP/SMAP, protection keys,
CET, LAM, HLAT and guest VMX are disabled. Set the guest's advertised physical
width explicitly within the retained backing layout. Use actual 4 KiB and
2 MiB x86 leaves; advertise PDPE1 GB=0 initially and reject a PDPTE PS=1 as the
corresponding unsupported/reserved case. No 1 GiB, PCID, memory-type or full-ISA
coverage follows from that finite mask; those are recorded compatibility/
mechanism extensions under `Q-02-03`, `Q-02-01` and `Q-03-04`.

The current foundation has only a 32-bit lower Arm VA envelope. Concrete code
must either extend it to the needed 48-bit low/high canonical test addresses,
preserving the existing foundation layout, or mark the unavailable native
address variants as missing coverage. A Python walk of a high address cannot
stand in for executing its Arm load/store. The fixture's reserved shim address
region and effective guest-privilege representation must also be stated; guest
CPL is not automatically Arm EL1's access privilege.

The candidate sequence is:

1. **Discover roles and intercept actual writes.** Track table roles by guest
   physical page and walk level, not by one guest VA. Starting from active guest
   CR3 roots, discover valid reachable nonleaf pages with a bounded four-level
   graph scan, including recursive/shared uses. Every translated guest-writable
   alias to those pages must fault on the native Arm store. A newly linked
   table must become protected before readers/writers can use it, including a
   pre-existing writable alias. No manual list of known PTE addresses suffices.
2. **Recover the attempted write.** Fixed handwritten translated shapes issue
   actual native loads/stores at guest VAs. A table-write protection fault uses
   PC/substep metadata to identify a selected scalar store or atomic RMW and
   its guest context. This step only captures/decodes operands and provisionally
   checks x86 access; tracking protection is not a genuine guest write denial.
   It performs no destination write, atomic comparison decision, or guest
   register/flag commit. Step 4 owns the sole commit. Initially implement aligned
   64-bit MOV, byte stores, and locked 64-bit compare/exchange success/failure
   with their declared state effects. Unsupported forms stop with diagnostics;
   arbitrary x86 write decoding/restart is a Q31/Q02-01 obligation, not assumed.
3. **Coordinate before publication.** The writer owns the global update lock,
   requests a maintenance epoch and brings peers to a bounded shim rendezvous.
   A peer already faulting or waiting for that lock must acknowledge the
   rendezvous before attempting the lock. The native IRQ path cannot wait on
   the lock its interrupted context owns. These rules are essential deadlock
   constraints, not implementation details to omit. Drain prior native accesses
   before acknowledgement; guest IF does not mask internal maintenance. Keep
   timer/SGI service and diagnostic progress live while peers are quiescent.
4. **Evict, update and resume.** Under the writer lock after guest accesses
   are quiescent, revalidate current guest access rights, address translation
   and destination; a provisional step-2 result cannot authorize a stale write.
   Account for required paging A/D effects and read the current destination
   for the atomic decision here. A denied access takes the guest-fault path
   without committing the instruction's destination/register/flag effects.
   For an entitled operation, invalidate old
   guest-shadow descriptors/caches under a reviewed Arm break-before-make and
   completion sequence, retaining shim execution mappings. Perform the sole
   destination write/atomic decision through a reserved shim alias and commit
   its guest register/flag result exactly once, including CMPXCHG mismatch
   writeback, RAX and all comparison flags. Recompute affected physical-page
   roles. The simplest
   candidate may empty all guest shadows and lazily rebuild them rather than
   surgically patching entries. Publish the completed epoch only after all
   targets have performed required local synchronization and no old walker can
   install a late result. Returning from the intercepted guest store may wait
   for this stronger internal completion. Guest INVLPG/CR3/CR4 operations still
   traverse their real translated control paths and have independent completion
   records; extra prior eviction does not excuse an incorrect acknowledgement.
5. **Walk and maintain A/D.** On an allowed native mirror miss, walk the current
   guest bytes under the lock and validate dependencies through installation.
   Set required guest A bits without losing concurrent guest updates. Leave an
   otherwise writable shadow write-protected while its guest leaf D is zero;
   the first permitted native write then sets D and can enable writes. If the
   destination is itself a tracked table page, its write remains trapped after
   D maintenance. Guest A/D clearing triggers the same update/coherence path.
   Arm AF or an Arm writable mapping alone cannot implement guest A/D state.
6. **Retire by use, not by history.** After a nonleaf removal or CR3 switch,
   rescan all active roots and cached/in-flight dependencies before dropping
   a page's final table role. Multiple levels/roots/aliases can retain roles.
   Once the required invalidations complete and no active use remains, ordinary
   writes to a reused data page must stop taking table-tracking faults. If a
   later CR3/nonleaf operation makes it a table again, rediscover/protect it
   before use. Keeping every page ever observed as a table permanently protected
   does not meet Q30. Reuse while stale references remain is also a failure.

Q30 checks native access permission outcomes and classification. It does not
claim the actual x86 IDT frame/restart mechanism owned by Q31. Genuine guest
faults are separately recorded and must never be repaired into unauthorized
access; the later Q31 growth adds delivery with every Q30 mechanism retained.
Guest table-page memory containing code remains tracked for both roles rather
than losing one classification when the other changes.

### Concrete address/context choices for the next code submission

The following are implementation candidates, not accepted runtime findings or
a product architecture. Preserve the accepted foundation's identity RAM, GIC,
vectors and diagnostic alias. Extend stage-1 roots to 48-bit lower and upper
VA regions. For an originally canonical x86 low address, the handwritten
translated memory shape uses `arm_va = x86_va | (1ULL << 47)`; a canonical high
x86 address is unchanged. This leaves the lower 128 TiB of Arm TTBR0 space
for the existing shim layout, separate from all transformed guest addresses.
Arm's [Memory Management 101811, address spaces](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/LearnTheArchitecture-MemoryManagement-101811_0100_00_en.pdf)
defines each region as `2^(64-TnSZ)` bytes. T0SZ=T1SZ=16 therefore gives 256 TiB
per region; this arithmetic supports the candidate namespace separation, not
the correctness of a concrete access transformation.

Validate original x86 canonicality and the entire selected access before
transforming it. Keep original GVA, namespace, access width/kind and substep in
