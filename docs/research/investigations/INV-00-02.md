## Resolution

“Unmodified modern x86-64 Linux compatibility” means every accepted host/OS
cell can directly boot, without firmware, a pinned 64-bit kernel and initramfs
into unmodified distribution userspace; bring every vCPU online; exercise
serial, block, network, entropy, timer/interrupt, reset, and orderly shutdown;
and pass the accepted correctness suite.

The selection policy identifies candidate release families: upstream Linux
6.12.108 and 6.18.49, Ubuntu Server 26.04 LTS amd64, and Debian 13 stable amd64
(13.6 at the freeze). The exact Ubuntu point release is deliberately unselected.
These are not yet experiment artifacts: no image, kernel, initramfs,
configuration, package snapshot, or authoritative digest is pinned by this
record. `Q-05-03` must record byte-identities, provenance, published checksums,
configurations, and a redistributability determination before any experiment
using a candidate is eligible. Linux 7.2.3 is forward-looking diagnostic only.

“Unmodified” is claim-specific. For an upstream-kernel claim, the recorded
kernel and configuration must be byte-identical to the pinned build inputs and
outputs. For a stock-distribution claim, the vendor image, kernel, initramfs,
and package baseline must be byte-identical to their pinned artifacts before
the run. Extracting the same vendor kernel/initramfs for direct loading is
allowed; replacing or rewriting either is not. A manifest records boot
arguments, extraction procedure, test-agent packages/files, ordinary updates,
and before/after hashes. Updates or agent installation create a separately
named configuration and may not inherit a pristine-image claim.

Direct boot uses Linux x86 boot protocol 2.15 and its 64-bit entry contract.
BIOS, UEFI, deprecated EFI handover, installation-media boot, and 32-bit kernel
entry are outside the promise.

The provisional userspace ISA baseline is cumulative x86-64-v2. It does not
define a system CPU. Candidate system requirements add
long mode, rings 0/3, NX, SYSCALL/SYSRET, CPUID, TSC, four-level paging, 4 KiB
and 2 MiB pages, precise exceptions, atomics/memory ordering, and the accepted
interrupt/SMP machine contract. AVX tiers, LA57, 1 GiB pages, nested
virtualization, PMU, SMM, SGX/SEV/TDX, and vendor acceleration are not
advertised unless a gated workload requirement reopens the boundary. `Q-02-03`
must enumerate every exposed CPUID leaf, MSR, reset/writable state, dependency,
exception, rejection behavior, APIC identity, and topology field. `Q-01-13`
must select the Virtio transport and negotiated features, ACPI/APIC table
subset, discovery path, timers, reset/shutdown behavior, and verify required
stock drivers. Compatibility is conditional on both questions being accepted.

Required acceptance topologies are 2, 4, and 8 vCPUs at 2 GiB and 8 GiB guest
RAM; 1 vCPU is diagnostic. The two minimum named admissible pairs are:

| Pair | Host configuration | macOS release | Support basis |
| --- | --- | --- | --- |
| `P1` | MacBook Pro (14-inch, 2021), Apple M1 Pro | macOS Sequoia 15 | `SRC-046` lists the model; `SRC-047` identifies M1 Pro. |
| `P2` | Mac mini (2024), Apple M4 | macOS Tahoe 26 | `SRC-048` lists the model; `SRC-049` identifies M4. |

Thus `H = 2`, and the minimum positive guest matrix has
`4 guests × 3 SMP topologies × 2 RAM sizes × 2 pairs = 48` cells. This is not
a Cartesian assertion: `P1` and `P2` are the only accepted pairings. `Q-05-02`
must pin exact OS builds/SDKs, reconfirm Apple support at method freeze, record
actual hardware identities, and may add separately reviewed admissible pairs;
it may not silently substitute or remove `P1`/`P2`. These pairs span two Apple
Silicon generations and two macOS releases. P/E-core placement, host
oversubscription, and two-live-instance cases are explicit dimensions owned by
`Q-05-02` and the applicable correctness methods.

Predeclared confound. `P1` and `P2` vary the Apple Silicon generation and the
macOS release together, and the captures show both crossed pairs are
vendor-compatible: `SRC-048` lists the 2021 14-inch MacBook Pro for Tahoe 26
and `SRC-046` lists the 2024 Mac mini for Sequoia 15. Excluding the crossed
pairs is therefore a scope decision that limits the minimum matrix to two
cells per guest configuration; it is not imposed by Apple support. No Track 00
or downstream claim may attribute a `P1`-versus-`P2` difference to the chip
generation rather than the macOS release, or vice versa, until `Q-05-02` adds
at least one reviewed crossed pair and measures it. `SRC-046`/`SRC-048`
establish install compatibility only; whether a release counts as a supported
macOS release for the envelope is a per-pair status that `Q-05-02` assigns at
method freeze from Apple's then-current support statements.

A cell passes only when readiness is reached, every vCPU is online, required
devices pass functional/error tests, orderly shutdown succeeds, and Track 02
correctness is accepted. Oops, panic, stall, unexplained warning, missing vCPU,
device timeout, or correctness failure fails the cell and invalidates its
performance samples. Statically unsupported configurations fail before vCPU
execution with a stable machine-readable reason. `Q-02-03` must enumerate the
guest-visible result for every runtime-unsupported operation—architectural
exception, architecturally defined value, or explicitly unavailable feature—
and tests must reject silent no-ops and host failure. Out-of-matrix guests are
best-effort and cannot widen the claim.

## Falsifiers and alternatives

| Falsifier | Disposition |
| --- | --- |
| A mandatory workload needs excluded ISA, 32-bit userspace, or firmware. | Boundary revision: reopen `Q-00-01`, `Q-00-02`, and stop rules. |
| A selected stock kernel lacks the chosen built-in/initramfs transport driver. | Boundary/machine-contract failure: revise candidate guest or `Q-01-13`; do not patch and retain a stock claim. |
| The selected CPU model has unlisted architectural requirements. | CPU-contract failure: return `Q-02-03`; kill a family only if reviewed evidence shows it cannot satisfy the corrected contract. |
| A required guest/SMP/RAM cell on an admissible host/OS pair fails correctness. | Configuration failure; performance is invalid. Reproducible cross-family failure reopens the boundary; family-specific failure kills that family. |
| Machine discovery requires excluded firmware. | Boundary revision or project stop if accepted workloads cannot be served by direct boot. |
| An advertised unsupported feature silently misbehaves. | Correctness failure and method/result invalidation; family kill if not remediable within the maturity rule. |
| Required coverage cost exceeds the accepted research budget. | Scope/economic reopening under `Q-06-05`, never silent matrix reduction. |

`Q-01-13` owns the guest machine contract and `Q-02-03` the CPU contract; this
resolution specifies guest-visible requirements, not an implementation design.
