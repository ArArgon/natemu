## Supporting contracts and claims

Claims 01–07 are **accepted scoped source findings and explicit inferences**;
this does not accept a runtime mechanism or authorize execution. Intel
revision **092** is the current download at the
[official index](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)
checked 2026-09-06; use its chapter numbering.

**CLM-01-32-01 — Source-backed: guest delivery has a boundary and eligibility
contract.** Intel SDM
[Vol. 3A §§7.5–7.9](https://cdrdv2-public.intel.com/922487/253668-092-sdm-vol-3a.pdf)
places ordinary interrupt recognition between instructions, with return state
for the next instruction; repeated instructions admit iteration boundaries.
IF masks maskable hardware interrupts, not exceptions or NMI. At a boundary,
Table 7-2 gives an eligible maskable interrupt priority over a fault fetching
the next instruction. The table expressly does not rank faults arising during
the current instruction or event delivery. Consequently, “#PF always wins over
IRQ” is not a valid universal oracle. §§7.12 and 7.14 specify gate/frame/return
behavior; an interrupt gate clears IF, whereas a trap gate does not.

**CLM-01-32-02 — Source-backed: interrupt shadows are guest execution state.**
[Vol. 2B, STI and MOV](https://cdrdv2-public.intel.com/922481/253667-092-sdm-vol-2b.pdf)
and Vol. 3A §7.8 distinguish setting IF from becoming immediately interruptible.
With old IF=0, STI inhibits maskable interrupts at its following boundary until
the next instruction executes or another event is delivered. STI; CLI can keep
them inhibited; old IF=1 does not obtain the same promised delay. Loading SS
with MOV also inhibits interrupts on the following boundary, ending after the
next instruction or exception delivery. Consecutive SS loads guarantee this
inhibition only for the first; LSS does not have that inhibition. POP SS is not
a valid 64-bit fixture. CLI/STI privilege checks must use guest CPL/IOPL; neither
host privilege nor Arm PSTATE supplies that check. The manual also permits some
NMI/SMI inhibition after STI with old IF=0; no universal immediate-NMI assertion
is inferred here.

**CLM-01-32-03 — Source-backed: APIC priorities and coalescing are distinct
from a FIFO.** [Vol. 3A §§13.8.3–13.8.5](https://cdrdv2-public.intel.com/922487/253668-092-sdm-vol-3a.pdf)
uses the vector's upper nibble as priority class, its lower nibble to order
vectors within a class, and a processor-priority class determined by task
priority and the highest in-service class. Only a strictly higher class is
eligible for delivery. IRR records pending vectors and ISR records in-service
vectors; EOI clears the highest-priority ISR bit. Further arrivals of an
already-pending vector can coalesce, including one pending while that vector
is in service. Thus counts of emitted events, accepted pending bits and handler
entries need separate oracles. EOI has level-triggered notification semantics
too; treating it as merely decrementing a queue loses information.

**CLM-01-32-04 — Source-backed: halt and repeated-operation return state are
observable.** [Vol. 2A, HLT, p. 3-439](https://cdrdv2-public.intel.com/922480/253666-092-sdm-vol-2a.pdf)
requires CPL0, halts only the executing logical processor, and resumes on an
enabled interrupt with saved RIP after HLT. Other documented wake causes exist;
a masked fixed interrupt alone is not the proposed guest wake condition.
[Vol. 2B, REP, pp. 4-563–4-564](https://cdrdv2-public.intel.com/922481/253667-092-sdm-vol-2b.pdf)
preserves the repeated instruction RIP and count/address progress identifying
the next element after an interrupt. Finite RAM MOVSB cases do not establish
all repeated I/O instructions or vector partial progress.

**CLM-01-32-05 — Source-backed: native IRQ mechanisms identify native events.**
Arm's [AArch64 Exception Model 1.3, §§5.1–5.3](https://documentation-service.arm.com/static/63a065c41d698c4dc521cb1c)
specifies saved Arm exception state, software register preservation and ERET.
For asynchronous exceptions, ELR identifies the first Arm instruction not fully
executed. Arm IRQ masking is independent of the guest x86 IF model. Arm's
[GICv3/4 overview v3.0, §§4.1–4.2, 6.4 and 7](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/GICv3_v4_overview.pdf)
distinguishes SGI, PPI and SPI and their pending/active lifecycle. EOImode
determines whether EOIR also deactivates or needs a separate DIR operation.
An SGI INTID has one pending state per target, not a per-sender event queue;
simultaneous senders can coalesce. SGI routing supports an explicit affinity
target list or all participating targets except self. Native acknowledgement
and deactivation are therefore separate from guest APIC acceptance and EOI.

Apple's macOS **26.4 SDK**, Hypervisor.framework `hv_gic.h` and
`hv_gic_parameters.h`, documents `hv_gic_create`, `hv_gic_get_intid`,
`hv_gic_get_spi_interrupt_range` and
[`hv_gic_set_spi`](https://developer.apple.com/documentation/hypervisor/hv_gic_set_spi(_:_:))
(macOS 15+). SPI assertion sets a level and also creates an edge for an
edge-configured SPI; deassertion has no effect for an edge-configured SPI.
The assigned SPI range and timer INTID must be queried and retained rather
than assumed. These APIs establish available injection controls, not an
observed interrupt route or guest x86 behavior on this host.

**CLM-01-32-06 — Inferred: a native arrival must defer when guest state is
between commit points.** From claims 01–05 and Q31's recovery contract, a
native Arm exception point can lie inside one x86 instruction. Immediate
x86 frame construction there could expose partial register/flag/memory state.
The minimal candidate records pending guest state, preserves native execution
context, completes or faults the current guest operation under Q31, and checks
eligibility at a declared guest boundary. A software-only enqueue control can
test selection but cannot demonstrate real timer/SGI/SPI arrival. Short native
handlers need a bounded path to a guest boundary even when arrival was inside
shim code; indefinitely masking native IRQs or deferring until an unbounded
block completes does not answer the question.

**CLM-01-32-07 — Inferred: halt and code invalidation need coordinated
publication.** A halt implementation must publish its halted state and recheck
pending eligible events in a protocol that cannot lose an event between the
check and host/native wait. A native wake need not be a guest wake. Likewise,
pending guest delivery cannot retain a stale translated continuation after
a synchronized code write. Intel
[Vol. 3A §11.1.3](https://cdrdv2-public.intel.com/922487/253668-092-sdm-vol-3a.pdf)
defines local and cross-modifying code synchronization; the Q31 generation
and recovery contract must remain valid through deferred IRQ delivery and
return. These are requirements on the candidate, not proof that a particular
wait primitive or metadata lifetime works.

The candidate adds a per-vCPU guest interrupt state to Q31: IF and interrupt
shadow, TPR, IRR/ISR/trigger state, guest halted state and event/frame state.
Native IRQ handling records the source and its payload/sequence separately
from the guest vector bitmap, follows the configured GIC acknowledgement
protocol, then returns or goes through a declared delivery point. Device
payload storage must tolerate a coalesced native notification. A translated
boundary selects eligible guest delivery and constructs the actual guest
IDT frame; guest handler execution and IRET verify it. Merely logging the
desired RIP/vector is not delivery.

**Known — Source-backed:** Intel Vol. 2A, `INT n/INTO/INT3/INT1`, Operation,
p. 3-469, expressly includes external interrupts in its delivery algorithm.
When a check raises a nested exception, the original event is not delivered.
Its `TRAP-OR-INTERRUPT-GATE` path, p. 3-472, reads the target code descriptor
before entering either privilege-transfer path. Architectural RSP/SS/CS/RIP
assignments and frame writes occur later, pp. 3-474 and 3-477–3-479.
Thus a deliberately absent target-descriptor page supplies a pre-transfer
fault site; it does not require rollback from an already changed stack or
partly constructed IRQ frame.
[Vol. 2A revision 092](https://cdrdv2-public.intel.com/922480/253666-092-sdm-vol-2a.pdf).

**Known — Source-backed:** Vol. 3A §13.8.4, p. 13-31, separates acceptance
into IRR from core dispatch: dispatch clears the selected IRR bit and sets its
ISR bit before sending the vector to the core. §13.8.5, pp. 13-31–13-32,
requires a distinct EOI write, normally before IRET, to clear the highest
in-service vector. The IRET operation restores the saved execution context;
it is not an EOI write. §§7.12.1/7.14.3 and Vol. 2A's IRET operation describe
that restoration, including CS:RIP, flags and the saved SS:RSP.
[Vol. 3A revision 092](https://cdrdv2-public.intel.com/922487/253668-092-sdm-vol-3a.pdf),
[Vol. 2A, IRET, pp. 3-490–3-496](https://cdrdv2-public.intel.com/922480/253666-092-sdm-vol-2a.pdf).

**Inferred consequence:** for the single edge-triggered IRQ fixture, with no
second arrival, EOI or reset, a descriptor-read #PF does not license changing
the accepted vector back from ISR to IRR or marking it serviced. A later
ordinary #PF-handler IRET restores the saved pre-transfer program context;
it does not itself reconstruct or retry the external IRQ. Unlike Q31's
noncanonical instruction that raises a fresh #GP when re-executed, there is
no faulting IRQ instruction to re-execute. This follows from the preceding
separate delivery, return and APIC contracts; it is not a measured claim of
hardware recovery behavior or a complete OS recovery recipe.

**Known — Source-backed:** INTR is in the benign class in Vol. 3A §7.15,
Event 8, Tables 7-4/7-5, pp. 7-36–7-37. A benign event followed by #PF is
handled serially rather than becoming #DF. Here “serially” does not override
the original-event non-delivery rule or invent automatic IRQ requeue.
GDT reads are implicit supervisor accesses regardless of interrupted CPL
(§4.2); an absent descriptor page therefore raises a supervisor-read #PF,
error code **0**, with CR2 naming the descriptor's faulting linear address
(§5.7 and Event 14). Do not OR the selector-error EXT bit into a #PF code:
#PF has its own P/W/U/RSVD/I-D layout.
[Vol. 3A revision 092](https://cdrdv2-public.intel.com/922487/253668-092-sdm-vol-3a.pdf).
