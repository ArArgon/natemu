## Question and decision relevance

- Question ID and text: `Q-01-19` — Is per-thread JIT write-protection state
  preserved across host fault delivery and return, and what fault-handler
  discipline is admissible while a vCPU thread holds write permission or
  patches code?
- Decisions affected: translation-family admissibility under SMP; the
  `INV-01-02` family register; `Q-01-12`'s prototype method; and containment
  work in `Q-02-04`.
- Why this must be resolved now: accepted JIT and basic fault probes establish
  their mechanisms separately. They do not establish their composition during
  callback writing, cache maintenance, publication, or live patching.

## Assumptions

- Declared assumptions: routine operation is unprivileged and public-API only;
  the product topology is 2/4/8 vCPUs; correctness failures invalidate cost
  samples; all observations remain platform/signing-cell specific.
- Assumptions to challenge: handler entry preserves JIT state; return restores
  it; a handler may safely repair state; callback failure can use non-local
  transfer; one-thread behavior transfers to simultaneous faults; and a
  post-return state check detects transient unsafe execution.

## Hypothesis and falsifier

- Hypothesis: at least one immutable, callback-bounded, quiesced, per-vCPU, or
  explicit-check discipline composes JIT state and fault delivery safely under
  public APIs at 2/4/8 vCPUs.
- Falsifiers: wrong state after entry or return; region left writable; partial
  or stale code execution; wrong PC/register/stack; lost or misclassified
  fault; unsafe nested delivery; use-after-reclaim; or unbounded deadlock under
  an admitted scheduling cell.
- Predicted outcomes: M19-2's preservation candidate predicts allowed-write /
  denied-execute samples in supported write windows, the opposite after normal
  callback return, exact normal resumption and no premature publication or
  quiescence. Predictions are falsifiable, not platform guarantees.

### Process, ownership and handler surface

An external parent starts a fresh executable child for each cell/repetition or
negative arm, records the complete arm identity and pre-arm state durably,
drains normal-context child telemetry, and records exit/signal/timeout even if
the child cannot flush. Do not fork a running multithreaded JIT process. Child
setup creates the Q18 arena/protocol, immutable event descriptors, bounded
per-thread/depth trace slots, worker/helper threads, alternate-stack storage
and dedicated non-JIT fault pages in normal context. All storage is allocated,
prefaulted and bound before arming; no handler owns a resource lock. Handler
installation uses sigaction, not ISO C signal(). Exact compiler options and
arm64 opaque-context configuration are recorded.

Every handler-visible registry field, pointer, event flag, depth and trace slot
with static/thread storage is a lock-free atomic object, verified by compile
constraints and normal-context atomic_is_lock_free checks. Handlers use scalar
automatic locals, inline read-only context accessors and the audited inline
atomic operations only. Disassembly must reject out-of-line atomic helpers,
TLS resolution, lazy binding, compiler-emitted copying/stack helpers or any
unexpected call on the handler path. No pthread identity query, mutex,
allocation, formatted logging, clock call, mprotect, JIT transition, cache
maintenance or other unlisted API is permitted there. The only possible
library call is the documented async-signal-safe _exit for terminal failure.
Thus handler telemetry does not depend on pipe atomicity or a libc write path.
Normal-context helpers serialize completed atomic records to the parent.
Release-committed slot flags and acquire reads distinguish partial records;
fixed slots are not recycled until the normal-context consumer acknowledges
them. Nested depths use different slots. Overflow is an integrity failure,
never dropped successful events. No process-shared C atomic claim is needed.

Identity is checked without unsafe TLS: full simultaneous arms identify the
current handler's automatic-local address within one unique registered
alternate-stack range, then compare the captured interrupted PC/register
cookie with the armed thread/event. No-altstack diagnostics use exact assembly
checkpoint PC and a dedicated captured general-register thread/event cookie;
an unknown or ambiguous match fails closed. Arbitrary-PC delivery lacking an
independently validated identity route is coverage-missed, not counted as a
successful targeted event. Context size/accessor support is checked against
the accepted same-cell Q06 baseline before field use. The handler never edits
the supplied context, clears a Q18 hazard, publishes code, acknowledges a stop,
or restores a JIT permission. Atomic telemetry is experiment instrumentation,
not guest architectural state.

### Delivery and normal-return paths

A: a normal-context controller waits for an acquire-observed named checkpoint,
then calls pthread_kill on the intended worker, checks its return, and waits
for that event's handler and resumed acknowledgements. Only one event of a
given signal type is outstanding per worker; standard-signal queuing/counting
is not assumed. A checkpoint assembly wrapper freezes its expected PC range,
thread/event cookie, register sentinels and SP, while preserving the live
protocol ownership. Handler return is normal with unchanged context. The
post-return wrapper checks the exact instruction continuation, SP/cookie and
sentinels before allowing the protocol to advance. Masked delivery is tested
as a separate arm: arm and send while masked, assert no handler acknowledgement
before a normal-context unmask boundary, then require exactly one delivery.
This is an observation, not a pthread_kill timing guarantee.

R: call a fixed, disassembled assembly load/store helper at the selected
checkpoint, including inside a write callback. Its only faulting operand is
the current worker's dedicated non-JIT page, set PROT_NONE before arming. The
handler accepts a recoverable synthetic guest-classified event only when
signal class, exact fault PC, address/range, operation, event nonce, thread and
live protocol phase all match its immutable descriptor. It records context,
release-publishes a repair request and waits on its own atomic acknowledgement.
A separate normal-context helper, not the handler and not a stopped vCPU,
checks that request and uses mprotect to restore only that dedicated data page
to the predeclared permissions. It records the exact return/error and publishes
acknowledgement only on success. Handler return then leaves the context
unchanged, so the original instruction is expected to retry and complete.
The callback continues on its original control path and returns normally.
This Darwin extension is an experimental hypothesis, not portable ISO C
behavior or a source-proven composition. A same-cell no-JIT retry baseline
must pass first. No handler waits for a lock or for the faulting vCPU to make
progress; the external watchdog bounds helper failure. Restore PROT_NONE for
the next event only after normal completion and explicit disarming.

Each synthetic guest operation has a normal-context precommit journal and a
single post-retry commit counter. Require no commit before successful retry,
exactly one commit afterward, unchanged unrelated data, and the expected
loaded/stored value. This is a surrogate oracle, not x86 guest exception
semantics. Unexpected PC/address, stale nonce, helper-thread fault, emulator
bug or resource failure is host/unclassified and terminal; it is never
relabelled guest to keep a run alive. An F discipline treats even a recognized
fault in a write window as terminal; only a fresh child with a newly built
arena may continue. F must not report in-process restoration. X performs the
same operation/journal with an explicit precheck and error return before the
write callback; matching output and zero handler entries are its oracle.
Keeping fault-prone work outside callbacks is a separate A/F/X alternative;
it does not answer whether R inside callbacks is viable.

### P and D handler configurations — mandatory separation (REV178 R1)

The normal-return configuration is P; the sacrificial permission-denial
configuration is D. Their dispositions are installed in normal context before
workers arm and never changed by a handler. A fresh child is required to switch
configurations. Both use SA_SIGINFO and, in alternate-stack cells, SA_ONSTACK;
the no-SA_ONSTACK diagnostic clears only that flag. Neither sets SA_RESETHAND
or SA_RESTART. Before arming each participating worker, normal-context setup
establishes a base mask B that blocks every blockable signal except SIGUSR1,
SIGUSR2, SIGBUS and SIGSEGV. SIGKILL/SIGSTOP cannot be blocked. The exact mask,
dispositions and setup return values are captured; inherited masks are not
assumed empty. The masked-delivery arm adds only SIGUSR1
to B until the declared normal-context unmask boundary. It never
deliberately blocks a synchronous-fault signal while inducing that fault.
Non-vCPU helpers do not receive targeted USR notifications; helper-fault
controls are separate sacrificial children with the same explicit fault
dispositions and their own registered identity/storage.

| Configuration and signal | Handler identity, sa_mask and flags in addition to SIGINFO/stack flag | Allowed entry and disposition |
| --- | --- | --- |
| P: SIGUSR1 | P_outer; sa_mask={USR1,BUS,SEGV}; no NODEFER | depth1 A; USR2 may be delivered at depth2; normal unchanged-context return |
| P: SIGUSR2 | P_inner; sa_mask={USR1,USR2,BUS,SEGV}; no NODEFER | depth2 under A or R only; no third positive entry; normal unchanged-context return |
| P: SIGBUS and SIGSEGV | P_fault installed for both; sa_mask={USR1,BUS,SEGV}; no NODEFER | depth1 R only on the exact private-page descriptor; both fault classes stay masked during recovery; USR2 may enter at depth2 |
| D: SIGUSR1 | D_outer; sa_mask={USR1}; no NODEFER | same requested A checkpoint, but distinct diagnostic configuration; BUS/SEGV and controlled USR2 remain unblocked |
| D: SIGUSR2 | D_inner; sa_mask={USR1,USR2}; no NODEFER | depth2 A/R diagnostic checkpoint; BUS/SEGV remain unblocked for the one terminal witness |
| D: SIGBUS and SIGSEGV | D_fault installed for both; sa_mask={USR1}; SA_NODEFER | exact original depth1 R event may use helper retry; an independently armed W/X denial terminates at depth1,2 or3 according to its parent depth |

The effective mask is B plus inherited handler masks plus the row's sa_mask
and the automatic current signal unless NODEFER suppresses it. In D, neither
fault class is placed in any row's sa_mask. Thus a SIGBUS inside a SIGBUS R
handler, or SIGSEGV inside SIGSEGV R, is explicitly requested to be deliverable
with NODEFER; the method never assumes the kernel chooses the other class.
This configuration is only a Darwin-specific sacrificial experiment, not a
guarantee that nested synchronous faults are supported or a portable-C path.
The actual signal class and mask/context must be observed in same-cell
preflight. If the source/API baseline cannot validate the required mask setup,
delivery or context size, the corresponding cell is blocked, not implemented
using guessed thread-mask semantics.
Normal-context setup readback records B and each installed disposition.
The delivered uc_sigmask is checked as the interrupted context's mask, not
misreported as the newly entered handler's effective mask. In particular a
depth2/3 terminal record checks its parent context against the explicit union
above. No extra mask-query call is introduced into a handler. The normal
controller sends nested USR2 only after acquiring the outer entry record, so
controlled nesting cannot precede the outer depth/token initialization.

Positive depth counts only normal-return A/R handlers: outside=0, outer A or
R=1, controlled USR2=2. D reserves one extra terminal depth: witness outside a
handler enters at1, inside an outer at2, inside its USR2 at3. A depth3 entry
is never a positive return, never issues a repair and never runs another
witness. Each entry increments a per-worker lock-free depth counter before
selecting its preallocated slot; normal return decrements after committing its
return marker. Parent event/depth identity is recorded independently of the
counter. A fourth entry, wrong parent or unexpected signal cannot index past
storage: take the fail-closed _exit path, with parent pre-arm records retained;
such an exit is not successful denial evidence.

Every witness has a fresh nonce and descriptor naming child/configuration,
worker, root event, parent event, parent depth, expected terminal depth,
protocol phase, access kind, exact access instruction/PC range, expected
address/range and expected permitted signal set {BUS,SEGV}. Class alone is
insufficient. The original R private-page descriptor and the W/X descriptor
are different objects with different addresses/PCs/nonces. Before executing
the one witness instruction, its current context release-arms that witness's
atomic token; the terminal entry requires that exact live token and parent
chain and marks it consumed once. Both same-class and other-class returns
are classified by the observed signal, never relabelled to bypass masks.

The MAP_JIT non-code store word is unique for each worker/event/parent-depth
and separated from every instruction slot; no simultaneous access writes a
shared witness word. Execute probes use separately identified immutable stubs
retained until child termination, never a slot being patched or reclaimed by
the Q18 test. Atomic trace/ack slots are unique per worker/event/entry-depth,
including terminal depth3; immutable descriptors remain until all workers
join or the child exits. The expected permissions include process-wide Q18
mapping state: during a deliberately PROT_NONE arena phase, both accesses are
expected denied rather than attributed to per-thread JIT-state restoration.

Before a D evidence cell, same-cell sacrificial code-validation controls must
induce an exact owned non-JIT protected-page fault inside an outer R fault
handler, then separately inside its depth2 USR2 handler, using D's actual
dispositions and slots. Require the depth2/depth3 terminal trace, parent nonce,
exact PC/address and captured mask to match; deliberately select the same
fault-producing instruction/page arrangement as the outer event, and record
whether the actual class repeats. Same-class coverage is owed explicitly:
if that platform does not deliver it, report unavailable/failed coverage,
not a pass justified by an other-class event. Also test one terminal witness
under A and directly at depth0, wrong parent/nonce/address/PC, replay, depth
overflow, missing consumer acknowledgement and blocked same-class delivery.
The last is a deliberately invalid containment diagnostic in its own child,
not a P or D evidence configuration. It must not be mistaken for a successful
permission denial merely because the child dies. No JIT/cache/mapping API is
called from any handler in these controls.

Full simultaneous D denial arms arm all eligible workers, wait for every required
terminal record to be committed and acknowledged by the normal-context
consumer, then let one designated terminal handler _exit. Until that release,
each terminal handler waits only on its own acknowledgement and the shared
atomic exit grant; it never resumes the faulting access. The controller cannot
grant exit early and count unobserved siblings as passed. If any terminal entry
or helper stalls, the existing parent watchdog records incomplete coverage and
terminates the child. Record/ack loss, blocked delivery, crash, depth overflow
and partial output remain failed/unresolved coverage, never successful denial.
If a D access completes instead of faulting, its exact completion marker
consumes/disarms the witness token. An expected-allowed D arm continues to
normal-context completion; completion contradicting a denial prediction is a
candidate failure, not a reason to wait forever for a nonexistent terminal
record. Both paths retain D's separate mask/configuration identity.

### Permission-state witnesses and their limits

pthread_jit_write_protect_supported_np is a capability query, not a current
state query. There is no assumed public permission-state introspector. At
each named checkpoint sample (a) an aligned store to a dedicated non-code word
in the arena and (b) execution of an immutable previously validated JIT stub.
They occupy disjoint slots and never patch the probe itself. Run each access
in a separately armed D sacrificial sibling because an expected denial faults.
An allowed access requires the exact post-access marker/value; a denied access
requires the precise expected access PC/address/signal record from the nested
terminal handler, normal-context consumer acknowledgement of that record,
and the complete-cell D exit grant before _exit. The parent watchdog handles
failure before the record is committed;
an unexplained crash or missing record is inconclusive/integrity failure, not
evidence of denial. This nested terminal witness is Darwin-specific empirical
diagnostic behavior, not a portable-C or recoverable positive control.

For protection-supported cells, the preservation candidate predicts W-allowed,
X-denied inside the write window, including its signal-handler entry and
pre-return checkpoints; it predicts W-denied, X-allowed before entry and after
normal callback return. The corresponding allowed-only witness is also run
through a complete P normal-return A/R lifecycle, with every completion marker
and generation verified. Complementary denial evidence comes from D siblings,
not an assertion that one event survived both checks. Because P and D masks
differ, D permission samples do not prove identical permission behavior in P;
their configuration-qualified results must remain separate. An unexpected
fault on a P allowed-only witness fails that cell; blocked/missing terminal
telemetry cannot be silently borrowed from D to classify it as a proven denial.
In unsupported cells,
record both actual access results and the callback's direct-invocation branch;
do not impose supported-path exclusivity or claim state restoration.

Finite entry/return/checkpoint observations cannot prove absence of every
transient writable or executable interval. Report the exact covered PC/state
and paired-access limitations. Opportunistic asynchronous interruptions inside
opaque JIT/cache APIs are separately tagged by captured PC and do not count as
deterministic internal-state coverage or authorize their reentrance. No finite
success establishes a platform-wide preservation contract.

### Fault-during-publication, patch and quiescence matrix

For each retained Q18 alternative I (immutable/hazard), S (stop/quiesce patch),
E (epoch), V (per-vCPU cache) and M (mapping changes), inherit its exact
entry/maintenance/lifetime protocol and generation/two-field execution oracle.
Run A/R/F/X at every applicable row below; record structurally absent states
as NA with a protocol reason, never mark an unexecuted state passed. R uses
only its private fault page; it must not repair a shared Q18 mapping before
quiescence. A fault caused by an improperly changed shared mapping is a
protocol failure, not a recoverable injected guest event.

| Target role/state | Injection boundaries | Mandatory invariant after return or terminal outcome |
| --- | --- | --- |
| writer | before callback; callback entered writable; partial byte copy; copy complete before return; callback returned before cache maintenance; maintenance complete before publish; published before retire | partial/faulted generation remains unreachable; callback returns normally on R; cache and publication order unchanged |
| writer API-boundary variant | maintenance inside a callback only if separately admitted by the Q18 method; before/after that call and before callback return | never insert this unapproved sequence into the normal Q18 lane; branch blocked until that method is accepted |
| reader | entry before hazard; hazard advertised before revalidation; revalidated before execution; inside generated block; returned before hazard clear | interrupted ownership/hazard stays live; old inflight generation is not falsely treated as retired or reused |
| quiescing worker | stop requested before acknowledgement; final access before dropping reference; just after acknowledgement with no reference | no handler acknowledgement; writer waits for actual normal-context safe-point completion |
| coordinator | all-but-one stopped; all acknowledgements acquired before patch; before resume | faulted/terminated worker never silently counts as quiescent; no resume of incomplete generation |
| reclaimer/translator | before retirement test; after eligible retirement before reuse; version read before attempted publish; each mapping-transition boundary | no stale translation publish, early reclaim, generation ABA or shared mapping transition with live readers |
| E/V reader | request acquired before dropping prior pointer; exact ACK emitted before SC entry reload | before ACK the old call may finish and dependent retirement waits; after ACK coordinator may retire, but resumed reader reloads, waits on zero or applies acquired version floor; no artificial RESUME wait |

These rows compose with every arm-specific allowed outcome in accepted M18-2,
not a blanket requirement that all competitors block. In I/E, holding an
unpublished writer permits a reader to finish the current old entry; I's
advertised hazard prevents retirement until normal-context release; E/V's
exact request/ACK and version-floor reload rules replace any hazard/RESUME
shortcut. V finishes its callback and drops old pointers before ACK and may
not withhold ACK while waiting for installation. S/M alone require matching
RESUME before new admission. The one-outstanding-epoch rule and coordinator
ownership spanning final check/install or complete invalidation/ACK drain
remain intact during a handler interruption. A fault must not turn an
otherwise permitted old inflight call into a false stale-execution failure.
Retained immutable descriptors may still be inspected after code retirement;
retained execution rights and calls through retired code may not. The full
hook manifest must include both final-check/install orderings and each M18-2
arrive/attempt/release causal handshake, without instrumentation supplying
ACKs, clearing hazards or granting mutation ownership.

For every role rotate the injected target over all workers at n=1/2/4/8, then
inject simultaneously on all active eligible workers and on writer+reader
roles. Include one delayed nonacknowledging worker and two producer requests
under Q18's serialized mutation-grant rule; this is not two unsynchronized
writers. A faulting callback continues holding its legitimate writer grant;
the repair helper never needs that grant. A terminated worker causes a
protocol abort, not permission to publish/reclaim. Test a fault immediately
before and after each stop acknowledgement and before/after release of each
hazard/epoch obligation. All execution traces retain arena, generation,
guest-version, owner, state and parent event IDs. Expected old-generation
execution is judged by the inherited lifetime rules, not by a blanket
"latest at every instant" oracle.

### Stack, nesting and API/signing branches

Normal context installs a distinct prefaulted alternate stack for each worker;
register exact address/size, returned setup status and canaries. Allocate at
least max(64 KiB, 4*MINSIGSTKSZ), rounded to the observed host page size, with
guard pages. This size is an experimental budget, not a sufficiency theorem.
Handler entry/depth SP must fall in its own registered range; normal context
checks canaries after return. Repeat one-event no-SA_ONSTACK diagnostics using
the assembly-cookie identity route. Observing per-worker behavior supplies a
same-cell result only; SRC090's wording does not prove a per-thread contract.

Nested positive delivery is bounded to depth two: outer SIGUSR1 enters and
records its token; a normal helper sends SIGUSR2 to that worker; the inner
handler returns, then outer returns. Neither handler raises a signal. Distinct
depth slots preserve both contexts; stack pointers, tokens and return ordering
must match. Run this at every A checkpoint. During R's helper wait the
synchronous-fault handler itself is depth one and only SIGUSR2 is injected at
depth two; no third positive depth is allowed. Helpers must progress
independently. The mandatory D permission witnesses use the exact
same-class NODEFER/depth3 terminal configuration above, never P's positive
configuration. Other same-signal NODEFER diagnostics, synchronous faults
outside an armed witness, protected/unmapped alternate stack and stack overflow
remain separate sacrificial diagnostic/containment arms. They cannot establish
an admitted recovery discipline. Default masking, explicit masking/unmasking,
single and simultaneous workers, helper faults and parent-triggered helper
stall are all named cells, not incidental background disturbances.

Cross n=1/2/4/8 with P1/P2 and every surviving distribution configuration from
Q01-01/04: record signature/CDHash, entitlements, hardened-runtime, notarization,
sandbox, loader images and exact callback API availability. Distinguish direct
toggle (where admitted), callback without allowlist, callback with startup
allowlist, and late-loaded callbacks with the required exactly-once freeze
before first callback. A supported=false branch must actually occur on the
tested host or remain unavailable; do not fake its capability query. Direct
toggle under an enforcing allowlist, nonallowlisted callback, premature
callback-before-freeze, missing entitlement/freeze misuse and recursive entry
are expected-rejection diagnostics only. Startup and loaded-image identity,
freeze call count/order and every API error are durable normal-context fields.
An unavailable Developer-ID/notarized/sandbox/P1 cell stays unavailable, not
substituted by ad-hoc P2 success.

Intentionally forbidden callback recursion, longjmp/exception-style nonlocal
escape, cancellation, thread exit and termination during writable state each
run in a fresh sacrificial process after code review. Nonlocal diagnostics
use otherwise-live saved frames and language-defined objects where relevant,
but remain invalid under the callback contract. No observed survival can
support a candidate discipline. No forbidden JIT/cache/mapping call is placed
in a signal handler even in a negative arm. Direct toggles, where admitted,
must restore state in normal context; an interrupted toggle is not "repaired"
in a handler. Compiler/runtime behavior and possible process damage in invalid
arms are reported as diagnostics without causal contract conclusions.
